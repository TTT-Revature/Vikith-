# SQL Constraints in MySQL

## 1. Introduction to Constraints

Constraints are rules applied to columns or tables to control what kind of data can be inserted, updated, or stored.

They help maintain:

- Data accuracy
- Data consistency
- Data integrity
- Valid relationships between tables

For example:

Imagine a college database. Every student must have a unique student ID, and a student's name should not be empty.

We can enforce these rules using SQL constraints.

---

## 2. Types of SQL Constraints

The major SQL constraints are:

1. `NOT NULL`
2. `UNIQUE`
3. `PRIMARY KEY`
4. `FOREIGN KEY`
5. `CHECK`
6. `DEFAULT`

Let's understand each one.

---

## 3. NOT NULL Constraint

The `NOT NULL` constraint ensures that a column cannot store a NULL value.

In simple words, the column must have a value.

### Example

```sql
CREATE TABLE students (
    student_id INT,
    name VARCHAR(100) NOT NULL,
    age INT
);
```

Here, the `name` column cannot be NULL.

### Valid INSERT

```sql
INSERT INTO students
VALUES (1, 'Rahul', 22);
```

### Invalid INSERT

```sql
INSERT INTO students
VALUES (2, NULL, 23);
```

This produces an error because the name column does not allow NULL values.

**Important:** NULL means a missing or unknown value. It is different from zero (`0`) or an empty string (`''`).

---

## 4. UNIQUE Constraint

The `UNIQUE` constraint ensures that values in a column or combination of columns do not contain duplicates.

### Example

```sql
CREATE TABLE students (
    student_id INT,
    email VARCHAR(100) UNIQUE
);
```

Now, two records cannot have the same non-NULL email address.

### Valid INSERT

```sql
INSERT INTO students
VALUES
(1, 'rahul@gmail.com'),
(2, 'priya@gmail.com');
```

### Invalid INSERT

```sql
INSERT INTO students
VALUES (3, 'rahul@gmail.com');
```

This produces an error because the email already exists.

**Important:** MySQL allows multiple NULL values in a UNIQUE column.

---

## 5. PRIMARY KEY Constraint

A `PRIMARY KEY` uniquely identifies every record in a table.

It combines two important rules:

- UNIQUE
- NOT NULL

### Example

```sql
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100),
    age INT
);
```

Here, `student_id` uniquely identifies each student.

### Valid INSERT

```sql
INSERT INTO students
VALUES
(101, 'Rahul', 22),
(102, 'Priya', 23);
```

### Invalid INSERT – Duplicate ID

```sql
INSERT INTO students
VALUES (101, 'Aman', 21);
```

This produces an error because student ID 101 already exists.

### Invalid INSERT – NULL ID

```sql
INSERT INTO students
VALUES (NULL, 'Aman', 21);
```

This also produces an error because a primary key cannot contain NULL.

### Composite Primary Key

A primary key can consist of multiple columns.

Example:

```sql
CREATE TABLE enrollments (
    student_id INT,
    course_id INT,
    enrollment_date DATE,
    PRIMARY KEY (student_id, course_id)
);
```

Here, the combination of `student_id` and `course_id` must be unique.

A student can enroll in multiple courses, but the same student-course combination cannot be inserted twice.

---

## 6. FOREIGN KEY Constraint

A foreign key creates a relationship between two tables.

It ensures that a value in the child table refers to an existing key value in the parent table, or is NULL if the column permits it.

### Example

First, create the parent table:

```sql
CREATE TABLE departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(100)
);
```

Insert department records:

```sql
INSERT INTO departments
VALUES
(1, 'IT'),
(2, 'HR'),
(3, 'Finance');
```

Now create the child table:

```sql
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    name VARCHAR(100),
    department_id INT,
    FOREIGN KEY (department_id)
        REFERENCES departments(department_id)
);
```

### Valid INSERT

```sql
INSERT INTO employees
VALUES (101, 'Rahul', 1);
```

This works because department ID 1 exists in the parent table.

### Invalid INSERT

```sql
INSERT INTO employees
VALUES (102, 'Priya', 10);
```

This produces an error because department ID 10 does not exist in the `departments` table.

### Understanding the Relationship

**Parent table – departments**

| department_id | department_name |
|---:|---|
| 1 | IT |
| 2 | HR |
| 3 | Finance |

**Child table – employees**

| employee_id | name | department_id |
|---:|---|---:|
| 101 | Rahul | 1 |

The employee's department ID must refer to an existing department.

### ON DELETE CASCADE

This option automatically deletes matching child records when the referenced parent record is deleted.

```sql
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    name VARCHAR(100),
    department_id INT,
    FOREIGN KEY (department_id)
        REFERENCES departments(department_id)
        ON DELETE CASCADE
);
```

If department ID 1 is deleted, employees referencing department ID 1 are also deleted.

### Other Referential Actions

| Action | Meaning |
|---|---|
| CASCADE | Automatically updates or deletes matching child records |
| SET NULL | Sets the foreign key to NULL |
| RESTRICT | Prevents the parent record from being deleted or updated when matching child records exist |
| NO ACTION | Similar to RESTRICT in MySQL |

**Important:** `SET NULL` requires the foreign key column to allow NULL values.

---

## 7. CHECK Constraint

The `CHECK` constraint ensures that values satisfy a specified condition.

### Example

```sql
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100),
    age INT CHECK (age >= 18)
);
```

Here, the age must be at least 18.

### Valid INSERT

```sql
INSERT INTO students
VALUES (1, 'Rahul', 22);
```

### Invalid INSERT

```sql
INSERT INTO students
VALUES (2, 'Priya', 15);
```

This produces an error because 15 does not satisfy the condition.

### Multiple CHECK Conditions

```sql
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    name VARCHAR(100),
    salary DECIMAL(10,2),
    age INT,
    CHECK (salary > 0),
    CHECK (age >= 18)
);
```

Now:

- Salary must be greater than zero.
- Age must be at least 18.

**Note:** In MySQL 8.0.16 and later, CHECK constraints are enforced. Earlier versions generally parsed but ignored them.

---

## 8. DEFAULT Constraint

The `DEFAULT` constraint provides a default value when an INSERT statement does not supply a value for that column.

### Example

```sql
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    name VARCHAR(100),
    department VARCHAR(50) DEFAULT 'IT'
);
```

Insert a record without specifying the department:

```sql
INSERT INTO employees (employee_id, name)
VALUES (101, 'Rahul');
```

The department is automatically assigned the default value `IT`.

### Result

| employee_id | name | department |
|---:|---|---|
| 101 | Rahul | IT |

**Important:** An explicitly supplied NULL is not replaced by the default value. A NOT NULL constraint may reject it.

---

## 9. Combining Multiple Constraints

We can apply multiple constraints to a single table.

Example:

```sql
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE,
    age INT CHECK (age >= 18),
    course VARCHAR(50) DEFAULT 'MCA'
);
```

### Understanding the Rules

| Column | Constraint | Purpose |
|---|---|---|
| student_id | PRIMARY KEY | Unique identification |
| name | NOT NULL | Name cannot be NULL |
| email | UNIQUE | Prevents duplicate non-NULL emails |
| age | CHECK | Age must be at least 18 |
| course | DEFAULT | Defaults to MCA |

## 10. Adding Constraints Using ALTER TABLE

Constraints can also be added after creating a table.

### Add UNIQUE

```sql
ALTER TABLE students
ADD CONSTRAINT unique_email UNIQUE (email);
```

### Add CHECK

```sql
ALTER TABLE students
ADD CONSTRAINT check_age CHECK (age >= 18);
```

### Add FOREIGN KEY

```sql
ALTER TABLE employees
ADD CONSTRAINT fk_department
FOREIGN KEY (department_id)
REFERENCES departments(department_id);
```

### Add PRIMARY KEY

```sql
ALTER TABLE students
ADD PRIMARY KEY (student_id);
```

This works only if the existing data satisfies the primary key requirements.

### Drop a Constraint

Remove a UNIQUE constraint:

```sql
ALTER TABLE students
DROP INDEX unique_email;
```

Remove a foreign key:

```sql
ALTER TABLE employees
DROP FOREIGN KEY fk_department;
```

Remove a CHECK constraint:

```sql
ALTER TABLE students
DROP CHECK check_age;
```

## 11. Difference Between PRIMARY KEY and UNIQUE

| Feature | PRIMARY KEY | UNIQUE |
|---|---|---|
| Duplicate values | Not allowed | Not allowed |
| NULL values | Not allowed | MySQL allows multiple NULL values |
| Number per table | One primary key constraint | Multiple UNIQUE constraints |
| Purpose | Identifies each record | Prevents duplicate values |

Example:

```sql
CREATE TABLE users (
    user_id INT PRIMARY KEY,
    email VARCHAR(100) UNIQUE,
    username VARCHAR(50) UNIQUE
);
```

Here:

- `user_id` uniquely identifies a user.
- `email` must be unique.
- `username` must also be unique.

## 12. Constraint Summary

| Constraint | Main Purpose |
|---|---|
| NOT NULL | Prevents NULL values |
| UNIQUE | Prevents duplicate values |
| PRIMARY KEY | Uniquely identifies records |
| FOREIGN KEY | Maintains relationships between tables |
| CHECK | Validates values using a condition |
| DEFAULT | Supplies a default value |

## 13. Interview Questions

**Q1. What are constraints in SQL?**

Constraints are rules applied to columns or tables to maintain data accuracy and integrity.

**Q2. What is the difference between PRIMARY KEY and UNIQUE?**

A primary key uniquely identifies records and does not allow NULL. A UNIQUE constraint prevents duplicate non-NULL values, but MySQL allows multiple NULL values.

**Q3. Can a table have multiple primary keys?**

No. A table can have only one primary key constraint, but it can contain multiple columns as a composite primary key.

**Q4. What is a foreign key?**

A foreign key is a column or group of columns that references a key in another table, maintaining referential integrity.

**Q5. What happens when we use ON DELETE CASCADE?**

Deleting a referenced parent record automatically deletes matching child records.

**Q6. What is the purpose of CHECK?**

It validates values against a specified condition.

**Q7. What is the purpose of DEFAULT?**

It provides a predefined value when a column is omitted from an INSERT statement.

**Q8. Can UNIQUE and NOT NULL be used together?**

Yes. This ensures that a column contains a value and that the value is unique.

**Q9. Can a foreign key contain NULL?**

Yes, provided the foreign key column permits NULL and no NOT NULL constraint is applied.

**Q10. Can we add constraints after creating a table?**

Yes. We can use `ALTER TABLE` to add constraints.

## 15. Key Takeaways

- Constraints are rules that protect database integrity.
- PRIMARY KEY uniquely identifies records.
- FOREIGN KEY connects related tables.
- UNIQUE prevents duplicate non-NULL values.
- NOT NULL prevents missing values.
- CHECK validates data using conditions.
- DEFAULT supplies values when a column is omitted.
- ALTER TABLE can add or remove constraints.

**Remember:** Constraints make sure that invalid data does not enter your database.
