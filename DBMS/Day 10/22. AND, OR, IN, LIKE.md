# AND, OR, IN, LIKE Operators in SQL (MySQL)

## 1. Introduction

SQL provides different operators to filter records based on specific conditions.

The four important operators covered in this topic are:

| Operator | Purpose |
|---|---|
| `AND` | All conditions must be true |
| `OR` | At least one condition must be true |
| `IN` | Checks whether a value matches any value in a list |
| `LIKE` | Searches for a specific pattern in text |

These operators are commonly used with the `WHERE` clause.

## 3. AND Operator

The `AND` operator is used when multiple conditions must all be satisfied.

**Syntax:**

```sql
SELECT column_names
FROM table_name
WHERE condition1 AND condition2;
```

### Example 1: Employees working in IT and located in Chennai

```sql
SELECT *
FROM employees
WHERE department = 'IT'
AND city = 'Chennai';
```

**Output:**

| employee_id | name | department | city | salary |
|---|---|---|---|---:|
| 1 | Rahul | IT | Chennai | 50000 |
| 3 | Arjun | IT | Chennai | 60000 |

Both conditions must be true.

### Example 2: Employees earning more than ₹40,000 and less than ₹60,000

```sql
SELECT *
FROM employees
WHERE salary > 40000
AND salary < 60000;
```

**Output:**

| name | salary |
|---|---:|
| Rahul | 50000 |
| Priya | 45000 |
| Meera | 55000 |
| Neha | 42000 |

### Important

If even one condition is false, the complete `AND` expression becomes false.

| Condition 1 | Condition 2 | AND Result |
|---|---|---|
| TRUE | TRUE | TRUE |
| TRUE | FALSE | FALSE |
| FALSE | TRUE | FALSE |
| FALSE | FALSE | FALSE |

---

## 4. OR Operator

The `OR` operator is used when at least one condition must be satisfied.

**Syntax:**

```sql
SELECT column_names
FROM table_name
WHERE condition1 OR condition2;
```

### Example 1: Employees working in IT or HR

```sql
SELECT *
FROM employees
WHERE department = 'IT'
OR department = 'HR';
```

**Output:**

| name | department |
|---|---|
| Rahul | IT |
| Sneha | HR |
| Arjun | IT |
| Kiran | HR |
| Aman | IT |
| Neha | HR |

### Example 2: Employees located in Chennai or earning more than ₹60,000

```sql
SELECT *
FROM employees
WHERE city = 'Chennai'
OR salary > 60000;
```

**Output:**

| name | city | salary |
|---|---|---:|
| Rahul | Chennai | 50000 |
| Arjun | Chennai | 60000 |
| Meera | Chennai | 55000 |
| Aman | Bangalore | 70000 |
| Neha | Chennai | 42000 |

An employee is included if either condition is true.

### OR Truth Table

| Condition 1 | Condition 2 | OR Result |
|---|---|---|
| TRUE | TRUE | TRUE |
| TRUE | FALSE | TRUE |
| FALSE | TRUE | TRUE |
| FALSE | FALSE | FALSE |

---

## 5. Difference Between AND and OR

| AND | OR |
|---|---|
| All conditions must be true | At least one condition must be true |
| Usually makes filtering more restrictive | Usually makes filtering less restrictive |
| Example: IT AND Chennai | Example: IT OR Chennai |

### Example Comparison

**Using AND:**

```sql
SELECT *
FROM employees
WHERE department = 'IT'
AND city = 'Chennai';
```

Returns employees who satisfy both conditions.

**Using OR:**

```sql
SELECT *
FROM employees
WHERE department = 'IT'
OR city = 'Chennai';
```

Returns employees who satisfy either condition or both.

---

## 6. Combining AND and OR

We can combine `AND` and `OR` in the same query.

### Example

Find employees who:

- Work in IT and live in Chennai, OR
- Work in HR and live in Mumbai.

```sql
SELECT *
FROM employees
WHERE (department = 'IT' AND city = 'Chennai')
OR (department = 'HR' AND city = 'Mumbai');
```

**Output:**

| name | department | city |
|---|---|---|
| Rahul | IT | Chennai |
| Arjun | IT | Chennai |
| Kiran | HR | Mumbai |

### Why use parentheses?

Parentheses make the intended condition grouping clear.

SQL evaluates `AND` before `OR` when parentheses do not specify otherwise.

For example:

```sql
WHERE department = 'IT'
OR department = 'HR'
AND city = 'Chennai';
```

This is interpreted as:

```sql
WHERE department = 'IT'
OR (department = 'HR' AND city = 'Chennai');
```

It does not mean:

```sql
WHERE (department = 'IT' OR department = 'HR')
AND city = 'Chennai';
```

Use parentheses whenever combining `AND` and `OR` to avoid unexpected results.

## 7. IN Operator

The `IN` operator checks whether a value matches any value in a specified list.

It is a cleaner alternative to writing multiple `OR` conditions.

**Syntax:**

```sql
SELECT column_names
FROM table_name
WHERE column_name IN (value1, value2, value3);
```

### Example 1: Employees working in IT, HR, or Finance

Using OR:

```sql
SELECT *
FROM employees
WHERE department = 'IT'
OR department = 'HR'
OR department = 'Finance';
```

Using IN:

```sql
SELECT *
FROM employees
WHERE department IN ('IT', 'HR', 'Finance');
```

Both queries return the same matching employees.

### Example 2: Employees located in Chennai or Mumbai

```sql
SELECT *
FROM employees
WHERE city IN ('Chennai', 'Mumbai');
```

**Output:**

| name | city |
|---|---|
| Rahul | Chennai |
| Arjun | Chennai |
| Kiran | Mumbai |
| Meera | Chennai |
| Neha | Chennai |

### Example 3: Employees earning one of the specified salaries

```sql
SELECT *
FROM employees
WHERE salary IN (35000, 45000, 55000);
```

**Output:**

| name | salary |
|---|---:|
| Priya | 45000 |
| Kiran | 35000 |
| Meera | 55000 |

### NOT IN

`NOT IN` returns rows whose values do not match any value in the list.

```sql
SELECT *
FROM employees
WHERE department NOT IN ('IT', 'HR');
```

**Output:**

| name | department |
|---|---|
| Priya | Finance |
| Meera | Finance |

**Important NULL behavior:** If a `NOT IN` list contains NULL, comparisons can evaluate to UNKNOWN and unexpectedly return no matching rows. Be careful when using `NOT IN` with a subquery that may return NULL.

## 8. LIKE Operator

The `LIKE` operator is used to search for a particular pattern in a text column.

It is commonly used with wildcard characters.

MySQL supports two important wildcards:

| Wildcard | Meaning |
|---|---|
| `%` | Matches zero or more characters |
| `_` | Matches exactly one character |

### 8.1 Percentage (%) Wildcard

The `%` wildcard matches zero or more characters.

#### Example 1: Names starting with A

```sql
SELECT *
FROM employees
WHERE name LIKE 'A%';
```

**Output:**

| name |
|---|
| Arjun |
| Aman |

`A%` means:

- Starts with A.
- Can have any number of characters after A.

#### Example 2: Names ending with a

```sql
SELECT *
FROM employees
WHERE name LIKE '%a';
```

**Output:**

| name |
|---|
| Sneha |
| Priya |
| Meera |
| Neha |

#### Example 3: Names containing the letter e

```sql
SELECT *
FROM employees
WHERE name LIKE '%e%';
```

**Output:**

| name |
|---|
| Sneha |
| Meera |
| Neha |

#### Example 4: Names starting with R and ending with l

```sql
SELECT *
FROM employees
WHERE name LIKE 'R%l';
```

**Output:**

| name |
|---|
| Rahul |

### 8.2 Underscore (_) Wildcard

The `_` wildcard matches exactly one character.

#### Example 1: Names containing exactly four characters

```sql
SELECT *
FROM employees
WHERE name LIKE '____';
```

**Output:**

| name |
|---|
| Neha |

There are four underscores, so exactly four characters must match.

#### Example 2: Names starting with R followed by exactly four characters

```sql
SELECT *
FROM employees
WHERE name LIKE 'R____';
```

**Output:**

| name |
|---|
| Rahul |

The pattern has one R followed by four characters.

#### Example 3: Names with A as the second character

```sql
SELECT *
FROM employees
WHERE name LIKE '_a%';
```

This matches names whose second character is `a`.

**Output:**

| name |
|---|
| Rahul |
| Kiran |

---

## 9. NOT LIKE Operator

`NOT LIKE` returns rows that do not match a specified pattern.

### Example: Names that do not start with A

```sql
SELECT *
FROM employees
WHERE name NOT LIKE 'A%';
```

**Output:**

| name |
|---|
| Rahul |
| Sneha |
| Priya |
| Kiran |
| Meera |
| Neha |

---

## 10. Combining AND, OR, IN, and LIKE

These operators can be combined to create more advanced filtering conditions.

### Example 1

Find employees who work in IT or HR and whose salary is greater than ₹40,000.

```sql
SELECT *
FROM employees
WHERE department IN ('IT', 'HR')
AND salary > 40000;
```

**Output:**

| name | department | salary |
|---|---|---:|
| Rahul | IT | 50000 |
| Arjun | IT | 60000 |
| Aman | IT | 70000 |
| Neha | HR | 42000 |

### Example 2

Find employees whose names start with A or R and who earn more than ₹40,000.

```sql
SELECT *
FROM employees
WHERE (name LIKE 'A%' OR name LIKE 'R%')
AND salary > 40000;
```

**Output:**

| name | salary |
|---|---:|
| Rahul | 50000 |
| Arjun | 60000 |
| Aman | 70000 |

### Example 3

Find employees located in Chennai or Bangalore who work in Finance.

```sql
SELECT *
FROM employees
WHERE city IN ('Chennai', 'Bangalore')
AND department = 'Finance';
```

**Output:**

| name | department | city |
|---|---|---|
| Priya | Finance | Bangalore |
| Meera | Finance | Chennai |

## 11. Case Sensitivity in LIKE

Whether `LIKE` is case-sensitive depends on the collation of the column or expression.

Many common MySQL collations are case-insensitive.

For example, under a case-insensitive collation:

```sql
SELECT *
FROM employees
WHERE name LIKE 'rah%';
```

This can match `Rahul`.

To force case-sensitive matching in MySQL, you can use:

```sql
SELECT *
FROM employees
WHERE name LIKE BINARY 'Rah%';
```

The `BINARY` approach performs a case-sensitive comparison.

## 12. Common Mistakes

### Mistake 1: Using = with multiple values

Incorrect:

```sql
WHERE department = ('IT', 'HR');
```

Correct:

```sql
WHERE department IN ('IT', 'HR');
```

### Mistake 2: Forgetting wildcards

```sql
WHERE name LIKE 'A';
```

This matches only the exact string `A`.

To find names starting with A:

```sql
WHERE name LIKE 'A%';
```

### Mistake 3: Using AND when OR is required

```sql
WHERE department = 'IT'
AND department = 'HR';
```

A single department value cannot normally be both IT and HR at the same time.

Use:

```sql
WHERE department IN ('IT', 'HR');
```

### Mistake 4: Ignoring operator precedence

When combining `AND` and `OR`, use parentheses to make your intended logic explicit.

## 13. Quick Revision

| Requirement | SQL Condition |
|---|---|
| Both conditions must be true | `condition1 AND condition2` |
| Either condition can be true | `condition1 OR condition2` |
| Match one of several values | `column IN (value1, value2)` |
| Does not match listed values | `column NOT IN (value1, value2)` |
| Starts with A | `column LIKE 'A%'` |
| Ends with A | `column LIKE '%A'` |
| Contains A | `column LIKE '%A%'` |
| Exactly four characters | `column LIKE '____'` |
| Does not match a pattern | `column NOT LIKE 'A%'` |

## 16. Key Takeaways

- `AND` requires all conditions to be true.
- `OR` requires at least one condition to be true.
- `IN` checks whether a value exists in a specified list.
- `NOT IN` excludes specified values.
- `LIKE` performs pattern matching.
- `%` represents zero or more characters.
- `_` represents exactly one character.
- `NOT LIKE` excludes matching patterns.
- Parentheses help control the order of combined conditions.
- MySQL `LIKE` case sensitivity depends on collation.
