# Relational Model Constraints – Advanced

## 1. Introduction

Constraints are rules applied to database tables to maintain data accuracy, consistency, and integrity.

They prevent invalid data from being inserted, updated, or deleted.

For example, in a Student Management System:

- Every student must have a unique student ID.
- Student names should not be NULL.
- Age should be within an acceptable range.
- Every department ID must refer to an existing department.

These rules are implemented using database constraints.

## 2. Types of Relational Model Constraints

The major constraints in relational databases include:

1. Domain Constraints
2. Key Constraints
3. Entity Integrity Constraints
4. Referential Integrity Constraints
5. NOT NULL Constraints
6. UNIQUE Constraints
7. CHECK Constraints
8. DEFAULT Constraints

---

## 3. Domain Constraints

A Domain Constraint defines the valid values that an attribute can contain.

It ensures that a column stores values belonging to its specified domain.

### Example

Consider a Students table.

| student_id | name | age |
|---|---|---:|
| 1 | Rahul | 22 |
| 2 | Priya | 23 |
| 3 | Amit | 21 |

Here:

- student_id should contain integers.
- name should contain text.
- age should contain valid numeric values.

### SQL Implementation

```sql
CREATE TABLE Students (
    student_id INT,
    name VARCHAR(50),
    age INT
);
```

Here, INT and VARCHAR define the data types of the attributes.

We can also use CHECK constraints to enforce additional domain rules.

```sql
CREATE TABLE Students (
    student_id INT,
    name VARCHAR(50),
    age INT CHECK (age >= 18)
);
```

Now the age must be at least 18.

## 4. Key Constraints

Key Constraints ensure that records can be uniquely identified.

A key can consist of one or multiple attributes.

### Types of Keys

- Super Key
- Candidate Key
- Primary Key
- Alternate Key
- Foreign Key
- Composite Key

### Example

| student_id | email | name |
|---|---|---|
| 1 | rahul@gmail.com | Rahul |
| 2 | priya@gmail.com | Priya |
| 3 | amit@gmail.com | Amit |

Here:

- student_id uniquely identifies each student.
- email also uniquely identifies each student, assuming emails are unique.

### SQL Implementation

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    email VARCHAR(100) UNIQUE,
    name VARCHAR(50)
);
```

Here:

- student_id is the Primary Key.
- email is another unique candidate key.

---

## 5. Entity Integrity Constraint

Entity Integrity states that a Primary Key cannot contain NULL values.

Every record must have a valid identifier.

### Example

Consider the following table:

| student_id | name |
|---|---|
| 1 | Rahul |
| 2 | Priya |
| NULL | Amit |

The third record violates Entity Integrity because the Primary Key cannot be NULL.

### SQL Implementation

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50)
);
```

The PRIMARY KEY constraint automatically ensures:

- Unique values.
- No NULL values.

### Important Points

- Every table should have a Primary Key for reliable row identification.
- A Primary Key cannot contain NULL.
- A Primary Key can consist of multiple columns.

---

## 6. Referential Integrity Constraint

Referential Integrity ensures that a Foreign Key references an existing record in the parent table, or contains NULL if NULL is permitted.

### Example

Consider two tables.

**Departments Table**

| department_id | department_name |
|---|---|
| 101 | IT |
| 102 | HR |
| 103 | Finance |

**Employees Table**

| employee_id | employee_name | department_id |
|---|---|---|
| 1 | Rahul | 101 |
| 2 | Priya | 102 |
| 3 | Amit | 101 |

Here:

- department_id in Departments is the Primary Key.
- department_id in Employees is the Foreign Key.

### SQL Implementation

```sql
CREATE TABLE Departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(50)
);

CREATE TABLE Employees (
    employee_id INT PRIMARY KEY,
    employee_name VARCHAR(50),
    department_id INT,

    FOREIGN KEY (department_id)
        REFERENCES Departments(department_id)
);
```

### What Happens If We Insert Invalid Data?

```sql
INSERT INTO Employees
VALUES (4, 'Kiran', 999);
```

This operation fails because department_id 999 does not exist in Departments.

### Important Points

- A Foreign Key references a candidate key, commonly the Primary Key, in another table.
- Foreign Keys maintain relationships between tables.
- A Foreign Key can contain duplicate values.
- A Foreign Key can contain NULL if it is nullable.
- Invalid references are rejected.

## 7. NOT NULL Constraint

The NOT NULL constraint ensures that a column cannot contain NULL values.

### Example

Every student must have a name.

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    age INT
);
```

The following query fails because the name is missing:

```sql
INSERT INTO Students
VALUES (1, NULL, 22);
```

### Important Points

- NOT NULL prevents missing values in a column.
- It is useful for mandatory information.
- A column can have NOT NULL without being a Primary Key.

---

## 8. UNIQUE Constraint

The UNIQUE constraint ensures that all non-NULL values in a column or combination of columns are unique.

### Example

Every student must have a different email address.

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    email VARCHAR(100) UNIQUE
);
```

The following records are valid:

| student_id | name | email |
|---|---|---|
| 1 | Rahul | rahul@gmail.com |
| 2 | Priya | priya@gmail.com |

But inserting another student with rahul@gmail.com will violate the UNIQUE constraint.

### Important Points

- UNIQUE prevents duplicate values.
- A table can have multiple UNIQUE constraints.
- NULL handling depends on the DBMS.
- MySQL permits multiple NULL values in a UNIQUE column.

---

## 9. CHECK Constraint

The CHECK constraint ensures that values satisfy a specified condition.

### Example 1: Age Restriction

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT CHECK (age >= 18)
);
```

Age must be at least 18.

### Example 2: Salary Restriction

```sql
CREATE TABLE Employees (
    employee_id INT PRIMARY KEY,
    employee_name VARCHAR(50),
    salary DECIMAL(10,2) CHECK (salary > 0)
);
```

Salary must be greater than zero.

### Example 3: Multiple Conditions

```sql
CREATE TABLE Products (
    product_id INT PRIMARY KEY,
    product_name VARCHAR(50),
    price DECIMAL(10,2),
    quantity INT,

    CHECK (price > 0 AND quantity >= 0)
);
```

Both conditions must be satisfied.

## 10. DEFAULT Constraint

The DEFAULT constraint assigns a predefined value when no value is supplied for a column during insertion.

### Example

```sql
CREATE TABLE Employees (
    employee_id INT PRIMARY KEY,
    employee_name VARCHAR(50),
    city VARCHAR(50) DEFAULT 'Chennai'
);
```

Insert a record without specifying the city:

```sql
INSERT INTO Employees
(employee_id, employee_name)
VALUES
(1, 'Rahul');
```

Result:

| employee_id | employee_name | city |
|---|---|---|
| 1 | Rahul | Chennai |

The database automatically assigns Chennai.

**Important:** Explicitly inserting NULL does not activate the DEFAULT value.

## 11. ON DELETE and ON UPDATE Actions

Foreign Keys can define what happens when a referenced parent record is deleted or updated.

Common actions include:

### 11.1 ON DELETE CASCADE

When a parent record is deleted, its related child records are also deleted.

```sql
CREATE TABLE Departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(50)
);

CREATE TABLE Employees (
    employee_id INT PRIMARY KEY,
    employee_name VARCHAR(50),
    department_id INT,

    FOREIGN KEY (department_id)
        REFERENCES Departments(department_id)
        ON DELETE CASCADE
);
```

Example:

Deleting department 101 automatically deletes employees belonging to department 101.

### 11.2 ON DELETE SET NULL

When a parent record is deleted, the related Foreign Key values in child records become NULL.

```sql
CREATE TABLE Employees (
    employee_id INT PRIMARY KEY,
    employee_name VARCHAR(50),
    department_id INT NULL,

    FOREIGN KEY (department_id)
        REFERENCES Departments(department_id)
        ON DELETE SET NULL
);
```

### 11.3 ON DELETE RESTRICT

Prevents deleting a parent record if related child records exist.

```sql
FOREIGN KEY (department_id)
REFERENCES Departments(department_id)
ON DELETE RESTRICT
```

### 11.4 ON UPDATE CASCADE

When a referenced parent key changes, the corresponding Foreign Key values in child records are updated automatically.

```sql
FOREIGN KEY (department_id)
REFERENCES Departments(department_id)
ON UPDATE CASCADE
```

## 12. Difference Between Important Constraints

| Constraint | Purpose |
|---|---|
| PRIMARY KEY | Uniquely identifies each record |
| FOREIGN KEY | Maintains relationships between tables |
| UNIQUE | Prevents duplicate non-NULL values |
| NOT NULL | Prevents NULL values |
| CHECK | Validates a condition |
| DEFAULT | Supplies a predefined value |

## 13. Complete Practical Example

Let's create a Student Management System using multiple constraints.

### Step 1: Create Departments

```sql
CREATE TABLE Departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(50) UNIQUE NOT NULL
);
```

### Step 2: Create Students

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    age INT CHECK (age >= 18),
    city VARCHAR(50) DEFAULT 'Chennai',
    department_id INT,

    FOREIGN KEY (department_id)
        REFERENCES Departments(department_id)
);
```

### Step 3: Insert Departments

```sql
INSERT INTO Departments VALUES
(101, 'Computer Science'),
(102, 'Data Science'),
(103, 'Information Technology');
```

### Step 4: Insert Students

```sql
INSERT INTO Students
(student_id, student_name, email, age, department_id)
VALUES
(1, 'Rahul', 'rahul@gmail.com', 22, 101),
(2, 'Priya', 'priya@gmail.com', 23, 102),
(3, 'Amit', 'amit@gmail.com', 21, 101);
```

### Step 5: Display Students

```sql
SELECT * FROM Students;
```

### Expected Output

| student_id | student_name | email | age | city | department_id |
|---|---|---|---:|---|---|
| 1 | Rahul | rahul@gmail.com | 22 | Chennai | 101 |
| 2 | Priya | priya@gmail.com | 23 | Chennai | 102 |
| 3 | Amit | amit@gmail.com | 21 | Chennai | 101 |

This example demonstrates:

- PRIMARY KEY
- FOREIGN KEY
- UNIQUE
- NOT NULL
- CHECK
- DEFAULT

## 16. Key Takeaways

- Constraints are rules applied to database tables.
- Domain Constraints restrict valid attribute values.
- Key Constraints ensure unique identification.
- Entity Integrity prevents NULL Primary Keys.
- Referential Integrity maintains valid Foreign Key references.
- NOT NULL prevents missing values.
- UNIQUE prevents duplicate non-NULL values.
- CHECK validates conditions.
- DEFAULT supplies predefined values.
- CASCADE automatically propagates certain parent changes.
- RESTRICT prevents certain operations that would violate relationships.
- Constraints help maintain data accuracy and consistency.
