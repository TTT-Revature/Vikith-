# Views in SQL (MySQL)

## 1. What Is a View?

A VIEW is a virtual table created using a SQL query.

It does not normally store the actual result data separately. Instead, it stores the query definition and retrieves data from the underlying tables when the view is queried.

A view can contain:
- Selected columns from a table.
- Filtered records.
- Data from multiple tables using JOINs.
- Aggregate results.

### Real-World Example

Imagine a company has an `employees` table containing:

- Employee ID
- Name
- Email
- Salary
- Phone number
- Department ID

The HR team may need only employee names, emails, and department information.

Instead of repeatedly writing the same query, we can create a VIEW containing the required columns.

---

## 2. Why Do We Use Views?

Views provide several advantages:

1. **Simplification:** Hide complex SQL queries behind a simple view name.
2. **Security:** Expose only selected columns or rows to users.
3. **Reusability:** Reuse frequently required queries.
4. **Consistency:** Provide a common definition of calculated or filtered data.
5. **Abstraction:** Users can query a simplified representation of underlying tables.

## 4. CREATE VIEW Statement

The `CREATE VIEW` statement is used to create a view.

### Syntax

```sql
CREATE VIEW view_name AS
SELECT column_names
FROM table_name
WHERE condition;
```

### Example: Create a view containing employee names and departments.

```sql
CREATE VIEW employee_details AS
SELECT
    employee_id,
    name,
    department
FROM employees;
```

The view is now created.

### Query the View

```sql
SELECT *
FROM employee_details;
```

**Output:**

| employee_id | name | department |
|---|---|---|
| 1 | Rahul | IT |
| 2 | Sneha | HR |
| 3 | Arjun | IT |
| 4 | Priya | Finance |
| 5 | Kiran | HR |
| 6 | Meera | Finance |

Notice that we are querying the view just like a table.

---

## 5. Creating a View with WHERE

A view can contain filtering conditions.

### Example: Create a view for IT employees.

```sql
CREATE VIEW it_employees AS
SELECT
    employee_id,
    name,
    salary
FROM employees
WHERE department = 'IT';
```

Query:

```sql
SELECT *
FROM it_employees;
```

**Output:**

| employee_id | name | salary |
|---|---|---:|
| 1 | Rahul | 50000 |
| 3 | Arjun | 60000 |

The view displays only employees belonging to IT.

---

## 6. Creating a View Using JOIN

Views can combine information from multiple tables.

Consider these two tables:

### Employees

| employee_id | name | department_id |
|---|---|---|
| 1 | Rahul | 101 |
| 2 | Sneha | 102 |
| 3 | Arjun | 101 |

### Departments

| department_id | department_name |
|---|---|
| 101 | IT |
| 102 | HR |

### Create a View

```sql
CREATE VIEW employee_department_view AS
SELECT
    e.employee_id,
    e.name,
    d.department_name
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id;
```

Query:

```sql
SELECT *
FROM employee_department_view;
```

**Output:**

| employee_id | name | department_name |
|---|---|---|
| 1 | Rahul | IT |
| 2 | Sneha | HR |
| 3 | Arjun | IT |

We can now retrieve employee and department information without rewriting the JOIN every time.

---

## 7. Creating a View with Aggregate Functions

Views can also contain aggregate calculations.

### Example: Create a view showing department-wise average salaries.

```sql
CREATE VIEW department_salary_summary AS
SELECT
    department,
    COUNT(*) AS total_employees,
    AVG(salary) AS average_salary,
    SUM(salary) AS total_salary
FROM employees
GROUP BY department;
```

Query:

```sql
SELECT *
FROM department_salary_summary;
```

**Output:**

| department | total_employees | average_salary | total_salary |
|---|---:|---:|---:|
| Finance | 2 | 50000 | 100000 |
| HR | 2 | 37500 | 75000 |
| IT | 2 | 55000 | 110000 |

This is useful for reporting and analytics.

## 8. CREATE OR REPLACE VIEW

If a view already exists, we can replace its definition using `CREATE OR REPLACE VIEW`.

### Syntax

```sql
CREATE OR REPLACE VIEW view_name AS
SELECT column_names
FROM table_name;
```

### Example

Initially:

```sql
CREATE VIEW employee_details AS
SELECT employee_id, name
FROM employees;
```

Now update the view to include department and salary:

```sql
CREATE OR REPLACE VIEW employee_details AS
SELECT
    employee_id,
    name,
    department,
    salary
FROM employees;
```

The existing view definition is replaced with the new query.

---

## 9. ALTER VIEW

MySQL also supports `ALTER VIEW` to modify an existing view definition.

### Syntax

```sql
ALTER VIEW view_name AS
SELECT column_names
FROM table_name;
```

### Example

```sql
ALTER VIEW employee_details AS
SELECT
    employee_id,
    name,
    city
FROM employees;
```

The view now exposes employee ID, name, and city.

---

## 10. DROP VIEW

The `DROP VIEW` statement removes a view from the database.

### Syntax

```sql
DROP VIEW view_name;
```

### Example

```sql
DROP VIEW employee_details;
```

This removes the view definition.

**Important:** Dropping a view does not delete the underlying employees table or its records.

### Drop Multiple Views

```sql
DROP VIEW employee_details, it_employees;
```

### Use IF EXISTS

```sql
DROP VIEW IF EXISTS employee_details;
```

This avoids an error if the view does not exist.

## 11. Updating Data Through a View

Some views allow INSERT, UPDATE, and DELETE operations.

These are called updatable views.

### Example

Create a simple view:

```sql
CREATE VIEW employee_basic AS
SELECT
    employee_id,
    name,
    department
FROM employees;
```

Update an employee through the view:

```sql
UPDATE employee_basic
SET department = 'Finance'
WHERE employee_id = 1;
```

This updates the underlying `employees` table.

### Verify the Change

```sql
SELECT *
FROM employees
WHERE employee_id = 1;
```

**Output:**

| employee_id | name | department |
|---|---|---|
| 1 | Rahul | Finance |

### Important

Not every view is updatable.

A view is generally not updatable when its definition contains features such as:

- Aggregate functions like `SUM()` and `AVG()`.
- `GROUP BY`.
- `DISTINCT`.
- `UNION`.
- Certain joins and other complex query structures.

MySQL has specific rules for determining whether a view can be updated.

---

## 12. WITH CHECK OPTION

`WITH CHECK OPTION` prevents INSERT or UPDATE operations through a view from creating rows that do not satisfy the view's WHERE condition.

### Example

```sql
CREATE VIEW it_employees AS
SELECT
    employee_id,
    name,
    department
FROM employees
WHERE department = 'IT'
WITH CHECK OPTION;
```

Now try:

```sql
UPDATE it_employees
SET department = 'HR'
WHERE employee_id = 1;
```

This update is rejected because the modified row would no longer satisfy the view condition.

### Why Is This Useful?

It ensures that changes made through the view continue to satisfy its filtering condition.

## 13. Views vs Tables

| View | Table |
|---|---|
| Virtual table based on a query | Stores actual table data |
| Stores a query definition | Stores rows and columns |
| Usually does not store result data separately | Stores data |
| Can simplify complex queries | Stores the underlying records |
| Can expose selected columns | Contains its defined columns |
| Depends on underlying tables | Can exist independently of a view |

**Important:** MySQL also supports other storage mechanisms, such as materialized-result tables built manually. A regular MySQL view is not a materialized view.

---

## 14. Views vs Subqueries

| View | Subquery |
|---|---|
| Named database object | Query nested inside another query |
| Can be reused across multiple queries | Usually written as part of a specific statement |
| Created using CREATE VIEW | Written inside SELECT, FROM, or WHERE |
| Stored as a database object | Not created as a separate database object |

### Subquery Example

```sql
SELECT *
FROM (
    SELECT department, AVG(salary) AS average_salary
    FROM employees
    GROUP BY department
) AS department_summary
WHERE average_salary > 45000;
```

### View Example

```sql
CREATE VIEW department_summary AS
SELECT
    department,
    AVG(salary) AS average_salary
FROM employees
GROUP BY department;
```

Then:

```sql
SELECT *
FROM department_summary
WHERE average_salary > 45000;
```

Both approaches can produce similar results.

## 15. Advantages and Limitations of Views

### Advantages

1. Reduces repeated SQL code.
2. Simplifies complex JOIN queries.
3. Helps restrict access to sensitive columns.
4. Makes reporting queries easier to reuse.
5. Provides a consistent way to access calculated results.

### Limitations

1. Views depend on underlying tables.
2. Complex views can be difficult to maintain.
3. Some views cannot be updated.
4. Views do not automatically improve query performance.
5. Changes to underlying tables can affect dependent views.

## 16. Important MySQL Commands

| Command | Purpose |
|---|---|
| `CREATE VIEW` | Creates a view |
| `CREATE OR REPLACE VIEW` | Creates or replaces a view |
| `ALTER VIEW` | Modifies a view definition |
| `DROP VIEW` | Removes a view |
| `SHOW FULL TABLES` | Lists tables and views |
| `SHOW CREATE VIEW` | Displays the SQL definition of a view |

### Example: Display All Views

```sql
SHOW FULL TABLES
WHERE Table_type = 'VIEW';
```

### Example: View the Definition

```sql
SHOW CREATE VIEW employee_details;
```

## 19. Key Takeaways

- A view is a virtual table based on a SQL query.
- A regular MySQL view stores a query definition, not a separate copy of the result data.
- Views can contain JOINs, WHERE conditions, and aggregate functions.
- `CREATE VIEW` creates a view.
- `CREATE OR REPLACE VIEW` replaces its definition.
- `ALTER VIEW` modifies its definition.
- `DROP VIEW` removes the view.
- Some views support INSERT, UPDATE, and DELETE.
- `WITH CHECK OPTION` enforces the view's filtering condition for changes made through it.
- Views are useful for simplifying queries and controlling data access.
