# Join Overview in SQL (MySQL)

## 1. What Is a JOIN?

A JOIN in SQL is used to combine rows from two or more tables based on a related column between them.

In a relational database, information is usually stored in separate tables to avoid unnecessary duplication.

For example, instead of storing department details repeatedly for every employee, we can maintain separate `employees` and `departments` tables.

JOINs help us retrieve information from these related tables.

---

## 2. Why Do We Need JOINs?

Consider two tables.

### Employees Table

| employee_id | name | department_id |
|---|---|---|
| 1 | Rahul | 101 |
| 2 | Sneha | 102 |
| 3 | Arjun | 101 |
| 4 | Priya | 103 |
| 5 | Kiran | NULL |

### Departments Table

| department_id | department_name |
|---|---|
| 101 | IT |
| 102 | HR |
| 103 | Finance |
| 104 | Marketing |

The `department_id` column connects these two tables.

- `employees.department_id` identifies an employee's department.
- `departments.department_id` identifies a department.

The relationship is established using this common column.

### Table Relationship

```text
Employees                         Departments
+-------------+                   +---------------+
| employee_id |                   | department_id |
| name        |                   | department_name|
| department_id| ---------------- |               |
+-------------+                   +---------------+
```

---

## 3. Basic JOIN Syntax

```sql
SELECT column_names
FROM table1
JOIN table2
ON table1.common_column = table2.common_column;
```

### Understanding the syntax

- `SELECT`: Specifies the columns to retrieve.
- `FROM`: Specifies the first table.
- `JOIN`: Specifies the second table.
- `ON`: Defines the condition used to match rows.

The matching condition usually uses a primary key and foreign key relationship.

---

## 4. Types of SQL JOINs

The major JOIN types are:

| JOIN Type | Purpose |
|---|---|
| INNER JOIN | Returns matching rows from both tables |
| LEFT JOIN | Returns all rows from the left table and matching rows from the right |
| RIGHT JOIN | Returns all rows from the right table and matching rows from the left |
| CROSS JOIN | Returns every possible combination of rows |
| SELF JOIN | Joins a table with itself |

We will study each JOIN with examples.

---

## 5. INNER JOIN

An `INNER JOIN` returns only the rows that have matching values in both tables.

### Syntax

```sql
SELECT columns
FROM table1
INNER JOIN table2
ON table1.common_column = table2.common_column;
```

### Example

```sql
SELECT
    employees.employee_id,
    employees.name,
    departments.department_name
FROM employees
INNER JOIN departments
ON employees.department_id = departments.department_id;
```

### Output

| employee_id | name | department_name |
|---|---|---|
| 1 | Rahul | IT |
| 2 | Sneha | HR |
| 3 | Arjun | IT |
| 4 | Priya | Finance |

### Explanation

- Rahul matches department 101.
- Sneha matches department 102.
- Arjun matches department 101.
- Priya matches department 103.
- Kiran has NULL department_id, so there is no match.
- Marketing has no matching employee.

Therefore, Kiran and Marketing are excluded.

**Remember:** INNER JOIN returns only matching records.

---

## 6. LEFT JOIN

A `LEFT JOIN` returns:

- All records from the left table.
- Matching records from the right table.
- NULL values for right-table columns when no match exists.

### Syntax

```sql
SELECT columns
FROM table1
LEFT JOIN table2
ON table1.common_column = table2.common_column;
```

### Example

```sql
SELECT
    employees.employee_id,
    employees.name,
    departments.department_name
FROM employees
LEFT JOIN departments
ON employees.department_id = departments.department_id;
```

### Output

| employee_id | name | department_name |
|---|---|---|
| 1 | Rahul | IT |
| 2 | Sneha | HR |
| 3 | Arjun | IT |
| 4 | Priya | Finance |
| 5 | Kiran | NULL |

### Explanation

All five employee records are returned.

Kiran does not have a matching department, so the department name becomes NULL.

**Remember:** LEFT JOIN preserves all records from the left table.

---

## 7. RIGHT JOIN

A `RIGHT JOIN` returns:

- All records from the right table.
- Matching records from the left table.
- NULL values for left-table columns when no match exists.

### Syntax

```sql
SELECT columns
FROM table1
RIGHT JOIN table2
ON table1.common_column = table2.common_column;
```

### Example

```sql
SELECT
    employees.employee_id,
    employees.name,
    departments.department_name
FROM employees
RIGHT JOIN departments
ON employees.department_id = departments.department_id;
```

### Output

| employee_id | name | department_name |
|---|---|---|
| 1 | Rahul | IT |
| 3 | Arjun | IT |
| 2 | Sneha | HR |
| 4 | Priya | Finance |
| NULL | NULL | Marketing |

### Explanation

All four department records are returned.

Marketing does not have any matching employee, so the employee columns contain NULL.

**Remember:** RIGHT JOIN preserves all records from the right table.

---

## 8. CROSS JOIN

A `CROSS JOIN` returns every possible combination of rows from two tables.

It is also called a Cartesian Product.

### Syntax

```sql
SELECT columns
FROM table1
CROSS JOIN table2;
```

### Example

Suppose we have these tables:

**Colors**

| color |
|---|
| Red |
| Blue |

**Sizes**

| size |
|---|
| Small |
| Large |
| Medium |

Query:

```sql
SELECT
    colors.color,
    sizes.size
FROM colors
CROSS JOIN sizes;
```

### Output

| color | size |
|---|---|
| Red | Small |
| Red | Large |
| Red | Medium |
| Blue | Small |
| Blue | Large |
| Blue | Medium |

### Calculation

If the first table contains 2 rows and the second table contains 3 rows:

```text
Total combinations = 2 × 3 = 6
```

**Remember:** CROSS JOIN does not require a matching condition.

A `SELF JOIN` is used when a table needs to be joined with itself.

It is useful when records in the same table are related to one another.
