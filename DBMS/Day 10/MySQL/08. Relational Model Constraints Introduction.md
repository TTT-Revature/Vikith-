# Relational Model Concepts in DBMS

## 1. Introduction

The Relational Model is a database model that organizes data into tables consisting of rows and columns.

It was introduced by **Edgar F. Codd in 1970**.

In the relational model:

- Data is stored in relations (tables).
- Rows represent individual records.
- Columns represent attributes.
- Keys identify records uniquely.
- Relationships connect different tables.
- Integrity constraints maintain data accuracy and consistency.

Most modern relational database systems, such as MySQL, PostgreSQL, Oracle, and SQL Server, are based on the relational model.

## 2. What is a Relation?

A Relation is a table that stores related data in rows and columns.

### Example: Students Relation

| student_id | student_name | age | city |
|---|---|---:|---|
| 1 | Rahul | 22 | Chennai |
| 2 | Priya | 23 | Bangalore |
| 3 | Amit | 21 | Mumbai |

Here, Students is the relation.

It contains information about students.

### Characteristics of a Relation

- Each relation has a unique name.
- Each column has a unique name within the relation.
- Each cell contains a single value.
- Each row represents a record.
- The order of rows does not matter.
- The order of columns does not matter logically.
- Duplicate tuples are not allowed in the formal relational model.

## 3. What is a Tuple?

A Tuple represents a single row or record in a relation.

### Example

| student_id | student_name | age | city |
|---|---|---:|---|
| 1 | Rahul | 22 | Chennai |
| 2 | Priya | 23 | Bangalore |

The following is one tuple:

`(1, Rahul, 22, Chennai)`

It represents one student's complete information.

### Important Points

- A tuple represents one record.
- A relation contains multiple tuples.
- In SQL, tuples are commonly represented as rows.

## 4. What is an Attribute?

An Attribute represents a property or characteristic of an entity.

In a relational database, attributes are represented as columns.

### Example

Students Relation:

| student_id | student_name | age | city |
|---|---|---|---|
| 1 | Rahul | 22 | Chennai |
| 2 | Priya | 23 | Bangalore |

Attributes:

- student_id
- student_name
- age
- city

### Important Points

- Attributes represent columns.
- Each attribute has a name.
- Each attribute has an associated domain.
- Attributes describe the properties of records.

## 5. What is a Domain?

A Domain is the set of valid values that an attribute is allowed to contain.

In simple words, a domain defines what kind of values a column can store.

### Example

Consider a Students table.

| Attribute | Domain |
|---|---|
| student_id | Positive integers |
| student_name | Character strings |
| age | Valid integer ages |
| city | Character strings |

For example:

The age column should contain numeric age values rather than names or city names.

### SQL Implementation

```sql
CREATE TABLE Students (
    student_id INT,
    student_name VARCHAR(50),
    age INT,
    city VARCHAR(50)
);
```

Here:

- INT defines the data type for student_id and age.
- VARCHAR(50) defines the allowed character storage for student_name and city.

**Remember:** A SQL data type helps restrict values, while additional constraints may be needed to enforce business rules such as positive age.

## 6. What is a Relation Schema?

A Relation Schema describes the structure of a relation.

It defines:

- Relation name.
- Attribute names.
- Data types or domains.
- Constraints.

### Example

Consider the following relation schema:

`STUDENT(student_id, student_name, age, city)`

Here:

- STUDENT is the relation name.
- student_id is an attribute.
- student_name is an attribute.
- age is an attribute.
- city is an attribute.

The schema describes the structure, not the actual records.

## 7. What is a Relation Instance?

A Relation Instance represents the actual data stored in a relation at a particular point in time.

### Example

**Relation Schema:**

`STUDENT(student_id, student_name, age, city)`

**Relation Instance:**

| student_id | student_name | age | city |
|---|---|---:|---|
| 1 | Rahul | 22 | Chennai |
| 2 | Priya | 23 | Bangalore |
| 3 | Amit | 21 | Mumbai |

If we insert another student, the relation instance changes, but the schema remains the same.

### Difference Between Schema and Instance

| Schema | Instance |
|---|---|
| Defines database structure | Contains actual records |
| Changes less frequently | Changes frequently |
| Describes attributes | Contains attribute values |
| Example: STUDENT(id, name, age) | Example: (1, Rahul, 22) |

## 8. Degree of a Relation

The Degree of a Relation refers to the number of attributes (columns) present in a relation.

### Example

| student_id | name | age | city |
|---|---|---|---|
| 1 | Rahul | 22 | Chennai |
| 2 | Priya | 23 | Bangalore |

The relation contains four attributes.

Therefore:

**Degree = 4**

### Important Points

- Degree represents the number of columns.
- Degree does not depend on the number of rows.

## 9. Cardinality of a Relation

Cardinality refers to the number of tuples (rows) present in a relation.

### Example

| student_id | name | age |
|---|---|---:|
| 1 | Rahul | 22 |
| 2 | Priya | 23 |
| 3 | Amit | 21 |

The relation contains three records.

Therefore:

**Cardinality = 3**

### Important Points

- Cardinality represents the number of rows.
- Cardinality changes when records are inserted or deleted.

## 10. Difference Between Degree and Cardinality

| Degree | Cardinality |
|---|---|
| Number of columns | Number of rows |
| Represents attributes | Represents tuples |
| Changes when attributes are added or removed | Changes when records are added or removed |
| Example: 4 columns | Example: 3 rows |

**Easy way to remember:**

- Degree = Columns
- Cardinality = Rows

## 11. Keys in the Relational Model

Keys are attributes or combinations of attributes used to identify records and establish relationships between tables.

### 11.1 Super Key

A Super Key is any set of one or more attributes that can uniquely identify a record.

Example:

| student_id | email | name |
|---|---|---|
| 1 | rahul@gmail.com | Rahul |
| 2 | priya@gmail.com | Priya |

Possible Super Keys:

- student_id
- email
- (student_id, name)
- (email, name)

These combinations uniquely identify records, assuming student_id and email are unique.

### 11.2 Candidate Key

A Candidate Key is a minimal Super Key.

It uniquely identifies a record without unnecessary attributes.

Example:

- student_id
- email

If both are individually unique, they can be Candidate Keys.

### 11.3 Primary Key

A Primary Key is the Candidate Key selected to uniquely identify records in a table.

Example:

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    email VARCHAR(100)
);
```

Here, student_id is the Primary Key.

### 11.4 Alternate Key

Candidate Keys that are not selected as the Primary Key are called Alternate Keys.

Example:

- student_id = Primary Key
- email = Alternate Key

### 11.5 Foreign Key

A Foreign Key is an attribute that references a key in another table.

Example:

**Departments Table**

| department_id | department_name |
|---|---|
| 101 | IT |
| 102 | HR |

**Employees Table**

| employee_id | employee_name | department_id |
|---|---|---|
| 1 | Rahul | 101 |
| 2 | Priya | 102 |

Here, department_id in Employees references department_id in Departments.

### 11.6 Composite Key

A Composite Key consists of two or more attributes used together to uniquely identify a record.

Example:

**Enrollment Table**

| student_id | course_id | enrollment_date |
|---|---|---|
| 1 | 101 | 2026-01-10 |
| 1 | 102 | 2026-01-11 |
| 2 | 101 | 2026-01-12 |

The combination of student_id and course_id can uniquely identify an enrollment.

```sql
CREATE TABLE Enrollment (
    student_id INT,
    course_id INT,
    enrollment_date DATE,

    PRIMARY KEY (student_id, course_id)
);
```

## 12. Integrity Constraints in the Relational Model

Integrity Constraints are rules that maintain accuracy and consistency of data in a database.

There are three important types:

### 12.1 Entity Integrity

Entity Integrity states that a Primary Key cannot contain NULL values.

Every record must have a valid Primary Key.

Example:

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50)
);
```

The student_id column cannot contain NULL.

### 12.2 Referential Integrity

Referential Integrity ensures that a Foreign Key references an existing record in the parent table, or is NULL when permitted.

Example:

If department_id 101 does not exist in Departments, we cannot insert an employee referencing department_id 101.

This prevents invalid references.

### 12.3 Domain Integrity

Domain Integrity ensures that values stored in a column follow the allowed data type, range, or format.

Example:

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT CHECK (age >= 18)
);
```

Here, the CHECK constraint ensures that age is at least 18.

## 13. NULL Values in the Relational Model

NULL represents a missing, unknown, or unavailable value.

It is not the same as:

- Zero (0)
- Empty string ('')
- False

### Example

| student_id | name | phone |
|---|---|---|
| 1 | Rahul | 9876543210 |
| 2 | Priya | NULL |

Priya's phone number is currently unknown or unavailable.

### Checking NULL Values

```sql
SELECT *
FROM Students
WHERE phone IS NULL;
```

To find records where phone is not NULL:

```sql
SELECT *
FROM Students
WHERE phone IS NOT NULL;
```

**Important:** Use IS NULL and IS NOT NULL instead of = NULL or != NULL.

## 14. Properties of the Relational Model

1. Every relation has a unique name.
2. Every attribute has a unique name within its relation.
3. Each cell contains a single value.
4. Each tuple is unique in the formal relational model.
5. Values in an attribute belong to the same domain.
6. The order of rows is not important.
7. The order of columns is not important.
8. Primary Keys uniquely identify records.
9. Foreign Keys establish relationships.
10. Integrity constraints maintain data consistency.

## 15. Relational Model Example Using SQL

Let's create a simple Student and Department database.

### Step 1: Create Departments Table

```sql
CREATE TABLE Departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(50)
);
```

### Step 2: Create Students Table

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(50),
    age INT,
    department_id INT,

    FOREIGN KEY (department_id)
        REFERENCES Departments(department_id)
);
```

### Step 3: Insert Data

```sql
INSERT INTO Departments VALUES
(101, 'Computer Science'),
(102, 'Data Science');

INSERT INTO Students VALUES
(1, 'Rahul', 22, 101),
(2, 'Priya', 23, 102),
(3, 'Amit', 21, 101);
```

### Step 4: Retrieve Data

```sql
SELECT
    s.student_name,
    s.age,
    d.department_name
FROM Students s
INNER JOIN Departments d
ON s.department_id = d.department_id;
```

This query retrieves student information along with their department names.
