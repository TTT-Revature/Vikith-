# INNER JOIN in SQL (MySQL)

## 1. What Is INNER JOIN?

`INNER JOIN` is used to combine records from two or more tables based on a matching condition.

It returns **only the rows that have matching values in both tables**.

If a record from one table does not have a matching record in the other table, it will not appear in the result.

### Real-World Example

Imagine a company maintains two tables:

- `employees` – stores employee information.
- `departments` – stores department information.

Instead of storing department names repeatedly in the employee table, we use a common column called `department_id`.

INNER JOIN allows us to retrieve employee names along with their department names.

## 2. Sample Tables

### Employees Table

| employee_id | name | department_id | salary |
|---|---|---|---:|
| 1 | Rahul | 101 | 50000 |
| 2 | Sneha | 102 | 40000 |
| 3 | Arjun | 101 | 60000 |
| 4 | Priya | 103 | 45000 |
| 5 | Kiran | NULL | 35000 |
| 6 | Aman | 105 | 70000 |

### Departments Table

| department_id | department_name |
|---|---|
| 101 | IT |
| 102 | HR |
| 103 | Finance |
| 104 | Marketing |

### Observe the Data

- Rahul has department ID 101.
- Sneha has department ID 102.
- Arjun has department ID 101.
- Priya has department ID 103.
- Kiran has NULL as department ID.
- Aman has department ID 105, which does not exist in the departments table.
- Marketing has no matching employee.

---

## 3. INNER JOIN Syntax

```sql
SELECT column_names
FROM table1
INNER JOIN table2
ON table1.common_column = table2.common_column;
```

### Explanation

| Keyword | Purpose |
|---|---|
| SELECT | Specifies the columns to retrieve |
| FROM | Specifies the first table |
| INNER JOIN | Combines matching records |
| ON | Specifies the matching condition |

---

## 4. Basic INNER JOIN Example

Display employee names along with their department names.

```sql
SELECT
    employees.employee_id,
    employees.name,
    departments.department_name
FROM employees
INNER JOIN departments
ON employees.department_id = departments.department_id;
```

### Output

| employee_id | name | department_name |
|---|---|---|
| 1 | Rahul | IT |
| 2 | Sneha | HR |
| 3 | Arjun | IT |
| 4 | Priya | Finance |

### Why Are Some Records Missing?

| Employee / Department | Reason |
|---|---|
| Kiran | Department ID is NULL |
| Aman | Department ID 105 has no matching department |
| Marketing | No employee references department ID 104 |

INNER JOIN removes unmatched records from both sides.

---

## 5. How INNER JOIN Works Internally

Consider this condition:

```sql
ON employees.department_id = departments.department_id
```

MySQL compares the department IDs and returns rows where the condition is TRUE.

### Matching Process

| Employee | Employee Department ID | Department ID | Match? |
|---|---:|---:|---|
| Rahul | 101 | 101 | Yes |
| Sneha | 102 | 102 | Yes |
| Arjun | 101 | 101 | Yes |
| Priya | 103 | 103 | Yes |
| Kiran | NULL | — | No |
| Aman | 105 | — | No |

The final result contains only matching records.

**Important:** This describes the logical result of the JOIN. MySQL's actual execution plan may use different physical strategies, such as nested-loop or hash joins, depending on the query and available indexes.

## 6. INNER JOIN with Table Aliases

Instead of writing full table names repeatedly, we can use aliases.

### Without Aliases

```sql
SELECT
    employees.name,
    departments.department_name
FROM employees
INNER JOIN departments
ON employees.department_id = departments.department_id;
```

### With Aliases

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id;
```

Here:

- `e` represents the employees table.
- `d` represents the departments table.

Aliases make queries shorter and easier to understand.

## 7. INNER JOIN with WHERE

We can filter the joined result using the `WHERE` clause.

### Example 1: Find employees working in IT

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id
WHERE d.department_name = 'IT';
```

**Output:**

| name | department_name |
|---|---|
| Rahul | IT |
| Arjun | IT |

### Example 2: Find employees earning more than ₹45,000

```sql
SELECT
    e.name,
    d.department_name,
    e.salary
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id
WHERE e.salary > 45000;
```

**Output:**

| name | department_name | salary |
|---|---|---:|
| Rahul | IT | 50000 |
| Arjun | IT | 60000 |
| Aman | No matching department | — |

Correction: Aman is excluded because INNER JOIN has no matching department. The actual output is:

| name | department_name | salary |
|---|---|---:|
| Rahul | IT | 50000 |
| Arjun | IT | 60000 |

## 8. INNER JOIN with Multiple Conditions

We can specify more than one condition in the `ON` clause.

### Example

Suppose we have these tables:

**Employees**

| employee_id | name | department_id | city |
|---|---|---|---|
| 1 | Rahul | 101 | Chennai |
| 2 | Sneha | 102 | Bangalore |
| 3 | Arjun | 101 | Chennai |
| 4 | Priya | 103 | Bangalore |

**Departments**

| department_id | department_name | city |
|---|---|---|
| 101 | IT | Chennai |
| 102 | HR | Bangalore |
| 103 | Finance | Mumbai |

Suppose we want to match employees and departments using both department ID and city.

```sql
SELECT
    e.name,
    d.department_name,
    e.city
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id
AND e.city = d.city;
```

**Output:**

| name | department_name | city |
|---|---|---|
| Rahul | IT | Chennai |
| Sneha | HR | Bangalore |
| Arjun | IT | Chennai |

Priya is excluded because her city is Bangalore, whereas the Finance department's city is Mumbai.

**Remember:** Conditions in `ON` determine which rows match across the tables.

## 9. INNER JOIN with GROUP BY

We can combine JOINs with aggregate functions to calculate summaries.

### Example: Count employees in each department

```sql
SELECT
    d.department_name,
    COUNT(e.employee_id) AS total_employees
FROM departments d
INNER JOIN employees e
ON d.department_id = e.department_id
GROUP BY d.department_id, d.department_name;
```

**Output:**

| department_name | total_employees |
|---|---:|
| IT | 2 |
| HR | 1 |
| Finance | 1 |

Marketing is excluded because it has no matching employee.

### Example: Calculate average salary per department

```sql
SELECT
    d.department_name,
    AVG(e.salary) AS average_salary
FROM departments d
INNER JOIN employees e
ON d.department_id = e.department_id
GROUP BY d.department_id, d.department_name;
```

**Output:**

| department_name | average_salary |
|---|---:|
| IT | 55000 |
| HR | 40000 |
| Finance | 45000 |

---

## 10. INNER JOIN with HAVING

`HAVING` filters groups after aggregation.

### Example: Find departments with more than one employee

```sql
SELECT
    d.department_name,
    COUNT(e.employee_id) AS total_employees
FROM departments d
INNER JOIN employees e
ON d.department_id = e.department_id
GROUP BY d.department_id, d.department_name
HAVING COUNT(e.employee_id) > 1;
```

**Output:**

| department_name | total_employees |
|---|---:|
| IT | 2 |

Only IT has more than one matching employee.

---

## 11. INNER JOIN with ORDER BY

We can sort joined records.

### Example: Display employees from highest salary to lowest

```sql
SELECT
    e.name,
    d.department_name,
    e.salary
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id
ORDER BY e.salary DESC;
```

**Output:**

| name | department_name | salary |
|---|---|---:|
| Arjun | IT | 60000 |
| Rahul | IT | 50000 |
| Priya | Finance | 45000 |
| Sneha | HR | 40000 |

## 12. INNER JOIN with Three Tables

We can join three or more tables by specifying the matching conditions.

Consider three tables:

### Employees

| employee_id | name | department_id |
|---|---|---|
| 1 | Rahul | 101 |
| 2 | Sneha | 102 |
| 3 | Arjun | 101 |

### Departments

| department_id | department_name |
|---|---|
| 101 | IT |
| 102 | HR |

### Locations

| location_id | department_id | city |
|---|---|---|
| 1 | 101 | Chennai |
| 2 | 102 | Bangalore |

### Query

```sql
SELECT
    e.name,
    d.department_name,
    l.city
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id
INNER JOIN locations l
ON d.department_id = l.department_id;
```

### Output

| name | department_name | city |
|---|---|---|
| Rahul | IT | Chennai |
| Sneha | HR | Bangalore |
| Arjun | IT | Chennai |

### Explanation

1. Employees are matched with departments.
2. The resulting department information is matched with locations.
3. Only records matching both JOIN conditions are returned.

## 13. INNER JOIN vs LEFT JOIN

This is one of the most frequently asked SQL interview questions.

| INNER JOIN | LEFT JOIN |
|---|---|
| Returns only matching records | Returns all records from the left table |
| Unmatched left rows are excluded | Unmatched left rows are included |
| Unmatched right rows are excluded | Unmatched right rows are excluded |
| Useful when only matching data is required | Useful when all left-side records must be retained |

### INNER JOIN

```sql
SELECT e.name, d.department_name
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id;
```

Kiran and Aman are excluded because they have no matching department.

### LEFT JOIN

```sql
SELECT e.name, d.department_name
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.department_id;
```

Kiran and Aman are included, with NULL department names.

## 14. Important Concepts and Mistakes

### A. INNER JOIN and NULL

A normal equality condition does not match NULL with NULL.

```sql
ON e.department_id = d.department_id
```

If `e.department_id` is NULL, the condition does not evaluate to TRUE.

### B. Duplicate Rows

A JOIN can return multiple rows for one record if the matching column on the other side contains multiple matching records.

For example, one department can have multiple employees.

This is expected in a one-to-many relationship.

### C. Use Qualified Column Names

If both tables contain a column named `department_id`, specify which table it belongs to:

```sql
SELECT e.department_id
FROM employees e;
```

### D. Choose the Correct Matching Columns

Always identify the relationship between the tables before writing the `ON` condition.

Joining unrelated columns can produce incorrect results.

### E. ON vs WHERE

- `ON` specifies how records from different tables are matched.
- `WHERE` filters the rows after the JOIN result is formed, in the logical query-processing model.

For INNER JOINs, some predicates can be moved between `ON` and `WHERE` without changing the result. This is not generally true for outer joins such as LEFT JOIN.

## 17. Key Takeaways

- INNER JOIN combines rows from related tables.
- Only matching records are returned.
- The ON clause specifies the matching condition.
- Table aliases make queries easier to read.
- INNER JOIN can be combined with WHERE, GROUP BY, HAVING, and ORDER BY.
- Multiple tables can be joined in one query.
- NULL join keys do not match using ordinary equality.
- One-to-many relationships can produce multiple result rows.
