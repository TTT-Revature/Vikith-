# Subqueries in SQL (MySQL)

## 1. What Is a Subquery?

A subquery is a SQL query written inside another SQL query.

It is also called an **inner query** or **nested query**.

The query containing the subquery is called the **outer query**.

A subquery is useful when the result of one query is required by another query.

### Real-World Example

Suppose a company wants to find employees who earn more than the average salary.

We need two steps:

1. Calculate the average salary.
2. Find employees whose salary is greater than that average.

Instead of executing two separate queries, we can combine them using a subquery.

---

## 2. Basic Subquery Syntax

```sql
SELECT column_names
FROM table_name
WHERE column_name operator (
    SELECT column_name
    FROM another_table
    WHERE condition
);
```

### Understanding the Structure

- **Outer query:** The main query that retrieves the final result.
- **Inner query:** The query written inside the outer query.
- **Subquery result:** The value or set of values returned by the inner query.

## 4. Single-Row Subquery

A single-row subquery returns one row containing one value.

### Example: Find employees earning more than the average salary.

```sql
SELECT *
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);
```

### Step 1: Execute the Inner Query

```sql
SELECT AVG(salary)
FROM employees;
```

**Output:**

| AVG(salary) |
|---:|
| 49625.00 |

The average salary is ₹49,625.

### Step 2: Execute the Outer Query

The outer query becomes logically equivalent to:

```sql
SELECT *
FROM employees
WHERE salary > 49625;
```

**Final Output:**

| employee_id | name | salary |
|---|---|---:|
| 1 | Rahul | 50000 |
| 3 | Arjun | 60000 |
| 6 | Meera | 55000 |
| 7 | Aman | 70000 |

### Important

The inner query calculates a value, and the outer query uses that value to filter records.

## 5. Subquery with Comparison Operators

A single-value subquery can be used with comparison operators.

| Operator | Meaning |
|---|---|
| `=` | Equal to |
| `>` | Greater than |
| `<` | Less than |
| `>=` | Greater than or equal to |
| `<=` | Less than or equal to |
| `<>` | Not equal to |

### Example 1: Find employees earning the highest salary.

```sql
SELECT *
FROM employees
WHERE salary = (
    SELECT MAX(salary)
    FROM employees
);
```

**Output:**

| name | salary |
|---|---:|
| Aman | 70000 |

### Example 2: Find employees earning less than the average salary.

```sql
SELECT *
FROM employees
WHERE salary < (
    SELECT AVG(salary)
    FROM employees
);
```

**Output:**

| name | salary |
|---|---:|
| Sneha | 40000 |
| Priya | 45000 |
| Kiran | 35000 |
| Neha | 42000 |

### Example 3: Find employees earning the minimum salary.

```sql
SELECT *
FROM employees
WHERE salary = (
    SELECT MIN(salary)
    FROM employees
);
```

**Output:**

| name | salary |
|---|---:|
| Kiran | 35000 |

## 6. Multiple-Row Subquery

A multiple-row subquery returns more than one row.

For example, we want to find employees who belong to departments located in a particular department list.

We can use operators such as:

- `IN`
- `NOT IN`
- `ANY`
- `ALL`
- `EXISTS`

### Example: Find employees working in IT or HR.

```sql
SELECT *
FROM employees
WHERE department_id IN (
    SELECT department_id
    FROM departments
    WHERE department_name IN ('IT', 'HR')
);
```

### Inner Query

```sql
SELECT department_id
FROM departments
WHERE department_name IN ('IT', 'HR');
```

**Output:**

| department_id |
|---:|
| 101 |
| 102 |

### Outer Query

The outer query finds employees whose department ID is either 101 or 102.

**Final Output:**

| name | department_id |
|---|---:|
| Rahul | 101 |
| Sneha | 102 |
| Arjun | 101 |
| Kiran | 102 |
| Aman | 101 |
| Neha | 102 |

## 7. Subquery with IN

The `IN` operator checks whether a value matches any value returned by the subquery.

### Example: Find employees working in departments that exist in the departments table.

```sql
SELECT *
FROM employees
WHERE department_id IN (
    SELECT department_id
    FROM departments
);
```

This returns employees whose department IDs match a department ID in the departments table.

**Output:** All eight employees in this sample dataset.

### Example: Find departments that have employees.

```sql
SELECT *
FROM departments
WHERE department_id IN (
    SELECT department_id
    FROM employees
);
```

**Output:**

| department_id | department_name |
|---|---|
| 101 | IT |
| 102 | HR |
| 103 | Finance |

Marketing is excluded because no employee belongs to department 104.

---

## 8. Subquery with NOT IN

`NOT IN` returns values that do not match any value in the subquery result.

### Example: Find departments that do not have employees.

```sql
SELECT *
FROM departments
WHERE department_id NOT IN (
    SELECT department_id
    FROM employees
    WHERE department_id IS NOT NULL
);
```

**Output:**

| department_id | department_name |
|---|---|
| 104 | Marketing |

### Important NULL Behavior

Be careful when using `NOT IN`.

If the subquery returns NULL, the comparison may evaluate to UNKNOWN, producing unexpected results.

For example:

```sql
SELECT *
FROM departments
WHERE department_id NOT IN (
    SELECT department_id
    FROM employees
);
```

The employees table contains a NULL department ID for Kiran.

That NULL can prevent the expected results from being returned.

A safer alternative for finding unmatched departments is `NOT EXISTS`, which we will cover shortly.

---

## 9. Subquery with EXISTS

`EXISTS` checks whether a subquery returns at least one row.

- If the subquery returns a row, EXISTS is TRUE.
- If the subquery returns no rows, EXISTS is FALSE.

### Example: Find departments that have at least one employee.

```sql
SELECT *
FROM departments d
WHERE EXISTS (
    SELECT 1
    FROM employees e
    WHERE e.department_id = d.department_id
);
```

**Output:**

| department_id | department_name |
|---|---|
| 101 | IT |
| 102 | HR |
| 103 | Finance |

Marketing is excluded because no employee belongs to it.

### Why SELECT 1?

Inside EXISTS, we only care whether a matching row exists.

The actual selected value is not important. `SELECT 1` is a common convention.

### NOT EXISTS

`NOT EXISTS` checks whether the subquery returns no rows.

Example: Find departments without employees.

```sql
SELECT *
FROM departments d
WHERE NOT EXISTS (
    SELECT 1
    FROM employees e
    WHERE e.department_id = d.department_id
);
```

**Output:**

| department_id | department_name |
|---|---|
| 104 | Marketing |

## 10. Correlated Subquery

A correlated subquery is a subquery that refers to a column from the outer query.

Unlike a simple independent subquery, its condition depends on the current row being examined by the outer query.

### Example: Find employees earning more than their department's average salary.

```sql
SELECT
    e.employee_id,
    e.name,
    e.department_id,
    e.salary
FROM employees e
WHERE e.salary > (
    SELECT AVG(e2.salary)
    FROM employees e2
    WHERE e2.department_id = e.department_id
);
```

### Understand the Logic

For each employee, the inner query calculates the average salary of that employee's department.

**IT Department**

| Employee | Salary |
|---|---:|
| Rahul | 50000 |
| Arjun | 60000 |
| Aman | 70000 |

Average = ₹60,000.

**HR Department**

| Employee | Salary |
|---|---:|
| Sneha | 40000 |
| Kiran | 35000 |
| Neha | 42000 |

Average = ₹39,000.

**Finance Department**

| Employee | Salary |
|---|---:|
| Priya | 45000 |
| Meera | 55000 |

Average = ₹50,000.

### Final Output

| name | department_id | salary |
|---|---:|---:|
| Aman | 101 | 70000 |
| Neha | 102 | 42000 |
| Meera | 103 | 55000 |

### Why Is It Called Correlated?

Look at this condition:

```sql
WHERE e2.department_id = e.department_id
```

`e2` belongs to the inner query, while `e` belongs to the outer query.

The inner query depends on the outer employee's department ID.

## 11. Subquery with ANY

`ANY` compares a value with the values returned by a subquery.

The condition is TRUE if the comparison is TRUE for at least one value.

### Example

Find employees earning more than at least one employee in the HR department.

```sql
SELECT *
FROM employees
WHERE salary > ANY (
    SELECT salary
    FROM employees
    WHERE department_id = 102
);
```

HR salaries are:

```text
40000, 35000, 42000
```

The condition is TRUE if an employee earns more than at least one of these values.

In this example, the condition is equivalent to earning more than the minimum HR salary of ₹35,000.

**Output:**

| name | salary |
|---|---:|
| Rahul | 50000 |
| Sneha | 40000 |
| Arjun | 60000 |
| Priya | 45000 |
| Meera | 55000 |
| Aman | 70000 |
| Neha | 42000 |

Kiran is excluded because their salary is ₹35,000.

---

## 12. Subquery with ALL

`ALL` compares a value with every value returned by the subquery.

The condition must be TRUE for all returned values.

### Example

Find employees earning more than every employee in the HR department.

```sql
SELECT *
FROM employees
WHERE salary > ALL (
    SELECT salary
    FROM employees
    WHERE department_id = 102
);
```

HR salaries:

```text
40000, 35000, 42000
```

The employee must earn more than ₹40,000 and ₹35,000 and ₹42,000.

In this example, the condition is equivalent to earning more than the maximum HR salary of ₹42,000.

**Output:**

| name | salary |
|---|---:|
| Rahul | 50000 |
| Arjun | 60000 |
| Priya | 45000 |
| Meera | 55000 |
| Aman | 70000 |

## 13. Subquery in the SELECT Clause

A subquery can also be used inside the SELECT clause.

### Example: Display each employee's salary and the overall average salary.

```sql
SELECT
    name,
    salary,
    (
        SELECT AVG(salary)
        FROM employees
    ) AS average_salary
FROM employees;
```

**Output:**

| name | salary | average_salary |
|---|---:|---:|
| Rahul | 50000 | 49625 |
| Sneha | 40000 | 49625 |
| Arjun | 60000 | 49625 |
| Priya | 45000 | 49625 |
| Kiran | 35000 | 49625 |
| Meera | 55000 | 49625 |
| Aman | 70000 | 49625 |
| Neha | 42000 | 49625 |

The same overall average is displayed for every employee.

## 14. Subquery in the FROM Clause

A subquery can be used in the FROM clause as a derived table.

A derived table is a temporary result set used by the outer query.

In MySQL, a derived table must have an alias.

### Example: Find departments with an average salary greater than ₹45,000.

```sql
SELECT *
FROM (
    SELECT
        department_id,
        AVG(salary) AS average_salary
    FROM employees
    GROUP BY department_id
) AS department_summary
WHERE average_salary > 45000;
```

**Output:**

| department_id | average_salary |
|---|---:|
| 101 | 60000 |
| 103 | 50000 |

### Explanation

**Inner Query:**

```sql
SELECT
    department_id,
    AVG(salary) AS average_salary
FROM employees
GROUP BY department_id;
```

It calculates the average salary for every department.

**Outer Query:**

```sql
WHERE average_salary > 45000;
```

It filters the derived result to keep departments with an average above ₹45,000.

## 15. Subquery vs JOIN

Both subqueries and JOINs can retrieve information from related tables, but they express the problem differently.

### Using a JOIN

Find employee names and their department names.

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id;
```

### Using a Subquery

```sql
SELECT
    name,
    department_id
FROM employees
WHERE department_id IN (
    SELECT department_id
    FROM departments
);
```

The second query returns employee names and department IDs, not department names.

### Difference

| Subquery | JOIN |
|---|---|
| Query written inside another query | Combines rows from multiple tables |
| Useful for filtering using query results | Useful for retrieving related columns |
| Can use IN, EXISTS, ANY, and ALL | Uses ON to define matching conditions |
| Can appear in SELECT, FROM, or WHERE | Appears in the FROM clause |

**Important:** Neither is always faster. MySQL may optimize equivalent subqueries and joins differently. Check execution plans with `EXPLAIN` when performance matters.

## 16. Types of Subqueries – Quick Revision

| Type | Description |
|---|---|
| Single-row subquery | Returns one row |
| Multiple-row subquery | Returns multiple rows |
| Multiple-column subquery | Returns multiple columns |
| Correlated subquery | Depends on the outer query |
| Non-correlated subquery | Can execute independently of the outer query |
| Scalar subquery | Returns exactly one value |
| Derived table | Subquery used in the FROM clause |

### Important Difference

A scalar subquery returns a single value (one row and one column).

If a scalar subquery returns more than one row, MySQL raises an error.

## 17. Common Mistakes

### Mistake 1: Using = with a multiple-row subquery

Incorrect:

```sql
SELECT *
FROM employees
WHERE department_id = (
    SELECT department_id
    FROM departments
);
```

The inner query returns multiple department IDs.

Use `IN` instead:

```sql
SELECT *
FROM employees
WHERE department_id IN (
    SELECT department_id
    FROM departments
);
```

### Mistake 2: Forgetting the derived table alias

Incorrect:

```sql
SELECT *
FROM (
    SELECT department_id, AVG(salary)
    FROM employees
    GROUP BY department_id
);
```

Correct:

```sql
SELECT *
FROM (
    SELECT department_id, AVG(salary) AS average_salary
    FROM employees
    GROUP BY department_id
) AS department_summary;
```

### Mistake 3: Ignoring NULL in NOT IN

A NULL in the subquery result can cause unexpected filtering.

Use `NOT EXISTS` when checking for the absence of matching records.

### Mistake 4: Forgetting the correlation condition

A correlated subquery must reference the outer query correctly.

Without the intended relationship, the query may calculate a result for the wrong group.

## 20. Key Takeaways

- A subquery is a query inside another query.
- The inner query provides a result to the outer query.
- Single-row subqueries return one row.
- Multiple-row subqueries can be used with IN, ANY, and ALL.
- EXISTS checks whether matching records exist.
- NOT EXISTS finds records without matches.
- Correlated subqueries depend on the outer query.
- Subqueries can be used in SELECT, FROM, and WHERE.
- Derived tables are subqueries used in FROM.
- Always consider NULL behavior when using NOT IN.
