# String Patterns, Ranges, and Sets in SQL (MySQL)

## 1. Introduction

SQL provides different operators to filter records based on text patterns, value ranges, and collections of values.

The three important concepts are:

1. **String Patterns** – Search for text using `LIKE` and wildcards.
2. **Ranges** – Filter values within a specific range using `BETWEEN`.
3. **Sets** – Match values against a list using `IN`.

These operators are commonly used with the `WHERE` clause.

Let's use the following table throughout this topic.

### Sample Employees Table

| employee_id | name | department | salary | city |
|---:|---|---|---:|---|
| 101 | Rahul | IT | 45000 | Chennai |
| 102 | Priya | HR | 35000 | Bangalore |
| 103 | Aman | IT | 55000 | Chennai |
| 104 | Sneha | Finance | 40000 | Mumbai |
| 105 | Arjun | IT | 60000 | Bangalore |
| 106 | Kiran | HR | 30000 | Chennai |
| 107 | Ananya | Finance | 48000 | Hyderabad |
| 108 | Rakesh | IT | 52000 | Mumbai |

# 2. String Patterns – LIKE Operator

The `LIKE` operator is used to search for a particular pattern in a string column.

It is especially useful when we do not know the complete text value.

For example:
- Find employees whose names start with A.
- Find employees whose names end with a.
- Find employees whose names contain `an`.
- Find employees whose names have a specific number of characters.

### Syntax

```sql
SELECT column_name
FROM table_name
WHERE column_name LIKE pattern;
```

## 3. Wildcard Characters

MySQL supports two main wildcard characters with LIKE.

| Wildcard | Meaning |
|---|---|
| `%` | Matches zero or more characters |
| `_` | Matches exactly one character |

### 3.1 Percentage (%) Wildcard

The `%` wildcard matches zero or more characters.

**Example 1: Names starting with A**

```sql
SELECT *
FROM employees
WHERE name LIKE 'A%';
```

Output:

| employee_id | name |
|---:|---|
| 103 | Aman |
| 105 | Arjun |
| 107 | Ananya |

Explanation:

- `A` means the name must start with A.
- `%` means any number of characters can follow.

**Example 2: Names ending with a**

```sql
SELECT *
FROM employees
WHERE name LIKE '%a';
```

Output:

| employee_id | name |
|---:|---|
| 102 | Priya |
| 104 | Sneha |
| 107 | Ananya |

**Example 3: Names containing an**

```sql
SELECT *
FROM employees
WHERE name LIKE '%an%';
```

This searches for the sequence `an` anywhere in the name.

**Example 4: Names starting with R and ending with h**

```sql
SELECT *
FROM employees
WHERE name LIKE 'R%h';
```

Result: Rakesh.

### 3.2 Underscore (_) Wildcard

The `_` wildcard matches exactly one character.

**Example 1: Names with A as the second character**

```sql
SELECT *
FROM employees
WHERE name LIKE '_a%';
```

The first underscore matches exactly one character. The second character must be `a`.

**Example 2: Names containing exactly five characters**

```sql
SELECT *
FROM employees
WHERE name LIKE '_____';
```

Five underscores represent exactly five characters.

**Example 3: Names starting with R followed by exactly four characters**

```sql
SELECT *
FROM employees
WHERE name LIKE 'R____';
```

This matches a five-character name beginning with R.

## 4. Combining % and _

We can combine both wildcard characters to create more specific patterns.

Example:

```sql
SELECT *
FROM employees
WHERE name LIKE '_a%h';
```

This means:

- The first character can be anything.
- The second character must be `a`.
- Any number of characters can follow.
- The name must end with `h`.

Another example:

```sql
SELECT *
FROM employees
WHERE name LIKE 'A___';
```

This matches names starting with A and containing exactly four characters.

## 5. NOT LIKE – Excluding String Patterns

`NOT LIKE` returns records that do not match a specified pattern.

Example:

```sql
SELECT *
FROM employees
WHERE name NOT LIKE 'A%';
```

This returns employees whose names do not start with A.

Another example:

```sql
SELECT *
FROM employees
WHERE city NOT LIKE 'C%';
```

This excludes cities beginning with C.

## 6. Case Sensitivity in LIKE

In MySQL, whether string comparisons are case-sensitive depends on the column's collation.

Many common MySQL collations are case-insensitive.

For example, under a case-insensitive collation:

```sql
SELECT *
FROM employees
WHERE name LIKE 'a%';
```

This may match names beginning with either lowercase `a` or uppercase `A`.

For an explicit case-sensitive comparison, use `LIKE BINARY`:

```sql
SELECT *
FROM employees
WHERE name LIKE BINARY 'A%';
```

This matches uppercase A specifically.

# 7. Ranges – BETWEEN Operator

The `BETWEEN` operator filters values within a specified range.

It is commonly used with:

- Numbers
- Dates
- Times
- Other comparable values

### Syntax

```sql
SELECT column_name
FROM table_name
WHERE column_name BETWEEN value1 AND value2;
```

**Important:** BETWEEN includes both the lower and upper boundary values.

## 8. Numeric Range Filtering

Example: Find employees earning between 40000 and 55000.

```sql
SELECT *
FROM employees
WHERE salary BETWEEN 40000 AND 55000;
```

Output:

| employee_id | name | salary |
|---:|---|---:|
| 101 | Rahul | 45000 |
| 103 | Aman | 55000 |
| 104 | Sneha | 40000 |
| 107 | Ananya | 48000 |
| 108 | Rakesh | 52000 |

Both 40000 and 55000 are included.

### Equivalent Query Using Comparison Operators

```sql
SELECT *
FROM employees
WHERE salary >= 40000
AND salary <= 55000;
```

Both queries produce the same result.

## 9. NOT BETWEEN

`NOT BETWEEN` returns values outside the specified range.

Example:

```sql
SELECT *
FROM employees
WHERE salary NOT BETWEEN 40000 AND 55000;
```

This returns employees earning less than 40000 or greater than 55000.

## 10. BETWEEN with Dates

BETWEEN can also be used to filter dates.

Suppose we have an `orders` table:

| order_id | customer_name | order_date |
|---:|---|---|
| 1 | Rahul | 2026-11-01 |
| 2 | Priya | 2026-11-05 |
| 3 | Aman | 2026-11-10 |
| 4 | Sneha | 2026-11-15 |
| 5 | Arjun | 2026-11-20 |

Find orders placed between November 5 and November 15.

```sql
SELECT *
FROM orders
WHERE order_date BETWEEN '2026-11-05' AND '2026-11-15';
```

This includes November 5 and November 15.

**Important:** If filtering a DATETIME column for an entire date range, a safer approach is to use a half-open range.

```sql
SELECT *
FROM orders
WHERE order_date >= '2026-11-05'
AND order_date < '2026-11-16';
```

This includes every time on November 15, not just midnight.

# 11. Sets – IN Operator

A set is a collection of specific values.

The `IN` operator checks whether a column's value matches any value in a specified list.

### Syntax

```sql
SELECT column_name
FROM table_name
WHERE column_name IN (value1, value2, value3);
```

Example: Find employees working in IT, HR, or Finance.

```sql
SELECT *
FROM employees
WHERE department IN ('IT', 'HR', 'Finance');
```

This returns employees from any of the three departments.

## 12. IN vs OR

We can write the same query using OR.

Using IN:

```sql
SELECT *
FROM employees
WHERE department IN ('IT', 'HR');
```

Using OR:

```sql
SELECT *
FROM employees
WHERE department = 'IT'
OR department = 'HR';
```

Both queries produce the same result.

**Why use IN?**

- Cleaner syntax.
- Easier to read.
- Convenient when checking many possible values.

## 13. NOT IN

`NOT IN` excludes records whose values match the specified list.

Example: Find employees who do not belong to IT or HR.

```sql
SELECT *
FROM employees
WHERE department NOT IN ('IT', 'HR');
```

Output:

| employee_id | name | department |
|---:|---|---|
| 104 | Sneha | Finance |
| 107 | Ananya | Finance |

**Important NULL behavior:** If the list supplied to `NOT IN` contains NULL, the result can become UNKNOWN for comparisons, and rows may not be returned as expected. Handle NULL values explicitly when necessary.

# 14. Combining String Patterns, Ranges, and Sets

The real power comes when we combine these operators.

```sql

FROM employees
```

### Example 2: Names Starting with A or R

```sql
SELECT *
```
