# SQL Data Types in MySQL

## 1. Introduction to Data Types

A data type defines the kind of value that can be stored in a database column.

For example:

- A person's age requires an integer.
- A person's name requires a string.
- An employee's salary requires a decimal number.
- A joining date requires a date value.

When creating a table, we specify a data type for every column.

Example:

```sql
CREATE TABLE employees (
    employee_id INT,
    name VARCHAR(100),
    age INT,
    salary DECIMAL(10,2),
    joining_date DATE
);
```

Here:

| Column | Data Type | Example Value |
|---|---|---|
| employee_id | INT | 101 |
| name | VARCHAR(100) | Rahul |
| age | INT | 25 |
| salary | DECIMAL(10,2) | 45000.50 |
| joining_date | DATE | 2026-11-27 |

## 3. Numeric Data Types

Numeric data types are used to store numbers.

They are useful for storing:

- Age
- Salary
- Product price
- Quantity
- Account balance
- Percentage

### 3.1 Integer Data Types

Integer types store whole numbers without decimal points.

| Data Type | Storage | Signed Range |
|---|---:|---|
| TINYINT | 1 byte | -128 to 127 |
| SMALLINT | 2 bytes | -32,768 to 32,767 |
| MEDIUMINT | 3 bytes | -8,388,608 to 8,388,607 |
| INT | 4 bytes | -2,147,483,648 to 2,147,483,647 |
| BIGINT | 8 bytes | Approximately -9.22 quintillion to +9.22 quintillion |

**Example:**

```sql
CREATE TABLE products (
    product_id INT,
    quantity SMALLINT,
    rating TINYINT
);
```

Explanation:

- `product_id` stores product identification numbers.
- `quantity` stores product quantities.
- `rating` stores small integer ratings.

### Signed vs Unsigned

Integer types are signed by default, meaning they can store both positive and negative values.

An `UNSIGNED` integer stores only non-negative values and has a larger positive range.

Example:

```sql
CREATE TABLE products (
    product_id INT UNSIGNED,
    quantity INT UNSIGNED
);
```

For an unsigned `INT`, the range is:

0 to 4,294,967,295.

Use unsigned types when negative values are not meaningful.

### 3.2 Decimal Data Types

Decimal types store numbers with fractional parts.

| Data Type | Description |
|---|---|
| DECIMAL(M,D) | Exact fixed-point numeric value |
| FLOAT | Approximate floating-point value |
| DOUBLE | Approximate floating-point value with greater precision |

#### DECIMAL

`DECIMAL` is commonly used for financial values because it stores exact decimal values within its defined precision.

Syntax:

```sql
DECIMAL(M,D)
```

- M = Maximum total number of digits.
- D = Number of digits after the decimal point.

Example:

```sql
salary DECIMAL(10,2)
```

This allows up to 10 digits in total, with 2 digits after the decimal point.

Examples:

- 45000.50
- 99999999.99
- 1250.75

#### FLOAT

Stores approximate floating-point values.

```sql
temperature FLOAT
```

Useful when approximate precision is acceptable.

#### DOUBLE

Stores approximate floating-point values with more precision than FLOAT.

```sql
distance DOUBLE
```

### DECIMAL vs FLOAT vs DOUBLE

| Feature | DECIMAL | FLOAT | DOUBLE |
|---|---|---|---|
| Number type | Exact | Approximate | Approximate |
| Precision | Defined by M and D | Lower | Higher |
| Common use | Money and financial values | Scientific calculations | Scientific and engineering calculations |

**Important:** Prefer `DECIMAL` for money rather than `FLOAT` or `DOUBLE`, because floating-point calculations can introduce small rounding differences.

## 4. String Data Types

String data types store text and character values.

Examples:

- Names
- Email addresses
- Phone numbers
- Addresses
- Descriptions

### 4.1 CHAR

`CHAR` stores fixed-length character strings.

Example:

```sql
gender CHAR(1)
```

Possible values:

- M
- F

If a value is shorter than the declared length, MySQL stores it as a fixed-length value with padding spaces.

### 4.2 VARCHAR

`VARCHAR` stores variable-length strings.

Example:

```sql
name VARCHAR(100)
```

It can store names with different lengths, up to 100 characters.

Examples:

- Rahul
- Priya
- Vikith Kotian

`VARCHAR` is commonly used for names, email addresses, and other text fields with varying lengths.

### CHAR vs VARCHAR

| Feature | CHAR | VARCHAR |
|---|---|---|
| Length | Fixed | Variable |
| Storage | Fixed-length field | Depends on stored value and length overhead |
| Suitable for | Fixed-length values | Variable-length values |
| Example | Country code | Person's name |

### 4.3 TEXT

`TEXT` stores longer text values.

Example:

```sql
CREATE TABLE articles (
    article_id INT,
    title VARCHAR(200),
    content TEXT
);
```

Useful for:

- Articles
- Comments
- Descriptions
- Long messages

MySQL also provides different text types:

| Data Type | Maximum Length |
|---|---:|
| TINYTEXT | 255 bytes |
| TEXT | 65,535 bytes |
| MEDIUMTEXT | 16,777,215 bytes |
| LONGTEXT | 4,294,967,295 bytes |

These limits are in bytes, not necessarily characters. The number of characters depends on the character set.

## 5. Date and Time Data Types

Date and time data types store dates, times, and timestamps.

They are useful for:

- Employee joining dates
- Birth dates
- Order dates
- Login times
- Appointment schedules

| Data Type | Description | Example |
|---|---|---|
| DATE | Stores date | 2026-11-27 |
| TIME | Stores time | 10:30:00 |
| DATETIME | Stores date and time | 2026-11-27 10:30:00 |
| TIMESTAMP | Stores a date and time value with timestamp-related behavior | 2026-11-27 10:30:00 |
| YEAR | Stores a year | 2026 |

### 5.1 DATE

Stores date values in `YYYY-MM-DD` format.

```sql
CREATE TABLE students (
    student_id INT,
    date_of_birth DATE
);
```

Example value:

```sql
'2002-05-15'
```

### 5.2 TIME

Stores time values.

```sql
CREATE TABLE schedules (
    schedule_id INT,
    start_time TIME
);
```

Example value:

```sql
'10:30:00'
```

### 5.3 DATETIME

Stores both date and time.

```sql
CREATE TABLE appointments (
    appointment_id INT,
    appointment_time DATETIME
);
```

Example value:

```sql
'2026-11-27 10:30:00'
```

### 5.4 TIMESTAMP

Stores date and time values and supports automatic initialization or updating using options such as `DEFAULT CURRENT_TIMESTAMP` and `ON UPDATE CURRENT_TIMESTAMP`.

Example:

```sql
CREATE TABLE users (
    user_id INT PRIMARY KEY,
    username VARCHAR(50),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

When a record is inserted without specifying `created_at`, MySQL can automatically store the current timestamp.

### 5.5 YEAR

Stores a year value.

```sql
CREATE TABLE academic_years (
    year_id INT PRIMARY KEY,
    passing_year YEAR
);
```

Example:

```sql
2026
```

### DATE vs DATETIME vs TIMESTAMP

| Feature | DATE | DATETIME | TIMESTAMP |
|---|---|---|---|
| Stores date | Yes | Yes | Yes |
| Stores time | No | Yes | Yes |
| Time zone conversion | No | No | Yes, based on session time zone |
| Common use | Birth date | Appointment time | Record creation/update time |

## 6. Boolean Data Type

Boolean values represent two logical states:

- TRUE
- FALSE

In MySQL, `BOOLEAN` and `BOOL` are aliases for `TINYINT(1)`.

Example:

```sql
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    name VARCHAR(50),
    is_active BOOLEAN
);
```

Insert values:

```sql
INSERT INTO employees
VALUES
(1, 'Rahul', TRUE),
(2, 'Priya', FALSE);
```

MySQL represents:

- TRUE as 1
- FALSE as 0

Example query:

```sql
SELECT * FROM employees
WHERE is_active = TRUE;
```

This retrieves active employees.

## 7. Binary Data Types

Binary data types store binary values rather than ordinary text.

They can be useful for storing:

- Binary files
- Images
- Audio data
- Other binary information

| Data Type | Description |
|---|---|
| BINARY | Fixed-length binary data |
| VARBINARY | Variable-length binary data |
| TINYBLOB | Small binary large object |
| BLOB | Binary large object |
| MEDIUMBLOB | Medium-sized binary large object |
| LONGBLOB | Large binary large object |

Example:

```sql
CREATE TABLE documents (
    document_id INT PRIMARY KEY,
    document_name VARCHAR(100),
    document_data BLOB
);
```

**Note:** In many applications, files are stored in external storage, while their file paths or URLs are stored in the database.

## 8. JSON Data Type

MySQL provides a native `JSON` data type for storing JSON documents.

JSON stands for JavaScript Object Notation.

Example:

```sql
CREATE TABLE user_profiles (
    user_id INT PRIMARY KEY,
    profile JSON
);
```

Insert a JSON value:

```sql
INSERT INTO user_profiles
VALUES (
    1,
    '{"city": "Chennai", "skills": ["Python", "SQL"]}'
);
```

Retrieve a value from JSON:

```sql
SELECT
    profile->>'$.city' AS city
FROM user_profiles;
```

Output:

| city |
|---|
| Chennai |

JSON is useful when storing semi-structured data that does not always fit neatly into fixed columns.

## 9. Complete Practical Example

Let's create an employee table using different data types.

```sql
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    age TINYINT UNSIGNED,
    salary DECIMAL(10,2),
    experience FLOAT,
    joining_date DATE,
    login_time TIME,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    is_active BOOLEAN
);
```

Insert a record:

```sql
INSERT INTO employees (
    employee_id,
    name,
    age,
    salary,
    experience,
    joining_date,
    login_time,
    is_active
)
VALUES (
    101,
    'Rahul',
    25,
    45000.50,
    2.5,
    '2024-06-10',
    '09:30:00',
    TRUE
);
```

Retrieve the record:

```sql
SELECT * FROM employees;
```

Possible output:

| employee_id | name | age | salary | experience | joining_date | login_time | is_active |
|---:|---|---:|---:|---:|---|---|---|
| 101 | Rahul | 25 | 45000.50 | 2.5 | 2024-06-10 | 09:30:00 | 1 |

The `created_at` column is automatically populated with the current timestamp.

## 10. How to Choose the Right Data Type

| Requirement | Recommended Data Type |
|---|---|
| Student ID | INT |
| Large transaction ID | BIGINT |
| Age | TINYINT UNSIGNED or SMALLINT |
| Person's name | VARCHAR(100) |
| Gender code | CHAR(1) |
| Salary | DECIMAL(10,2) |
| Product quantity | INT |
| Birth date | DATE |
| Appointment date and time | DATETIME |
| Account active status | BOOLEAN |
| Long article content | TEXT |
| Flexible JSON information | JSON |

Always select a data type based on the actual values you expect to store.

For example, phone numbers should generally use `VARCHAR`, not `INT`, because phone numbers are identifiers rather than quantities and may contain leading zeros or a `+` sign.

## 11. Interview Questions

**Q1. What is a data type in SQL?**

A data type specifies the kind of values that a column can store.

**Q2. What is the difference between INT and BIGINT?**

INT uses 4 bytes, while BIGINT uses 8 bytes and supports a much larger range of integer values.

**Q3. What is the difference between CHAR and VARCHAR?**

CHAR is fixed-length, whereas VARCHAR is variable-length.

**Q4. Why is DECIMAL preferred for storing salary?**

DECIMAL stores exact fixed-point values and avoids the approximate representation associated with FLOAT and DOUBLE.

**Q5. What is the difference between DATE and DATETIME?**

DATE stores only a date, whereas DATETIME stores both date and time.

**Q6. Is BOOLEAN a separate storage type in MySQL?**

No. BOOLEAN and BOOL are aliases for TINYINT(1).

**Q7. Can we store numbers in VARCHAR?**

Yes, but they are treated as text. Numeric calculations may require conversion, so use a numeric type when the value represents a quantity.

**Q8. Which data type is used to store JSON in MySQL?**

JSON.

**Q9. Which data type is suitable for phone numbers?**

VARCHAR, because phone numbers may contain leading zeros, country codes, and special characters.

**Q10. What is the difference between FLOAT and DOUBLE?**

Both store approximate floating-point values, but DOUBLE provides greater precision.

## 13. Key Takeaways

- Data types define what values a column can store.
- Numeric types store numbers.
- String types store text.
- Date and time types store temporal values.
- BOOLEAN represents TRUE and FALSE, using TINYINT(1) in MySQL.
- BLOB types store binary data.
- JSON stores JSON documents.
- DECIMAL is preferred for financial values.
- VARCHAR is suitable for variable-length text.
- Always choose data types based on the actual requirements of your application.

**Remember:** Choosing the correct data type is an important part of designing an efficient and reliable database.
