# OUTER JOIN in SQL (MySQL)

## 1. What Is an OUTER JOIN?

An OUTER JOIN is used to combine records from two tables while preserving matching records and also including certain unmatched records.

Unlike INNER JOIN, which returns only matching records, OUTER JOIN can return unmatched records from one or both tables.

There are three main types:

1. LEFT OUTER JOIN
2. RIGHT OUTER JOIN
3. FULL OUTER JOIN

### Why Do We Need OUTER JOIN?

Imagine a company has two tables:

- `employees` – stores employee information.
- `departments` – stores department information.

We may want to answer questions such as:

- Display all employees, even if they don't belong to a department.
- Display all departments, even if no employees work there.
- Find employees without departments.
- Find departments without employees.

These situations are where OUTER JOIN becomes useful.

## 3. LEFT OUTER JOIN

### What Is LEFT OUTER JOIN?

A LEFT OUTER JOIN returns:

- All records from the left table.
- Matching records from the right table.
- NULL values for right-table columns when no matching record exists.

**Syntax:**

```sql
SELECT columns
FROM table1
LEFT OUTER JOIN table2
ON table1.common_column = table2.common_column;
```

`LEFT JOIN` and `LEFT OUTER JOIN` mean exactly the same thing in MySQL.

### Example

Display all employees along with their department names.

```sql
SELECT
    e.employee_id,
    e.name,
    d.department_name
FROM employees e
LEFT OUTER JOIN departments d
ON e.department_id = d.department_id;
```

### Output

| employee_id | name | department_name |
|---|---|---|
| 1 | Rahul | IT |
| 2 | Sneha | HR |
| 3 | Arjun | IT |
| 4 | Priya | Finance |
| 5 | Kiran | NULL |
| 6 | Aman | NULL |

### Explanation

- Rahul matches department 101.
- Sneha matches department 102.
- Arjun matches department 101.
- Priya matches department 103.
- Kiran has a NULL department ID.
- Aman has department ID 105, which has no matching department.

Even though Kiran and Aman do not have matching department records, they are still included because employees is the left table.

**Remember:** LEFT JOIN preserves every row from the left table.

---

## 4. RIGHT OUTER JOIN

### What Is RIGHT OUTER JOIN?

A RIGHT OUTER JOIN returns:

- All records from the right table.
- Matching records from the left table.
- NULL values for left-table columns when no matching record exists.

**Syntax:**

```sql
SELECT columns
FROM table1
RIGHT OUTER JOIN table2
ON table1.common_column = table2.common_column;
```

`RIGHT JOIN` and `RIGHT OUTER JOIN` mean the same thing.

### Example

Display all departments along with their employees.

```sql
SELECT
    e.employee_id,
    e.name,
    d.department_name
FROM employees e
RIGHT OUTER JOIN departments d
ON e.department_id = d.department_id;
```

### Output

| employee_id | name | department_name |
|---|---|---|
| 1 | Rahul | IT |
| 3 | Arjun | IT |
| 2 | Sneha | HR |
| 4 | Priya | Finance |
| NULL | NULL | Marketing |

### Explanation

All departments are returned because departments is the right table.

Marketing has no matching employee, so the employee columns contain NULL.

Kiran and Aman are not returned because they have no matching department.

**Remember:** RIGHT JOIN preserves every row from the right table.

---

## 5. FULL OUTER JOIN

### What Is FULL OUTER JOIN?

A FULL OUTER JOIN returns:

- All matching records.
- All unmatched records from the left table.
- All unmatched records from the right table.

It combines the behavior of LEFT JOIN and RIGHT JOIN.

### General SQL Syntax

```sql
SELECT columns
FROM table1
FULL OUTER JOIN table2
ON table1.common_column = table2.common_column;
```

### Important: MySQL Does Not Support Native FULL OUTER JOIN

Unlike some other database systems, MySQL does not support the `FULL OUTER JOIN` keyword directly.

However, we can achieve the same result using:

- LEFT JOIN
- UNION ALL
- RIGHT JOIN rows that have no match on the left

### FULL OUTER JOIN Equivalent in MySQL

```sql
SELECT
    e.employee_id,
    e.name,
    d.department_name
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.department_id

UNION ALL

SELECT
    e.employee_id,
    e.name,
    d.department_name
FROM employees e
RIGHT JOIN departments d
ON e.department_id = d.department_id
WHERE e.employee_id IS NULL;
```

### Output

| employee_id | name | department_name |
|---|---|---|
| 1 | Rahul | IT |
| 2 | Sneha | HR |
| 3 | Arjun | IT |
| 4 | Priya | Finance |
| 5 | Kiran | NULL |
| 6 | Aman | NULL |
| NULL | NULL | Marketing |

### Explanation

**First query:**

The LEFT JOIN returns all employees, including unmatched employees.

**Second query:**

The RIGHT JOIN finds departments without a matching employee.

```sql
WHERE e.employee_id IS NULL
```

This keeps only unmatched department records.

**UNION ALL** combines both results without removing duplicate rows.

Because the second query returns only unmatched right-side rows, matching records are not duplicated.

---

## 6. Difference Between LEFT, RIGHT, and FULL OUTER JOIN

| JOIN Type | All Left Rows | All Right Rows | Matching Rows |
|---|---|---|---|
| LEFT JOIN | Yes | No | Yes |
| RIGHT JOIN | No | Yes | Yes |
| FULL OUTER JOIN | Yes | Yes | Yes |

### Easy Memory Trick

- LEFT JOIN → Preserve everything from the left.
- RIGHT JOIN → Preserve everything from the right.
- FULL OUTER JOIN → Preserve everything from both sides.

## 7. Finding Unmatched Records Using OUTER JOIN

One of the most useful applications of OUTER JOIN is finding records that do not have a matching record in another table.

### Example 1: Find Employees Without a Matching Department

```sql
SELECT
    e.employee_id,
    e.name,
    e.department_id
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.department_id
WHERE d.department_id IS NULL;
```

### Output

| employee_id | name | department_id |
|---|---|---|
| 5 | Kiran | NULL |
| 6 | Aman | 105 |

### Explanation

The LEFT JOIN keeps all employees.

The WHERE condition selects employees for whom no matching department was found.

Notice that this includes both:
- Employees with a NULL department ID.
- Employees with a non-NULL department ID that does not exist in the departments table.

### Example 2: Find Departments Without Employees

```sql
SELECT
    d.department_id,
    d.department_name
FROM departments d
LEFT JOIN employees e
ON d.department_id = e.department_id
WHERE e.employee_id IS NULL;
```

### Output

| department_id | department_name |
|---|---|
| 104 | Marketing |

This is called an anti-join pattern: finding rows in one table that have no matching rows in another.

## 8. OUTER JOIN with WHERE

We can use WHERE to filter the results returned by an OUTER JOIN.

### Example: Display all employees from the IT department, including unmatched employees

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.department_id
WHERE d.department_name = 'IT';
```

**Output:**

| name | department_name |
|---|---|
| Rahul | IT |
| Arjun | IT |

Important: The WHERE condition removes unmatched employees because their department name is NULL.

Therefore, this query does not preserve all employee rows in the final result.

### Important Difference: ON vs WHERE

Consider these two queries.

**Query A: Filter inside ON**

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.department_id
AND d.department_name = 'IT';
```

This returns every employee.

Only IT departments are allowed to match. Employees in other departments or without a department get NULL for `department_name`.

**Query B: Filter inside WHERE**

```sql
SELECT
    e.name,
    d.department_name
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.department_id
WHERE d.department_name = 'IT';
```

This returns only employees whose matching department is IT.

**Key difference:**

- `ON` controls which right-side records can match.
- `WHERE` filters the resulting rows, including rows produced by the outer join.

## 9. OUTER JOIN with GROUP BY

We can use aggregate functions with OUTER JOIN.

### Example: Count employees in every department, including departments with zero employees.

```sql
SELECT
    d.department_name,
    COUNT(e.employee_id) AS total_employees
FROM departments d
LEFT JOIN employees e
ON d.department_id = e.department_id
GROUP BY d.department_id, d.department_name;
```

### Output

| department_name | total_employees |
|---|---:|
| IT | 2 |
| HR | 1 |
| Finance | 1 |
| Marketing | 0 |

### Why use COUNT(e.employee_id) instead of COUNT(*)?

This is important!

For Marketing, the LEFT JOIN still produces one result row, but the employee columns contain NULL.

- `COUNT(*)` counts that joined row and returns 1.
- `COUNT(e.employee_id)` ignores NULL and correctly returns 0.

---

## 10. OUTER JOIN with HAVING

We can filter grouped results using HAVING.

### Example: Find departments with fewer than two employees, including departments with zero employees.

```sql
SELECT
    d.department_name,
    COUNT(e.employee_id) AS total_employees
FROM departments d
LEFT JOIN employees e
ON d.department_id = e.department_id
GROUP BY d.department_id, d.department_name
HAVING COUNT(e.employee_id) < 2;
```

### Output

| department_name | total_employees |
|---|---:|
| HR | 1 |
| Finance | 1 |
| Marketing | 0 |

## 11. OUTER JOIN vs INNER JOIN

| INNER JOIN | OUTER JOIN |
|---|---|
| Returns only matching rows | Can preserve unmatched rows |
| Excludes unmatched records | Includes unmatched records from the preserved side |
| Useful when only related records are required | Useful when unmatched records are also important |

### INNER JOIN Example

```sql
SELECT e.name, d.department_name
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id;
```

Kiran, Aman, and Marketing are excluded.

### LEFT JOIN Example

```sql
SELECT e.name, d.department_name
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.department_id;
```

All employees are included, including Kiran and Aman.

## 12. Common Mistakes

### Mistake 1: Thinking LEFT JOIN and RIGHT JOIN are different in matching behavior

They both preserve one side and match the other. The difference is which table is preserved.

### Mistake 2: Using WHERE on the right table unintentionally

```sql
SELECT *
FROM employees e
LEFT JOIN departments d
ON e.department_id = d.department_id
WHERE d.department_name = 'IT';
```

This removes unmatched employees from the final result.

### Mistake 3: Using COUNT(*) for unmatched groups

When counting matching rows after a LEFT JOIN, prefer:

```sql
COUNT(e.employee_id)
```

rather than:

```sql
COUNT(*)
```

### Mistake 4: Assuming MySQL supports FULL OUTER JOIN

MySQL does not support native FULL OUTER JOIN syntax. Use a LEFT JOIN plus unmatched RIGHT JOIN rows with UNION ALL.

## 15. Key Takeaways

- OUTER JOIN preserves unmatched rows from one or both tables.
- LEFT JOIN preserves all rows from the left table.
- RIGHT JOIN preserves all rows from the right table.
- FULL OUTER JOIN preserves all rows from both tables.
- MySQL supports LEFT and RIGHT OUTER JOIN directly.
- MySQL does not support native FULL OUTER JOIN syntax.
- UNION ALL can simulate FULL OUTER JOIN when combined with an anti-match condition.
- LEFT JOIN with IS NULL is useful for finding unmatched records.
- COUNT(column) is often more appropriate than COUNT(*) when counting matching records after a LEFT JOIN.
