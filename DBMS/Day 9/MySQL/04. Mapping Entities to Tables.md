# Mapping Entities to Tables in DBMS

## 1. Introduction

Mapping Entities to Tables is the process of converting entities, attributes, and relationships from an Entity-Relationship (ER) model into relational database tables.

In simple words, we identify real-world objects, understand their properties, and convert them into tables and columns.

### Real-world Example

Consider a Student Management System.

We have the following entities:

- Student
- Course
- Teacher
- Department

When designing a relational database:

- Each entity generally becomes a table.
- Each attribute becomes a column.
- Each record becomes a row.
- Primary Keys uniquely identify records.
- Foreign Keys connect related tables.

## 2. Entity to Table Mapping

An entity represents a real-world object or concept.

Example: Student.

### Student Entity

Attributes:

- student_id
- student_name
- age
- email
- city

### Mapping into a Table

**Students Table**

| student_id | student_name | age | email | city |
|---|---|---:|---|---|
| 1 | Rahul | 22 | rahul@gmail.com | Chennai |
| 2 | Priya | 23 | priya@gmail.com | Bangalore |
| 3 | Amit | 21 | amit@gmail.com | Mumbai |

Here:

- Student becomes the Students table.
- student_id becomes a column.
- student_name becomes a column.
- Each student becomes a row.

### SQL Implementation

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(50),
    age INT,
    email VARCHAR(100),
    city VARCHAR(50)
);
```

## 3. Attribute to Column Mapping

Attributes describe the properties of an entity.

Each simple attribute generally becomes a column in the corresponding table.

### Example

Entity: Employee

Attributes:

- employee_id
- employee_name
- salary
- joining_date

### Mapping

| Attribute | SQL Column | Data Type |
|---|---|---|
| employee_id | employee_id | INT |
| employee_name | employee_name | VARCHAR(50) |
| salary | salary | DECIMAL(10,2) |
| joining_date | joining_date | DATE |

### SQL Implementation

```sql
CREATE TABLE Employees (
    employee_id INT PRIMARY KEY,
    employee_name VARCHAR(50),
    salary DECIMAL(10,2),
    joining_date DATE
);
```

## 4. Mapping Primary Keys

A Primary Key uniquely identifies each record in a table.

### Example

**Students Table**

| student_id | student_name |
|---|---|
| 1 | Rahul |
| 2 | Priya |
| 3 | Amit |

Here, student_id is the Primary Key.

### SQL Implementation

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(50)
);
```

### Important Rules

- A Primary Key must contain unique values.
- A Primary Key cannot contain NULL.
- A table has only one Primary Key constraint, which can consist of multiple columns.
- Primary Keys identify records uniquely.

## 5. Mapping One-to-One Relationships

In a One-to-One relationship, one record in one table is associated with one record in another table.

### Example: Person and Passport

One person has one passport record in this simplified database design.

### Person Table

| person_id | name |
|---|---|
| 1 | Rahul |
| 2 | Priya |

### Passport Table

| passport_id | person_id | passport_number |
|---|---|---|
| 101 | 1 | P12345 |
| 102 | 2 | P67890 |

### SQL Implementation

```sql
CREATE TABLE Person (
    person_id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE Passport (
    passport_id INT PRIMARY KEY,
    person_id INT UNIQUE,
    passport_number VARCHAR(20),

    FOREIGN KEY (person_id)
        REFERENCES Person(person_id)
);
```

### Why UNIQUE?

UNIQUE ensures that the same person_id cannot appear more than once in the Passport table.

This enforces the One-to-One restriction on the Passport side.

## 6. Mapping One-to-Many Relationships

In a One-to-Many relationship, one record from the first table can be associated with multiple records in the second table.

### Example: Department and Employees

- One department can have multiple employees.
- Each employee belongs to one department.

### Departments Table

| department_id | department_name |
|---|---|
| 101 | IT |
| 102 | HR |
| 103 | Finance |

### Employees Table

| employee_id | employee_name | department_id |
|---|---|---|
| 1 | Rahul | 101 |
| 2 | Priya | 101 |
| 3 | Amit | 102 |
| 4 | Sneha | 103 |

### SQL Implementation

```sql
CREATE TABLE Departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(50)
);

CREATE TABLE Employees (
    employee_id INT PRIMARY KEY,
    employee_name VARCHAR(50),
    department_id INT,

    FOREIGN KEY (department_id)
        REFERENCES Departments(department_id)
);
```

### Important Rule

In a One-to-Many relationship, the Foreign Key is placed in the Many-side table.

Here, department_id is stored in Employees because multiple employees can belong to one department.

## 7. Mapping Many-to-Many Relationships

In a Many-to-Many relationship:

- One student can enroll in multiple courses.
- One course can have multiple students.

Relational databases implement this relationship using an intermediate table.

It is called:

- Junction Table
- Bridge Table
- Associative Table

### Students Table

| student_id | student_name |
|---|---|
| 1 | Rahul |
| 2 | Priya |
| 3 | Amit |

### Courses Table

| course_id | course_name |
|---|---|
| 101 | Java |
| 102 | Python |
| 103 | SQL |

### Enrollment Table

| enrollment_id | student_id | course_id |
|---|---|---|
| 1 | 1 | 101 |
| 2 | 1 | 102 |
| 3 | 2 | 101 |
| 4 | 2 | 103 |
| 5 | 3 | 102 |

### SQL Implementation

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(50)
);

CREATE TABLE Courses (
    course_id INT PRIMARY KEY,
    course_name VARCHAR(50)
);

CREATE TABLE Enrollment (
    enrollment_id INT PRIMARY KEY,
    student_id INT,
    course_id INT,

    FOREIGN KEY (student_id)
        REFERENCES Students(student_id),

    FOREIGN KEY (course_id)
        REFERENCES Courses(course_id),

    UNIQUE (student_id, course_id)
);
```

### Why Do We Need an Enrollment Table?

A relational database does not normally store multiple course IDs in one student row.

Instead, each student-course combination is represented by a separate Enrollment record.

This makes the Many-to-Many relationship possible.

## 8. Mapping Composite Attributes

A composite attribute is an attribute that can be divided into smaller meaningful attributes.

### Example: Address

An address can contain:

- Street
- City
- State
- Pincode

Instead of storing everything in one column, we can separate the components.

### Students Table

| student_id | name | street | city | state | pincode |
|---|---|---|---|---|---|
| 1 | Rahul | MG Road | Chennai | Tamil Nadu | 600001 |

### SQL Implementation

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    street VARCHAR(100),
    city VARCHAR(50),
    state VARCHAR(50),
    pincode VARCHAR(10)
);
```

Each component becomes a separate column.

## 9. Mapping Multivalued Attributes

A multivalued attribute can contain multiple values for a single entity.

### Example: Employee Phone Numbers

One employee may have multiple phone numbers.

Instead of storing:

| employee_id | name | phone_numbers |
|---|---|---|
| 1 | Rahul | 9876543210, 9123456780 |

We create a separate table.

### Employees Table

| employee_id | name |
|---|---|
| 1 | Rahul |
| 2 | Priya |

### EmployeePhones Table

| phone_id | employee_id | phone_number |
|---|---|---|
| 1 | 1 | 9876543210 |
| 2 | 1 | 9123456780 |
| 3 | 2 | 9988776655 |

### SQL Implementation

```sql
CREATE TABLE Employees (
    employee_id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE EmployeePhones (
    phone_id INT PRIMARY KEY,
    employee_id INT,
    phone_number VARCHAR(15),

    FOREIGN KEY (employee_id)
        REFERENCES Employees(employee_id)
);
```

This keeps phone numbers organized without storing multiple values in one cell.

## 10. Mapping Weak Entities

A Weak Entity is an entity that cannot be uniquely identified using its own attributes alone and depends on an owner entity.

### Example: Employee and Dependents

A dependent belongs to an employee.

A dependent may be identified using:

- employee_id
- dependent_name

### Employees Table

| employee_id | employee_name |
|---|---|
| 1 | Rahul |
| 2 | Priya |

### Dependents Table

| employee_id | dependent_name | relationship |
|---|---|---|
| 1 | Ramesh | Father |
| 1 | Sita | Mother |
| 2 | Arun | Brother |

### SQL Implementation

```sql
CREATE TABLE Employees (
    employee_id INT PRIMARY KEY,
    employee_name VARCHAR(50)
);

CREATE TABLE Dependents (
    employee_id INT,
    dependent_name VARCHAR(50),
    relationship VARCHAR(30),

    PRIMARY KEY (employee_id, dependent_name),

    FOREIGN KEY (employee_id)
        REFERENCES Employees(employee_id)
);
```

Here, the combination of employee_id and dependent_name forms a Composite Primary Key.

## 11. Mapping Summary

| ER Concept | Relational Database Mapping |
|---|---|
| Strong Entity | Table |
| Simple Attribute | Column |
| Composite Attribute | Multiple columns |
| Multivalued Attribute | Separate table |
| Primary Key | Primary Key constraint |
| One-to-One | Foreign Key with UNIQUE |
| One-to-Many | Foreign Key on Many side |
| Many-to-Many | Junction table |
| Weak Entity | Table with owner key |

## 14. Key Takeaways

- Entity Mapping converts real-world entities into relational tables.
- Attributes become columns.
- Records become rows.
- Primary Keys uniquely identify records.
- Foreign Keys connect related tables.
- One-to-One relationships can use UNIQUE constraints.
- One-to-Many relationships place the Foreign Key on the Many side.
- Many-to-Many relationships require a junction table.
- Composite attributes can be separated into multiple columns.
- Multivalued attributes are represented using separate tables.
- Weak entities depend on owner entities for identification.
