# Information and Data Models in DBMS

## 1. Introduction

A Database Management System (DBMS) is software used to store, organize, manage, retrieve, and manipulate data efficiently.

Before designing a database, we need to understand how data is represented, structured, and connected.

Data models help us understand how information is organized inside a database.

## 2. What is Data?

Data refers to raw facts, figures, or values that can be collected and stored.

**Examples:**
- 25
- Rahul
- Chennai
- 45000
- 2026-11-27

Individually, these values may not provide much meaning.

For example, `25` could represent age, quantity, marks, or something else.

Data needs context to become meaningful information.

## 3. What is Information?

Information is processed, organized, or interpreted data that provides meaning.

**Example:**

Consider the following raw data:

- Rahul
- 25
- Chennai
- 45000

When organized into a table:

| Name | Age | City | Salary |
|---|---:|---|---:|
| Rahul | 25 | Chennai | 45000 |

Now the data becomes meaningful information about an employee.

### Difference Between Data and Information

| Data | Information |
|---|---|
| Raw facts and figures | Processed and meaningful data |
| May lack context | Provides context |
| Individual values | Organized values |
| Example: 25 | Example: Employee age is 25 |

## 4. What is a Data Model?

A Data Model is a conceptual representation of how data is organized, stored, connected, and managed in a database.

It describes:

- What data needs to be stored.
- How different data elements are related.
- What properties each entity has.
- What rules apply to the data.
- How data is structured inside a database.

### Real-world Example

Imagine building a food delivery application like Swiggy.

We need to store:

- Customers
- Restaurants
- Orders
- Payments
- Delivery partners

A data model helps us understand how these entities are connected before creating database tables.

## 5. Types of Data Models

Data models are commonly classified into three database design levels:

1. Conceptual Data Model
2. Logical Data Model
3. Physical Data Model

Each level represents a different stage of database design.

## 6. Conceptual Data Model

A Conceptual Data Model provides a high-level view of the database.

It focuses on identifying:

- Main entities.
- Relationships between entities.
- Business requirements.

It does not focus on implementation details such as column data types or SQL syntax.

### Example

Consider a food delivery application.

Main entities:

- Customer
- Restaurant
- Order
- Payment

Relationships:

- Customer places an Order.
- Restaurant receives an Order.
- Order has a Payment.

### Conceptual Representation

```text
Customer
    |
    | Places
    |
   Order
    |
    | Has
    |
  Payment

Restaurant
    |
    | Receives
    |
   Order
```

### Characteristics

- High-level representation.
- Easy for business users to understand.
- Focuses on entities and relationships.
- Independent of database technology.

## 7. Logical Data Model

A Logical Data Model provides a more detailed representation of the database.

It defines:

- Entities.
- Attributes.
- Primary Keys.
- Foreign Keys.
- Relationships.
- Constraints.

It explains how data is logically organized without depending on a specific database technology.

### Example

Consider the same food delivery application.

**Customer Entity**

| Attribute | Description |
|---|---|
| customer_id | Unique customer identifier |
| customer_name | Customer name |
| email | Customer email |
| phone | Customer phone number |

Primary Key: `customer_id`

**Order Entity**

| Attribute | Description |
|---|---|
| order_id | Unique order identifier |
| customer_id | Customer reference |
| restaurant_id | Restaurant reference |
| order_date | Date of order |
| amount | Total order amount |

Primary Key: `order_id`

Foreign Keys:

- `customer_id`
- `restaurant_id`

### Logical Representation

```text
CUSTOMER
----------------
customer_id (PK)
customer_name
email
phone

       |
       | 1:M
       |

ORDER
----------------
order_id (PK)
customer_id (FK)
restaurant_id (FK)
order_date
amount
```

### Characteristics

- Defines entities and attributes.
- Identifies primary and foreign keys.
- Defines relationships and constraints.
- Independent of a particular DBMS implementation.

## 8. Physical Data Model

A Physical Data Model describes how the database will actually be implemented in a specific database management system.

It includes:

- Actual table names.
- Column names.
- Data types.
- Primary Key constraints.
- Foreign Key constraints.
- Indexes.
- Database-specific implementation details.

### Example

The logical Customer entity can be implemented using SQL.

```sql
CREATE TABLE Customers (
    customer_id INT PRIMARY KEY,
    customer_name VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE,
    phone VARCHAR(15)
);
```

The logical Order entity can be implemented as:

```sql
CREATE TABLE Orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    restaurant_id INT,
    order_date DATE,
    amount DECIMAL(10,2),

    FOREIGN KEY (customer_id)
        REFERENCES Customers(customer_id)
);
```

*Note: This example assumes a Restaurants table will also be created before adding its foreign key constraint.*

### Characteristics

- Database-specific implementation.
- Specifies actual data types.
- Defines indexes and constraints.
- Used during database development.

## 9. Difference Between Conceptual, Logical, and Physical Models

| Conceptual Model | Logical Model | Physical Model |
|---|---|---|
| High-level view | Detailed logical structure | Actual implementation |
| Identifies entities | Defines entities and attributes | Defines tables and columns |
| Shows relationships | Defines keys and constraints | Implements keys and constraints |
| No technical details | Limited implementation details | Database-specific details |
| Business-focused | Design-focused | Developer/DBA-focused |

### Simple Example

Imagine designing a Student Management System.

**Conceptual Model:**

Identify Student, Course, and Teacher.

**Logical Model:**

Define Student ID, Student Name, Course ID, and relationships between entities.

**Physical Model:**

Create actual SQL tables using INT, VARCHAR, PRIMARY KEY, and FOREIGN KEY.

## 10. Common Types of Data Models Based on Structure

Apart from the three database design levels, data models can also be classified by how they organize data.

### 10.1 Hierarchical Data Model

The Hierarchical Data Model organizes data in a tree-like structure.

Each child record generally has one parent record.

**Example:**

```text
Company
   |
   +-- Department
          |
          +-- Employee 1
          |
          +-- Employee 2
```

**Characteristics:**

- Tree-based structure.
- Parent-child relationship.
- Suitable for hierarchical data.
- Represents one-to-many relationships naturally.

### 10.2 Network Data Model

The Network Data Model organizes data using records connected through links.

A record can have multiple parent and child records.

**Example:**

```text
       Student 1
        /     \
       /       \
   Course A   Course B
       \       /
        \     /
       Student 2
```

**Characteristics:**

- Supports many-to-many relationships.
- More flexible than the hierarchical model.
- Uses interconnected records.

### 10.3 Relational Data Model

The Relational Data Model organizes information into tables containing rows and columns.

Tables are connected using Primary Keys and Foreign Keys.

**Example:**

Students Table:

| student_id | name |
|---|---|
| 1 | Rahul |
| 2 | Priya |

Courses Table:

| course_id | course_name |
|---|---|
| 101 | Java |
| 102 | Python |

Enrollment Table:

| student_id | course_id |
|---|---|
| 1 | 101 |
| 1 | 102 |
| 2 | 101 |

**Characteristics:**

- Stores data in tables.
- Uses rows and columns.
- Supports relationships through keys.
- Uses SQL for querying.
- Supports normalization.

### 10.4 Object-Oriented Data Model

The Object-Oriented Data Model represents data as objects, similar to object-oriented programming.

Objects contain:

- Attributes (data).
- Methods (behavior).

**Example:**

```text
Student Object

Attributes:
    student_id
    name
    age

Methods:
    registerCourse()
    displayDetails()
```

This model combines data and behavior into objects.

## 11. What is an Entity?

An Entity is a real-world object, person, place, or concept about which we want to store information.

**Examples:**

- Student
- Employee
- Customer
- Product
- Order
- Department

In database design, entities are generally represented as tables in a relational database.

## 12. What is an Attribute?

An Attribute is a property or characteristic of an entity.

**Example:**

Entity: Student

Attributes:

- student_id
- student_name
- age
- email
- city

In relational databases, attributes are represented as columns.

## 13. What is a Relationship?

A Relationship describes how two or more entities are associated with each other.

**Examples:**

- A student enrolls in a course.
- A customer places an order.
- An employee works in a department.

Common relationship types:

1. One-to-One (1:1)
2. One-to-Many (1:M)
3. Many-to-Many (M:N)

These relationships will be covered in detail in the next topic.

## 14. Why Are Data Models Important?

1. Help understand business requirements.
2. Provide a clear database structure.
3. Reduce design mistakes.
4. Identify relationships between entities.
5. Improve data organization.
6. Help maintain data consistency.
7. Make database development easier.
8. Provide documentation for developers and database administrators.
