# Types of Relationships in DBMS

## 1. Introduction

In a relational database, a relationship describes how two or more tables are connected to each other.

Relationships help organize data and maintain connections between different entities.

For example, in a college management system:

- A student enrolls in courses.
- A teacher teaches subjects.
- A department has multiple employees.
- A person owns a passport.

Relationships are established using Primary Keys and Foreign Keys.

## 2. Types of Relationships

There are three major types of relationships in relational database design:

1. One-to-One (1:1)
2. One-to-Many (1:M)
3. Many-to-Many (M:N)

---

## 3. One-to-One Relationship (1:1)

A One-to-One relationship means one record in Table A is associated with only one record in Table B, and vice versa.

### Real-world Example

Consider two entities:

- Person
- Passport

Rules:

- One person has one passport.
- One passport belongs to one person.

### ER Diagram

```text
+----------------+       +----------------+
|     Person     |       |    Passport    |
+----------------+       +----------------+
| person_id (PK) |  1:1  | passport_id(PK)|
| name           |-------| person_id (FK) |
| age            |       | passport_no    |
+----------------+       +----------------+
```

### SQL Implementation

**Step 1: Create Person Table**

```sql
CREATE TABLE Person (
    person_id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT
);
```

**Step 2: Create Passport Table**

```sql
CREATE TABLE Passport (
    passport_id INT PRIMARY KEY,
    person_id INT UNIQUE,
    passport_no VARCHAR(20),

    FOREIGN KEY (person_id)
        REFERENCES Person(person_id)
);
```

### Why UNIQUE?

The UNIQUE constraint ensures that the same person_id cannot appear multiple times in the Passport table.

Without UNIQUE, one person could have multiple passport records in this table.

### Insert Records

```sql
INSERT INTO Person VALUES
(1, 'Rahul', 25),
(2, 'Priya', 23);

INSERT INTO Passport VALUES
(101, 1, 'P12345'),
(102, 2, 'P67890');
```

### Person Table

| person_id | name | age |
|---|---|---:|
| 1 | Rahul | 25 |
| 2 | Priya | 23 |

### Passport Table

| passport_id | person_id | passport_no |
|---|---|---|
| 101 | 1 | P12345 |
| 102 | 2 | P67890 |

### Important Points

- One record corresponds to one record in the other table.
- A Foreign Key establishes the relationship.
- UNIQUE enforces the One-to-One restriction on the foreign key.
- NOT NULL can be added if every passport must belong to a person.

## 4. One-to-Many Relationship (1:M)

A One-to-Many relationship means one record in Table A can be associated with multiple records in Table B.

However, each record in Table B is associated with only one record in Table A.

### Real-world Example

Consider two entities:

- Department
- Employees

Rules:

- One department can have multiple employees.
- Each employee belongs to one department.

|     Department      |
+---------------------+
| department_id (PK)  |
| department_name     |
+---------------------+
           |
           | 1
           |
           | M
           |
+---------------------+
|      Employees
