
# Introduction to SQL and Relational Databases

## 1. What is SQL?

SQL stands for **Structured Query Language**.

It is a standard language used to communicate with relational database management systems (RDBMS).

SQL is used to:

- Create databases and tables.
- Insert data into tables.
- Retrieve information from databases.
- Update existing records.
- Delete records.
- Manage database structures.
- Control access to database objects.

### Example

```sql
SELECT * FROM Employees;
```

This query retrieves all columns and records from the Employees table.

## 3. What is a Relational Database?

A relational database is a database that organizes data into tables consisting of rows and columns.

Different tables can be connected through relationships using keys.

### Example

Consider two tables: Customers and Orders.

#### Customers Table

| customer_id | customer_name | city |
|---|---|---|
| 1 | Rahul | Chennai |
| 2 | Priya | Bangalore |
| 3 | Amit | Mumbai |

#### Orders Table

| order_id | customer_id | amount |
|---|---|---|
| 101 | 1 | 500 |
| 102 | 2 | 750 |
| 103 | 1 | 300 |

Here:

- `customer_id` is the Primary Key in Customers.
- `customer_id` is a Foreign Key in Orders.
- The relationship connects customers with their orders.

A relational database helps maintain relationships between different tables.

## 4. Understanding Tables, Rows, and Columns

A relational database organizes information using tables.

Consider the Employees table.

| employee_id | name | age | salary |
|---|---|---|---|
| 1 | Rahul | 25 | 45000 |
| 2 | Priya | 23 | 55000 |
| 3 | Amit | 28 | 65000 |

### Table

A table stores related information.

Example: Employees.

### Row (Record)

A row represents one complete record.

Example:

`1, Rahul, 25, 45000`

### Column (Attribute)

A column represents a particular property of the data.

Examples:

- employee_id
- name
- age
- salary

### Cell

A cell represents a single value at the intersection of a row and column.

Example: Rahul's age is 25.

## 5. What is RDBMS?

RDBMS stands for **Relational Database Management System**.

It is software used to create, manage, and interact with relational databases.

### Popular RDBMS Software

| RDBMS | Description |
|---|---|
| MySQL | Popular open-source relational database |
| PostgreSQL | Advanced open-source relational database |
| Oracle Database | Enterprise-level relational database |
| Microsoft SQL Server | Microsoft's relational database system |
| SQLite | Lightweight embedded relational database |

### SQL vs RDBMS

| SQL | RDBMS |
|---|---|
| A query language | Database management software |
| Used to communicate with databases | Used to manage databases |
| Contains commands such as SELECT and INSERT | Executes SQL commands |
| Example: SELECT * FROM Employees | Example: MySQL |

## 7. Types of SQL Commands

SQL commands are commonly divided into five categories.

### 7.1 DDL – Data Definition Language

Used to define or modify database structures.

Commands:

- CREATE
- ALTER
- DROP
- TRUNCATE

Example:

```sql
CREATE TABLE Employees (
    employee_id INT,
    name VARCHAR(50)
);
```

### 7.2 DML – Data Manipulation Language

Used to modify data stored inside tables.

Commands:

- INSERT
- UPDATE
- DELETE

Example:

```sql
INSERT INTO Employees
VALUES (1, 'Rahul');
```

### 7.3 DQL – Data Query Language

Used to retrieve information from databases.

Command:

- SELECT

Example:

```sql
SELECT * FROM Employees;
```

### 7.4 DCL – Data Control Language

Used to manage database permissions.

Commands:

- GRANT
- REVOKE

### 7.5 TCL – Transaction Control Language

Used to manage database transactions.

Commands:

- COMMIT
- ROLLBACK
- SAVEPOINT

## 8. Creating Your First Database

The CREATE DATABASE command creates a new database.

```sql
CREATE DATABASE CompanyDB;
```

This creates a database named CompanyDB.

To select the database in MySQL:

```sql
USE CompanyDB;
```

The USE command makes CompanyDB the active database for subsequent queries.

---

## 9. Creating Your First Table

The CREATE TABLE command creates a new table.

```sql
CREATE TABLE Employees (
    employee_id INT,
    name VARCHAR(50),
    age INT,
    salary DECIMAL(10,2),
    city VARCHAR(50)
);
```

### Explanation of Data Types

| Data Type | Purpose | Example |
|---|---|---|
| INT | Stores whole numbers | 25 |
| VARCHAR(50) | Stores variable-length text | Rahul |
| CHAR(10) | Stores fixed-length text | ABC |
| DECIMAL(10,2) | Stores decimal numbers | 45000.50 |
| DATE | Stores dates | 2026-11-27 |
| BOOLEAN | Represents true or false values | TRUE |

## 10. Inserting Records

The INSERT command adds new records to a table.

```sql
INSERT INTO Employees
(employee_id, name, age, salary, city)
VALUES
(1, 'Rahul', 25, 45000, 'Chennai'),
(2, 'Priya', 23, 55000, 'Bangalore'),
(3, 'Amit', 28, 65000, 'Mumbai'),
(4, 'Sneha', 24, 40000, 'Delhi');
```

This inserts four employee records into the Employees table.

## 11. Retrieving Records Using SELECT

The SELECT command retrieves data from a database.

### Retrieve All Records

```sql
SELECT * FROM Employees;
```

### Retrieve Specific Columns

```sql
SELECT name, salary
FROM Employees;
```

### Retrieve Records Using WHERE

```sql
SELECT *
FROM Employees
WHERE city = 'Chennai';
```

The WHERE clause filters records based on a specified condition.

- Financial applications

### When to Use NoSQL?

- Real-time applications
- Large-scale distributed systems
- Flexible document storage
- Applications with rapidly changing data structures

## 14. Basic SQL Query Execution Order

SQL queries are written in a particular order, but their logical processing order is different.

Consider:

```sql
SELECT city, COUNT(*) AS total_employees
FROM Employees
WHERE age > 20
GROUP BY city
HAVING COUNT(*) > 1
ORDER BY total_employees DESC;
```

### Logical Execution Order

1. FROM – Identifies the source table.
2. WHERE – Filters individual records.
3. GROUP BY – Groups records.
4. HAVING – Filters groups.
5. SELECT – Determines the output columns.
6. ORDER BY – Sorts the result.

Note: This is the logical processing order, not necessarily the physical execution order used by the database engine.
