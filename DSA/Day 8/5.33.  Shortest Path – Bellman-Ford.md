# Shortest Path – Bellman-Ford Algorithm

## 1. What is Bellman-Ford Algorithm?

**Bellman-Ford** is a shortest-path algorithm used to find the minimum distance from a single source vertex to all other vertices in a weighted graph.

Unlike Dijkstra's Algorithm, Bellman-Ford can handle **negative edge weights**.

It can also detect **negative-weight cycles** that are reachable from the source.

### Real-world applications

- Currency exchange rate analysis.
- Network routing.
- Financial transaction analysis.
- Graphs containing negative costs or rewards.
- Detecting negative cycles in weighted graphs.

---

## 2. Understanding Weighted Graphs

A weighted graph contains edges with numerical values called weights.

Example:

```text
       4
   A ------> B
   |         |
  2|         |-3
   |         |
   ↓         ↓
   C ------> D
       5
```

Edges:

```text
A → B = 4
A → C = 2
B → D = -3
C → D = 5
```

Notice that one edge has a negative weight:

```text
B → D = -3
```

This means travelling along that edge decreases the total path cost.

**Important:** Negative edge weights are allowed in Bellman-Ford, but a reachable negative-weight cycle means there is no finite shortest distance for vertices that can be reached from that cycle.

---

## 3. Why Do We Need Bellman-Ford?

Let's compare Dijkstra and Bellman-Ford.

| Feature | Dijkstra | Bellman-Ford |
|---|---|---|
| Negative edge weights | Not supported in general | Supported |
| Negative cycle detection | No | Yes |
| Approach | Greedy | Repeated edge relaxation |
| Data structure | Priority queue | Edge list |
| Time complexity | O((V + E) log V) with a binary heap | O(V × E) |
| Usually faster | Yes | No |

### Example where Dijkstra can fail

Consider:

```text
A → B = 2
A → C = 5
C → B = -10
```

Possible paths from A to B:

**Path 1:**

```text
A → B

Cost = 2
```

**Path 2:**

```text
A → C → B

Cost = 5 + (-10) = -5
```

The shortest path is:

```text
A → C → B

Minimum cost = -5
```

Dijkstra may finalize B with distance 2 before discovering the better route through C.

Bellman-Ford can correctly discover the shorter path because it repeatedly relaxes all edges.

---

## 4. Understanding Edge Relaxation

Relaxation is the most important concept in Bellman-Ford.

It means checking whether a new path gives a smaller distance than the currently known distance.

Formula:

```text
new_distance = distance[u] + weight(u, v)
```

If:

```text
new_distance < distance[v]
```

Update:

```text
distance[v] = new_distance
```

### Example

Suppose:

```text
A → B = 4
B → C = 3
```

Initial distances:

```text
A = 0
B = ∞
C = ∞
```

Relax edge A → B:

```text
new_distance = 0 + 4 = 4
```

Update:

```text
B = 4
```

Relax edge B → C:

```text
new_distance = 4 + 3 = 7
```

Update:

```text
C = 7
```

Final distances:

```text
A = 0
B = 4
C = 7
```

---

## 5. Why Does Bellman-Ford Repeat V - 1 Times?

This is the central idea behind the algorithm.

A simple shortest path in a graph with V vertices can contain at most:

```text
V - 1 edges
```

Why?

A simple path does not repeat vertices.

For example, with four vertices:

```text
A → B → C → D
```

There are four vertices and three edges.

Therefore:

```text
Maximum edges in a simple path = V - 1
```

Each full iteration of Bellman-Ford relaxes all edges.

After:

- First iteration: shortest paths using at most 1 edge are found.
- Second iteration: shortest paths using at most 2 edges are found.
- Third iteration: shortest paths using at most 3 edges are found.

Therefore, after V - 1 iterations, all shortest distances are determined if there is no reachable negative-weight cycle.

**Important:** This reasoning assumes the usual shortest-path setting without reachable negative cycles. The implementation also handles edge ordering that may propagate updates faster than one edge per iteration.

## 6. Graph Representation Using an Edge List

Bellman-Ford is commonly implemented using an edge list.

Example:

```text
A → B = 4
A → C = 2
B → D = -3
C → D = 5
```

Python representation:

```python
edges = [
    ("A", "B", 4),
    ("A", "C", 2),
    ("B", "D", -3),
    ("C", "D", 5)
]
```

Each tuple contains:

```python
(source, destination, weight)
```

For example:

```python
("A", "B", 4)
```

means there is a directed edge from A to B with weight 4.

Unlike an undirected graph, a directed edge does not automatically create a reverse edge.

# PART 1: BELLMAN-FORD IMPLEMENTATION

## 7. Bellman-Ford Algorithm – Complete Python Code

```python
def bellman_ford(vertices, edges, start):

    distance = {
        vertex: float("inf")
        for vertex in vertices
    }

    distance[start] = 0

    # Relax all edges V - 1 times
    for _ in range(len(vertices) - 1):

        updated = False

        for u, v, weight in edges:

            if distance[u] != float("inf"):

                new_distance = distance[u] + weight

                if new_distance < distance[v]:

                    distance[v] = new_distance

                    updated = True

        # Stop early if no distance changed
        if not updated:
            break

    # Check for a reachable negative-weight cycle
    for u, v, weight in edges:

        if distance[u] != float("inf"):

            if distance[u] + weight < distance[v]:

                return None

    return distance


vertices = ["A", "B", "C", "D"]

edges = [
    ("A", "B", 4),
    ("A", "C", 2),
    ("B", "D", -3),
    ("C", "D", 5)
]

result = bellman_ford(vertices, edges, "A")

print(result)
```

Output:

```text
{
    'A': 0,
    'B': 4,
    'C': 2,
    'D': 1
}
```

### Understanding the result

| Vertex | Shortest distance from A |
|---|---:|
| A | 0 |
| B | 4 |
| C | 2 |
| D | 1 |

The shortest path from A to D is:

```text
A → B → D
```

Total cost:

```text
4 + (-3) = 1
```

The alternative path is:

```text
A → C → D

2 + 5 = 7
```

Therefore, the minimum distance is 1.

## 8. Understanding the Code Line by Line

### Step 1: Initialize distances

```python
distance = {
    vertex: float("inf")
    for vertex in vertices
}
```

Initially, every vertex has an unknown distance.

We assign infinity.

### Step 2: Set source distance

```python
distance[start] = 0
```

The distance from the source to itself is zero.

### Step 3: Repeat V - 1 times

```python
for _ in range(len(vertices) - 1):
```

We repeat the relaxation process V - 1 times.

Why?

Because a shortest simple path can contain at most V - 1 edges.

### Step 4: Iterate through every edge

```python
for u, v, weight in edges:
```

We examine each directed edge.

For example:

```python
("A", "B", 4)
```

Here:

- `u` = A
- `v` = B
- `weight` = 4

### Step 5: Check whether the source is reachable

```python
if distance[u] != float("inf"):
```

We should not calculate a path through a vertex that is unreachable from the starting vertex.

### Step 6: Calculate the new distance

```python
new_distance = distance[u] + weight
```

This calculates the cost of reaching v through u.

### Step 7: Relax the edge

```python
if new_distance < distance[v]:

    distance[v] = new_distance
```

If the newly discovered path is shorter, update the distance.

### Step 8: Early stopping optimization

```python
updated = False
```

We track whether any distance changed during an iteration.

If no distance changes:

```python
if not updated:
    break
```

There is no need to continue repeating the same work.

### Step 9: Detect a negative-weight cycle

```python
for u, v, weight in edges:

    if distance[u] != float("inf"):

        if distance[u] + weight < distance[v]:

            return None
```

After V - 1 iterations, if an edge can still be relaxed, a reachable negative-weight cycle exists.

We return `None` to indicate that no finite shortest-distance result exists for all reachable vertices.

# PART 2: NEGATIVE CYCLE DETECTION

## 10. What is a Negative-Weight Cycle?

A negative-weight cycle is a directed cycle whose total edge weight is negative.

Example:

```text
A → B = 2
B → C = -5
C → A = 1
```

Total cycle weight:

```text
2 + (-5) + 1 = -2
```

Since the total is negative, this is a negative-weight cycle.

### Why is this a problem?

Suppose we want to travel from A back to A.

We can repeatedly travel around the cycle:

```text
A → B → C → A
```

Each round reduces the total cost by 2.

After one round:

```text
Cost = -2
```

After two rounds:

```text
Cost = -4
```

After three rounds:

```text
Cost = -6
```

The cost can keep decreasing forever.

Therefore, a finite shortest path does not exist for vertices reachable from this negative cycle.

---

## 11. Detecting a Negative Cycle Using Bellman-Ford

Bellman-Ford performs V - 1 relaxation iterations.

After those iterations, it checks every edge one more time.

If any reachable edge can still be relaxed, a negative-weight cycle is reachable from the source.

### Example

```python
vertices = ["A", "B", "C"]

edges = [
    ("A", "B", 2),
    ("B", "C", -5),
    ("C", "A", 1)
]
```

Run:

```python
result = bellman_ford(vertices, edges, "A")

if result is None:
    print("Negative cycle detected")
else:
    print(result)
```

Output:

```text
Negative cycle detected
```

### Important distinction

The cycle must be reachable from the source to affect the result of a single-source Bellman-Ford run.

An unreachable negative cycle will not be detected by this source-specific check.

To detect a negative cycle anywhere in a graph, initialize all vertex distances to zero before running Bellman-Ford, or introduce a super-source connected to every vertex with a zero-weight edge.

---

## 12. Negative Cycle Detection – Step-by-Step Example

Consider:

```text
A → B = 2
B → C = -5
C → A = 1
```

Initial distances:

```text
A = 0
B = ∞
C = ∞
```

There are three vertices.

Therefore:

```text
V - 1 = 2 iterations
```

After repeated relaxation, distances keep decreasing because the cycle has negative total weight.

One possible set of distances after the two passes is:

```text
A = -2
B = 0
C = -5
```

Now perform the additional cycle check.

Check edge A → B:

```text
distance[A] + 2
= -2 + 2
= 0
```

Current distance[B] = 0.

No improvement here.

Check edge B → C:

```text
distance[B] + (-5)
= 0 - 5
= -5
```

Current distance[C] = -5.

No improvement here.

Check edge C → A:

```text
distance[C] + 1
= -5 + 1
= -4
```

Current distance[A] = -2.

Since:

```text
-4 < -2
```

The distance can still be reduced.

Therefore, a reachable negative-weight cycle exists.

# PART 3: RECONSTRUCTING THE SHORTEST PATH

## 13. Finding the Actual Shortest Path

Like Dijkstra, Bellman-Ford can return the actual shortest path using a parent dictionary.

Whenever a distance improves, store the previous vertex.

### Implementation

```python
def bellman_ford(vertices, edges, start):

    distance = {
        vertex: float("inf")
        for vertex in vertices
    }

    parent = {
        vertex: None
        for vertex in vertices
    }

    distance[start] = 0

    for _ in range(len(vertices) - 1):

        updated = False

        for u, v, weight in edges:

            if distance[u] != float("inf"):

                new_distance = distance[u] + weight

                if new_distance < distance[v]:

                    distance[v] = new_distance

                    parent[v] = u

                    updated = True

        if not updated:
            break

    for u, v, weight in edges:

        if distance[u] != float("inf"):

            if distance[u] + weight < distance[v]:

                return None, None

    return distance, parent


def get_path(parent, target):

    path = []

    current = target

    while current is not None:

        path.append(current)

        current = parent[current]

    path.reverse()

    return path


vertices = ["A", "B", "C", "D"]

edges = [
    ("A", "B", 4),
    ("A", "C", 2),
    ("B", "D", -3),
    ("C", "D", 5)
]

distance, parent = bellman_ford(vertices, edges, "A")

if distance is not None:

    print("Shortest distance:", distance["D"])

    if distance["D"] != float("inf"):
        print("Shortest path:", get_path(parent, "D"))
    else:
        print("Target is unreachable")
else:

    print("Negative cycle detected")
```

Output:

```text
Shortest distance: 1
Shortest path: ['A', 'B', 'D']
```

### Understanding the parent dictionary

```python
parent = {
    "A": None,
    "B": "A",
    "C": "A",
    "D": "B"
}
```

To reconstruct the path to D:

```text
D
↑
B
↑
A
```

Reverse it:

```text
A → B → D
```

# PART 4: IMPORTANT COMPARISONS

## 14. Bellman-Ford vs Dijkstra

| Feature | Bellman-Ford | Dijkstra |
|---|---|---|
| Negative edges | Yes | No, not in general |
| Negative cycle detection | Yes | No |
| Algorithm type | Repeated relaxation | Greedy |
| Data structure | Edge list | Priority queue |
| Time complexity | O(V × E) | O((V + E) log V) |
| Best use | Negative weights | Non-negative weights |

### When should you use Bellman-Ford?

Use Bellman-Ford when:
- The graph contains negative edge weights.
- You need to detect a reachable negative cycle.
- The graph is small enough for its higher time complexity.

### When should you use Dijkstra?

Use Dijkstra when:
- All edge weights are non-negative.
- You need an efficient shortest-path solution.
- The graph is large and a priority queue is suitable.

---

## 15. Bellman-Ford vs Floyd-Warshall

Both algorithms can handle negative edge weights under the appropriate conditions.

| Feature | Bellman-Ford | Floyd-Warshall |
|---|---|---|
| Problem type | Single-source shortest path | All-pairs shortest path |
| Negative edges | Yes | Yes |
| Negative cycle detection | Yes | Yes, using negative diagonal distances |
| Time complexity | O(V × E) | O(V³) |
| Space complexity | O(V) auxiliary space | O(V²) |

Use Bellman-Ford when you need shortest paths from one source.

Use Floyd-Warshall when you need shortest paths between every pair of vertices.

# PART 5: COMPLEXITY ANALYSIS

## 16. Time and Space Complexity

Let:

- V = Number of vertices.
- E = Number of edges.

### Time complexity

Bellman-Ford relaxes all edges V - 1 times.

Therefore:

```text
Time Complexity = O(V × E)
```

The final negative-cycle check takes O(E), which does not change the overall complexity.

### Space complexity

The algorithm maintains:

- Distance dictionary: O(V).
- Optional parent dictionary: O(V).
- Edge list: O(E), if included as part of the input representation.

Auxiliary space excluding the input graph:

```text
O(V)
```

### Complexity table

| Operation | Complexity |
|---|---|
| Initialize distances | O(V) |
| Relax all edges | O(V × E) |
| Detect negative cycle | O(E) |
| Auxiliary space | O(V) |

## 17. Common Mistakes

### Mistake 1: Running only V iterations without understanding the reason

The standard shortest-distance relaxation phase requires V - 1 passes.

The additional check is for negative-cycle detection.

### Mistake 2: Forgetting the infinity check

Incorrect:

```python
new_distance = distance[u] + weight
```

Better:

```python
if distance[u] != float("inf"):

    new_distance = distance[u] + weight
```

This prevents using an unreachable vertex as the starting point of a path.

### Mistake 3: Incorrect edge direction

For:

```python
("A", "B", 5)
```

The edge is A → B, not B → A.

### Mistake 4: Forgetting negative-cycle detection

Running V - 1 iterations alone does not tell us whether a reachable negative cycle exists.

Perform one additional relaxation check.

### Mistake 5: Confusing a negative edge with a negative cycle

A graph can contain negative edges without containing any negative cycle.

Bellman-Ford supports negative edges.

### Mistake 6: Detecting unreachable negative cycles incorrectly

A single-source implementation should only consider edges whose source vertex is reachable from the selected source.

### Mistake 7: Reconstructing a path to an unreachable vertex

Check whether its distance is infinity before reconstructing the path.
