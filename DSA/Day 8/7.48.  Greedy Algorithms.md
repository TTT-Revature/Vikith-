# Greedy Algorithms in Python – DSA Notes

## 1. What is a Greedy Algorithm?

A **Greedy Algorithm** is an algorithmic technique that makes the best possible choice at each step, hoping to achieve the overall optimal solution.

In simple words:

- Look at the available choices.
- Select the choice that appears best at the current moment.
- Move to the next step.
- Repeat until the problem is solved.

A greedy algorithm does not usually reconsider previous decisions.

### Real-Life Example

Imagine you are travelling and want to reach your destination as quickly as possible.

At every intersection, you choose the road that appears to get you closer to your destination.

You continue making the locally best decision until you reach the destination.

This is the basic idea behind greedy algorithms.

**Important:** A locally best choice does not always produce the globally best answer. Greedy algorithms work only when the problem has the right mathematical properties.

---

## 2. Understanding Local Optimal vs Global Optimal

These two concepts are very important.

### Local Optimal

The best choice available at the current step.

### Global Optimal

The best possible solution considering the entire problem.

Example:

Suppose you have coins:

```python
coins = [1, 5, 10, 25]
amount = 30
```

A greedy approach chooses the largest coin that does not exceed the remaining amount.

```text
30 - 25 = 5
5 - 5 = 0
```

Result:

```text
25 + 5 = 30
```

Number of coins = 2.

This is also the optimal solution for this coin system.

But greedy does not work for every coin system.

Consider:

```python
coins = [1, 3, 4]
amount = 6
```

Greedy chooses:

```text
4 + 1 + 1 = 6
```

Total coins = 3.

But the optimal solution is:

```text
3 + 3 = 6
```

Total coins = 2.

This demonstrates an important point:

**Making the best choice at each step does not always guarantee the best overall solution.**

---

## 3. When Should We Use Greedy Algorithms?

Greedy algorithms are useful when:

1. A locally optimal choice can lead to a globally optimal solution.
2. Decisions can be made without reconsidering previous choices.
3. The problem has a suitable greedy-choice property.
4. The problem has optimal substructure.

### Important Properties

#### A. Greedy Choice Property

A globally optimal solution can be obtained by making a locally optimal choice at each step.

#### B. Optimal Substructure

An optimal solution to a problem contains optimal solutions to its smaller subproblems.

These properties help establish whether a greedy approach is correct.

However, simply noticing that a greedy solution works for a few examples is not a proof.

---

# 4. Greedy Algorithm vs Dynamic Programming

Both techniques are used for optimization problems, but they work differently.

| Greedy Algorithm | Dynamic Programming |
|---|---|
| Makes a locally best choice | Solves and combines subproblems |
| Usually does not reconsider decisions | Stores results of subproblems |
| Often simpler and faster | May require more memory |
| Does not work for every optimization problem | Works when the required DP properties hold |
| Example: Activity Selection | Example: 0/1 Knapsack |

### Example: Coin Change

For coins:

```python
coins = [1, 3, 4]
amount = 6
```

Greedy result:

```text
4 + 1 + 1 = 6
```

3 coins.

Dynamic Programming can find:

```text
3 + 3 = 6
```

2 coins.

This is why we must understand whether a problem supports a greedy strategy before implementing it.

# 5. Classic Greedy Problems

## Problem 1: Activity Selection

**Problem:**

You are given start and finish times of different activities.

Select the maximum number of activities that do not overlap.

Input:

```python
activities = [
    (1, 3),
    (2, 5),
    (4, 7),
    (6, 9),
    (8, 10)
]
```

Each tuple represents:

```text
(start_time, finish_time)
```

Expected Output:

```text
[(1, 3), (4, 7), (8, 10)]
```

### Greedy Strategy

Always select the activity that finishes earliest among the remaining compatible activities.

Why?

Finishing early leaves more time for other activities.

### Python Implementation

```python
def activity_selection(activities):

    # Sort activities by finishing time
    activities.sort(key=lambda x: x[1])

    selected = []
    last_finish = float('-inf')

    for start, finish in activities:

        if start >= last_finish:

            selected.append((start, finish))
            last_finish = finish

    return selected


activities = [
    (1, 3),
    (2, 5),
    (4, 7),
    (6, 9),
    (8, 10)
]

print(activity_selection(activities))
```

Output:

```text
[(1, 3), (4, 7), (8, 10)]
```

### Explanation

First, sort by finishing time.

Then:

| Activity | Start | Finish | Selected? |
|---|---:|---:|---|
| A | 1 | 3 | Yes |
| B | 2 | 5 | No |
| C | 4 | 7 | Yes |
| D | 6 | 9 | No |
| E | 8 | 10 | Yes |

Why is activity B rejected?

Because it starts at 2, but the previously selected activity finishes at 3.

Therefore, they overlap.

### Complexity

- Sorting: O(n log n)
- Selection: O(n)
- Total Time: O(n log n)
- Auxiliary Space: O(n) for the selected output list, excluding sorting implementation details.

## Problem 2: Fractional Knapsack

**Problem:**

You are given items with different weights and values.

You have a bag with a limited capacity.

You can take an entire item or a fraction of it.

Find the maximum possible value.

Input:

```python
items = [
    (60, 10),
    (100, 20),
    (120, 30)
]

capacity = 50
```

Each tuple represents:

```text
(value, weight)
```

Expected Output:

```text
240.0
```

### Greedy Strategy

Calculate the value-to-weight ratio of each item.

Choose the item with the highest ratio first.

### Python Implementation

```python
def fractional_knapsack(items, capacity):

    # Sort by value-to-weight ratio
    items.sort(
        key=lambda item: item[0] / item[1],
        reverse=True
    )

    total_value = 0

    for value, weight in items:

        if capacity == 0:
            break

        if weight <= capacity:

            total_value += value
            capacity -= weight

        else:

            fraction = capacity / weight
            total_value += value * fraction

            capacity = 0

    return total_value


items = [
    (60, 10),
    (100, 20),
    (120, 30)
]

capacity = 50

print(fractional_knapsack(items, capacity))
```

Output:

```text
240.0
```

### Step-by-Step Explanation

Calculate the ratios:

| Item | Value | Weight | Ratio |
|---|---:|---:|---:|
| A | 60 | 10 | 6 |
| B | 100 | 20 | 5 |
| C | 120 | 30 | 4 |

Choose item A:

```text
Value = 60
Remaining capacity = 40
```

Choose item B:

```text
Value = 100
Remaining capacity = 20
```

Only 20 units of capacity remain, so take 20/30 of item C:

```text
Value = 120 × (20/30)
      = 80
```

Total:

```text
60 + 100 + 80 = 240
```

### Complexity

- Sorting: O(n log n)
- Iteration: O(n)
- Total Time: O(n log n)
- Auxiliary Space: Depends on sorting implementation; O(n) if a separate sorted copy is used.

**Important:** Fractional Knapsack supports this greedy strategy. The ordinary 0/1 Knapsack problem does not generally support the same greedy approach.

## Problem 3: Minimum Number of Coins

**Problem:**

Given coin denominations and an amount, find the minimum number of coins required.

Input:

```python
coins = [1, 5, 10, 25]
amount = 30
```

Expected Output:

```text
2
```

### Greedy Strategy

Always choose the largest coin that does not exceed the remaining amount.

### Python Implementation

```python
def min_coins(coins, amount):

    coins.sort(reverse=True)

    count = 0

    for coin in coins:

        if amount == 0:
            break

        number = amount // coin

        count += number
        amount %= coin

    if amount != 0:
        return -1

    return count


coins = [1, 5, 10, 25]
amount = 30

print(min_coins(coins, amount))
```

Output:

```text
2
```

Explanation:

```text
30 // 25 = 1
Remaining = 5

5 // 5 = 1
Remaining = 0
```

Total coins = 2.

**Important:** This greedy solution is not guaranteed to give the minimum number of coins for arbitrary denominations.

For example:

```python
coins = [1, 3, 4]
amount = 6
```

Greedy returns 3 coins:

```text
4 + 1 + 1
```

The optimal answer is 2:

```text
3 + 3
```

For arbitrary denominations, use Dynamic Programming to guarantee the minimum.

### Complexity

- Sorting: O(n log n)
- Iteration: O(n)
- Total Time: O(n log n)
- Auxiliary Space: O(1) excluding sorting details, if sorting is performed in place.

## Problem 4: Assign Cookies

**Problem:**

You have children with different greed factors and cookies with different sizes.

Each child can receive at most one cookie.

A child is satisfied if the cookie size is greater than or equal to their greed factor.

Find the maximum number of satisfied children.

Input:

```python
greed = [1, 2, 3]
cookies = [1, 1]
```

Expected Output:

```text
1
```

### Greedy Strategy

1. Sort the greed factors.
2. Sort the cookie sizes.
3. Give the smallest suitable cookie to the least greedy child.

### Python Implementation

```python
def find_content_children(greed, cookies):

    greed.sort()
    cookies.sort()

    child = 0
    cookie = 0

    while child < len(greed) and cookie < len(cookies):

        if cookies[cookie] >= greed[child]:

            child += 1

        cookie += 1

    return child


greed = [1, 2, 3]
cookies = [1, 1]

print(find_content_children(greed, cookies))
```

Output:

```text
1
```

### Complexity

- Sorting: O(n log n + m log m)
- Two-pointer traversal: O(n + m)
- Total Time: O(n log n + m log m)

Here, `n` is the number of children and `m` is the number of cookies.

## Problem 5: Jump Game

**Problem:**

You are given an array where each element represents the maximum number of steps you can jump forward from that position.

Determine whether you can reach the last index.

Input:

```python
arr = [2, 3, 1, 1, 4]
```

Expected Output:

```text
True
```

### Greedy Strategy

Keep track of the farthest index you can reach.

If the current index is beyond the farthest reachable index, return `False`.

### Python Implementation

```python
def can_jump(arr):

    farthest = 0

    for i in range(len(arr)):

        if i > farthest:
            return False

        farthest = max(farthest, i + arr[i])

        if farthest >= len(arr) - 1:
            return True

    return True


arr = [2, 3, 1, 1, 4]

print(can_jump(arr))
```

Output:

```text
True
```

### Explanation

```text
Index:  0  1  2  3  4
Array: [2, 3, 1, 1, 4]
```

At index 0:

```text
Farthest = 0 + 2 = 2
```

At index 1:

```text
Farthest = max(2, 1 + 3)
         = 4
```

We can reach the last index.

Therefore:

```text
True
```

### Complexity

- Time: O(n)
- Auxiliary Space: O(1)

# 6. Greedy vs Backtracking

Both techniques explore choices, but they approach decisions differently.

| Greedy | Backtracking |
|---|---|
| Makes the locally best choice | Explores multiple possible choices |
| Usually does not undo decisions | Reverses decisions when exploring another path |
| Often avoids exploring the full search space | May explore many possibilities |
| Requires a valid greedy-choice property | Can search for solutions systematically |
| Example: Activity Selection | Example: N-Queens |

### Example

Suppose you need to generate all subsets of:

```python
arr = [1, 2, 3]
```

Backtracking explores different combinations.

Greedy is not the natural technique because the task is to generate every possible subset, not choose one locally optimal solution.

# 7. Greedy Algorithm Template

A general greedy approach looks like this:

```python
def greedy_algorithm(items):

    # Step 1: Sort or arrange the choices
    items.sort()

    result = []

    # Step 2: Process each choice
    for item in items:

        # Step 3: Check whether the choice is valid
        if is_valid(item):

            # Step 4: Make the greedy choice
            result.append(item)

    return result
```

This is only a conceptual template. Some greedy algorithms use heaps, priority queues, two pointers, or other data structures instead of sorting.

# 8. How to Identify a Greedy Problem

Look for problem statements containing:

- Maximum number of activities
- Minimum number of operations
- Maximum profit
- Minimum resources
- Select the best available option
- Schedule tasks efficiently
- Reach the destination with minimum cost

However, these keywords alone do not prove that a greedy solution exists.

Ask yourself:

1. What is the locally best choice?
2. Why should this choice be safe?
3. Can making this choice prevent a better overall solution?
4. Can I prove that some optimal solution includes this choice?
5. Does the remaining problem have the same structure?

If you cannot justify the greedy choice, consider Dynamic Programming or another technique.

# 9. Common Mistakes in Greedy Algorithms

### Mistake 1: Assuming the Largest Value Is Always Best

Choosing the largest number at every step may not produce an optimal solution.

The correct greedy rule depends on the problem.

### Mistake 2: Not Sorting Correctly

Some problems require sorting by:

- Starting time
- Finishing time
- Value-to-weight ratio
- Cost
- Profit

Choosing the wrong sorting criteria can produce incorrect answers.

### Mistake 3: Confusing Fractional and 0/1 Knapsack

Fractional Knapsack allows taking part of an item.

0/1 Knapsack requires taking the whole item or leaving it.

The value-to-weight greedy strategy is optimal for Fractional Knapsack but not generally for 0/1 Knapsack.

### Mistake 4: Not Proving the Greedy Choice

A solution may work for sample inputs but fail on other cases.

Test edge cases and understand why the greedy choice is correct.

# 10. Time Complexity

Greedy algorithms do not have one fixed time complexity.

It depends on the problem and the operations performed.

| Operation | Time Complexity |
|---|---|
| Single traversal | O(n) |
| Sorting | O(n log n) |
| Two-pointer traversal | O(n) |
| Heap insertion/removal | O(log n) per operation |
| Sorting + traversal | Usually O(n log n) |

Examples:

| Problem | Time Complexity |
|---|---|
| Activity Selection | O(n log n) |
| Fractional Knapsack | O(n log n) |
| Coin Change (greedy) | O(n log n) with sorting |
| Assign Cookies | O(n log n + m log m) |
| Jump Game | O(n) |

# 14. Key Takeaways

1. Greedy algorithms make the best local choice at each step.
2. The goal is to achieve a globally optimal solution.
3. Greedy does not work for every optimization problem.
4. Sorting is frequently used to arrange choices.
5. Activity Selection is a classic greedy problem.
6. Fractional Knapsack can be solved optimally using greedy.
7. Ordinary 0/1 Knapsack generally requires Dynamic Programming for an optimal solution.
8. Jump Game is a classic example of maintaining the farthest reachable position.
9. Always justify why a greedy choice is safe.

## The Most Important Concept

Greedy is not simply choosing the biggest or smallest number.

It is about identifying a choice that is locally optimal and proving that making this choice will not prevent an optimal overall solution.

**Choose the best valid option → Update the problem → Repeat.**
