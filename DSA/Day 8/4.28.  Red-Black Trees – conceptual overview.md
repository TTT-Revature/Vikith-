# Red-Black Trees – Conceptual Overview

## 1. Introduction to Red-Black Trees

A **Red-Black Tree** is a self-balancing Binary Search Tree (BST) in which every node is assigned a color: either RED or BLACK.

The colors help maintain balance and prevent the tree from becoming highly skewed.

Like an AVL Tree, a Red-Black Tree automatically maintains its structure during insertion and deletion.

However, instead of maintaining a strict height balance using balance factors, Red-Black Trees use a set of coloring rules.

### Why Do We Need Red-Black Trees?

Consider inserting sorted values into a normal BST:

```python
values = [10, 20, 30, 40, 50]
```

The resulting tree becomes:

```text
10
  \
   20
     \
      30
        \
         40
           \
            50
```

This is a skewed tree.

Searching may take O(n) time.

A Red-Black Tree uses rotations and recoloring to maintain an approximately balanced structure.

Example:

```text
             20(B)
            /     \
         10(R)    40(R)
                  /   \
               30(B)  50(B)
```

Here:

- B represents BLACK.
- R represents RED.

The tree maintains its balancing properties.

**Important:** Red-Black Trees guarantee O(log n) worst-case time complexity for searching, insertion and deletion.

---

## 2. Properties of Red-Black Trees

A Red-Black Tree follows five important properties.

### Property 1: Every Node Is Either Red or Black

Each node must have one of two colors:

- RED
- BLACK

```text
       20(B)
       /
    10(R)
```

### Property 2: The Root Must Always Be Black

The root node of a Red-Black Tree must always be BLACK.

```text
       20(B)
       /
    10(R)
```

A red root is not allowed.

### Property 3: Every Leaf (NIL) Is Black

Every missing child is represented conceptually by a NIL node.

All NIL nodes must be BLACK.

Example:

```text
          20(B)
         /     \
      10(R)    NIL(B)
      /  \
   NIL(B) NIL(B)
```

**Important:** NIL leaves are conceptual external nodes. They are different from ordinary data-containing leaf nodes.

### Property 4: A Red Node Cannot Have a Red Child

A RED node cannot have another RED node as its child.

This means two consecutive RED nodes are not allowed on any path.

Invalid example:

```text
       20(R)
       /
     10(R)
```

Valid example:

```text
       20(B)
       /
     10(R)
```

### Property 5: Every Path Must Have the Same Black Height

Every path from a node to its descendant NIL leaves must contain the same number of BLACK nodes.

This is called the **Black Height Property**.

Example:

```text
              20(B)
             /     \
          10(B)    30(B)
          /  \      /  \
        NIL NIL   NIL  NIL
```

Every root-to-NIL path contains the same number of black nodes.

This property helps maintain balance.

---

## 3. Understanding Black Height

Black Height is the number of BLACK nodes on a path from a particular node to a descendant NIL leaf.

The exact counting convention varies between textbooks.

For this explanation, we count BLACK nodes excluding the starting node and including the NIL leaf.

Example:

```text
              20(B)
             /     \
          10(R)    30(B)
          /  \      /  \
        NIL NIL   NIL  NIL
```

Left path:

```text
20(B) → 10(R) → NIL(B)
```

Right path:

```text
20(B) → 30(B) → NIL(B)
```

Counting black nodes after the starting node:

- Left path = 1
- Right path = 2

Therefore, this tree is NOT a valid Red-Black Tree.

A valid Red-Black Tree must maintain equal black height on all paths.

---

## 4. Understanding Recoloring

Recoloring means changing a node's color from RED to BLACK or BLACK to RED.

It is used to restore Red-Black Tree properties after insertion or deletion.

Example:

Before recoloring:

```text
              20(B)
             /     \
          10(R)    30(R)
```

Suppose we insert 5 as the left child of 10.

Before fixing:

```text
              20(B)
             /     \
          10(R)    30(R)
          /
        5(R)
```

There are two consecutive RED nodes:

10(R) and 5(R).

This violates the Red-Black Tree property.

Since the parent (10) and uncle (30) are both RED, we can recolor:

- Parent 10 becomes BLACK.
- Uncle 30 becomes BLACK.
- Grandparent 20 becomes RED.

Then the root is recolored BLACK.

After recoloring:

```text
              20(B)
             /     \
          10(B)    30(B)
          /
        5(R)
```

Now the tree satisfies the Red-Black properties.

---

## 5. Understanding Rotations

Rotations are used to rearrange nodes without violating the Binary Search Tree ordering property.

There are two basic rotations:

1. Left Rotation
2. Right Rotation

### 5.1 Left Rotation

A left rotation moves a node down to the left and promotes its right child.

Before rotation:

```text
       10
         \
          20
            \
             30
```

After left rotation around 10:

```text
          20
         /  \
        10   30
```

### 5.2 Right Rotation

A right rotation moves a node down to the right and promotes its left child.

Before rotation:

```text
          30
         /
        20
       /
      10
```

After right rotation around 30:

```text
          20
         /  \
        10   30
```

**Important:** Unlike AVL Trees, Red-Black Trees do not use balance factors to decide when to rotate. They use coloring properties and the positions of the parent, uncle and grandparent.

---

## 6. Insertion in a Red-Black Tree – Concept

Insertion in a Red-Black Tree happens in two major stages.

1. Insert the new node using normal BST insertion.
2. Fix any violated Red-Black properties using recoloring and rotations.

### Important Rule

A newly inserted node is initially colored RED.

Why?

Because inserting a RED node does not immediately increase the black height of any path.

However, it may create two consecutive RED nodes.

### Example

Insert:

```python
[10, 20, 30]
```

Step 1: Insert 10.

```text
10(B)
```

The root must be BLACK.

Step 2: Insert 20.

```text
10(B)
   \
   20(R)
```

Step 3: Insert 30.

```text
10(B)
   \
   20(R)
      \
      30(R)
```

Now 20 and 30 are consecutive RED nodes.

This violates the Red-Black property.

A left rotation and recoloring are required.

Final tree:

```text
          20(B)
         /     \
      10(R)    30(R)
```

The tree is balanced and satisfies the Red-Black properties.

## 7. Deletion in a Red-Black Tree – Concept

Deletion is more complicated than insertion.

A node is first removed using the normal BST deletion process.

Then the Red-Black properties are checked.

### Important Cases

**Case 1: Deleting a RED node**

Deleting a RED node generally does not affect black height.

No additional balancing is usually required.

**Case 2: Deleting a BLACK node**

Deleting a BLACK node can reduce the black height of a path.

This may create a violation that needs to be fixed.

**Case 3: Node with Two Children**

The node is replaced using its inorder successor or predecessor, similar to normal BST deletion.

The color of the physically removed node determines whether additional balancing is required.

### How Is the Tree Fixed?

Red-Black Tree deletion uses:

- Recoloring.
- Left rotation.
- Right rotation.
- Different cases based on the sibling's color and the sibling's children.

The main objective is to restore equal black height and all other Red-Black properties.

## 8. Red-Black Tree vs AVL Tree

Both AVL Trees and Red-Black Trees are self-balancing BSTs.

However, their balancing strategies are different.

| Feature | AVL Tree | Red-Black Tree |
|---|---|---|
| Balancing Method | Balance Factor | Node Coloring |
| Node Information | Height or balance factor | Red or Black color |
| Balance | More strictly balanced | Less strictly balanced |
| Search | O(log n) | O(log n) |
| Insertion | O(log n) | O(log n) |
| Deletion | O(log n) | O(log n) |
| Rotations | Single and double rotations | Left and right rotations |
| Updates | Can require multiple rebalancing steps | Generally fewer rotations |
| Searching | Often faster in practice due to tighter balance | May have slightly greater height |

### When Should We Use AVL Trees?

AVL Trees are useful when:

- Searching happens frequently.
- Insertions and deletions are relatively less frequent.
- A more strictly balanced tree is beneficial.

### When Should We Use Red-Black Trees?

Red-Black Trees are useful when:

- Insertions and deletions happen frequently.
- A balance between searching and updating is important.
- A general-purpose balanced search tree is needed.

## 9. Time and Space Complexity

Let n represent the number of nodes.

| Operation | Time Complexity |
|---|---|
| Search | O(log n) |
| Insertion | O(log n) |
| Deletion | O(log n) |
| Find Minimum | O(log n) |
| Find Maximum | O(log n) |
| Left Rotation | O(1) |
| Right Rotation | O(1) |
| Traversal | O(n) |

### Space Complexity

- Storing the tree: O(n).
- Recursive search: O(log n) auxiliary stack space.
- Iterative search: O(1) auxiliary space.

A Red-Black Tree maintains logarithmic height, which is why its main operations are efficient.

---

## 10. Advantages of Red-Black Trees

1. Maintains balance automatically.
2. Guarantees O(log n) worst-case search, insertion and deletion.
3. Supports frequent insertions and deletions efficiently.
4. Does not require strict height balancing.
5. Useful for implementing ordered maps and sets.

## 11. Disadvantages of Red-Black Trees

1. More complex than a normal BST.
2. Insertion and deletion require recoloring and rotations.
3. Requires additional memory to store node colors.
4. Understanding deletion cases can be difficult.

---

## 12. Applications of Red-Black Trees

Red-Black Trees are used in several programming environments and systems.

### 1. C++ STL

The `std::map` and `std::set` implementations commonly use Red-Black Trees.

They maintain sorted elements and provide logarithmic search, insertion and deletion.

### 2. Java

Java's `TreeMap` and `TreeSet` use Red-Black Tree-based implementations.

### 3. Operating Systems

Red-Black Trees are used in certain kernel data structures, including Linux kernel scheduling-related structures.

### 4. Memory Management

They can be used to organize and search ordered memory-related information.

### 5. Database and Indexing Systems

Balanced search trees are useful in maintaining ordered data, although database indexes commonly use B-Trees or B+ Trees instead.

## 13. Important Interview Questions

### Basic Questions

**Q1. What is a Red-Black Tree?**

A Red-Black Tree is a self-balancing Binary Search Tree in which every node is colored either RED or BLACK.

**Q2. Why are Red-Black Trees used?**

They prevent a BST from becoming highly skewed and guarantee O(log n) worst-case operations.

**Q3. What are the five properties of a Red-Black Tree?**

1. Every node is RED or BLACK.
2. Root is BLACK.
3. NIL leaves are BLACK.
4. A RED node cannot have a RED child.
5. Every path from a node to its descendant NIL leaves has the same black height.

**Q4. What is recoloring?**

Changing the colors of nodes to restore Red-Black Tree properties.

**Q5. What is a rotation?**

A structural operation that rearranges nodes while preserving BST ordering.

### Intermediate Questions

**Q6. Why is a newly inserted node RED?**

Because inserting a RED node does not immediately change the black height of existing paths.

**Q7. What happens if a RED node has a RED parent?**

The Red-Black property is violated, and recoloring or rotations are required.

**Q8. What happens when a BLACK node is deleted?**

Black height may be violated, so additional balancing may be required.

**Q9. What is the maximum time complexity of searching?**

O(log n).

**Q10. What is the difference between AVL and Red-Black Trees?**

AVL Trees maintain stricter height balance using balance factors, while Red-Black Trees use coloring rules to maintain approximate balance.
