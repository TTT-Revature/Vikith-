# Caching – Practical Use Cases in Python

## 1. Introduction to Caching

Caching is a technique used to store frequently accessed data temporarily so that it can be retrieved faster when needed again.

Instead of performing the same expensive operation repeatedly, we save its result and reuse it.

Caching helps improve:

- Application performance.
- Response time.
- CPU efficiency.
- Database performance.
- Network efficiency.
- Overall user experience.

### Real-World Example

Imagine you visit a website and open your profile.

The application retrieves your profile information from the database.

When you visit the same profile again, the application can retrieve the previously stored information from a cache instead of querying the database again.

This reduces repeated database operations.

## 2. Why Do We Need Caching?

Consider a function that performs an expensive calculation.

```python
import time

def expensive_function():
    time.sleep(3)
    return "Data Retrieved"

print(expensive_function())
print(expensive_function())
```

The function takes approximately 3 seconds each time it executes.

Total execution time is approximately 6 seconds.

But what if the result could be reused?

Instead of calculating the result again, we can store it.

This is where caching becomes useful.

### Without Caching

```text
First Request
     |
     v
Perform Expensive Operation
     |
     v
Return Result

Second Request
     |
     v
Perform Expensive Operation Again
     |
     v
Return Result
```

### With Caching

```text
First Request
     |
     v
Check Cache
     |
     v
Cache Miss
     |
     v
Perform Expensive Operation
     |
     v
Store Result in Cache
     |
     v
Return Result

Second Request
     |
     v
Check Cache
     |
     v
Cache Hit
     |
     v
Return Stored Result
```

The second request does not need to repeat the expensive operation.

## 3. Important Caching Terminology

### 3.1 Cache

A cache is a temporary storage location used to keep frequently accessed data.

### 3.2 Cache Hit

A cache hit occurs when the requested data is already available in the cache.

Example:

```text
Requested Data: User Profile

Cache: User Profile Found

Result: Cache Hit
```

### 3.3 Cache Miss

A cache miss occurs when the requested data is not available in the cache.

The application must retrieve it from the original data source.

Example:

```text
Requested Data: User Profile

Cache: User Profile Not Found

Result: Cache Miss

Action: Retrieve Data from Database
```

### 3.4 Cache Hit Ratio

The cache hit ratio measures how often requested data is successfully found in the cache.

Formula:

```text
Cache Hit Ratio = Cache Hits / Total Requests
```

For percentage:

```text
Hit Ratio = (Cache Hits / Total Requests) * 100
```

Example:

```text
Total Requests = 100

Cache Hits = 80

Cache Hit Ratio = (80 / 100) * 100

                 = 80%
```

A higher hit ratio generally indicates that the cache is serving more requests.

### 3.5 Cache Miss Ratio

The cache miss ratio measures how often requested data is not available in the cache.

Formula:

```text
Cache Miss Ratio = Cache Misses / Total Requests
```

## 4. How Does Caching Work?

Caching generally follows these steps:

1. The application receives a request.
2. It checks whether the requested data exists in the cache.
3. If the data exists, it returns the cached result.
4. If the data does not exist, it retrieves the data from the original source.
5. It stores the retrieved result in the cache.
6. It returns the result to the user.

### Example: Student Information

Suppose an application needs student information.

```python
cache = {}

def get_student(student_id):

    if student_id in cache:

        print("Cache Hit")
        return cache[student_id]

    print("Cache Miss")

    # Simulating database retrieval
    student = {
        "id": student_id,
        "name": "Rahul",
        "course": "MCA"
    }

    cache[student_id] = student

    return student


print(get_student(101))
print(get_student(101))
```

Output:

```text
Cache Miss
{'id': 101, 'name': 'Rahul', 'course': 'MCA'}

Cache Hit
{'id': 101, 'name': 'Rahul', 'course': 'MCA'}
```

### Explanation

First request:

- Student 101 is not available in the cache.
- The application retrieves the student information.
- It stores the result in the dictionary.

Second request:

- Student 101 is already available.
- The application returns the cached information.
- No repeated database retrieval is needed.

## 5. Practical Use Cases of Caching

Caching is used in many real-world applications.

### 5.1 Database Caching

Applications frequently retrieve data from databases.

Repeated database queries can increase response time and database load.

Caching frequently requested database results can reduce repeated queries.

Example:

An e-commerce application displays product information.

Instead of retrieving the same product details repeatedly from MySQL, the application can temporarily store popular product information in a cache.

Benefits:

- Fewer database queries.
- Faster response times.
- Reduced database load.

### 5.2 API Response Caching

An API may receive thousands of requests for the same information.

If the response does not change frequently, it can be cached.

Example:

A weather application requests weather information for a particular city.

Instead of calling the weather API every time, the application can reuse a cached response for a limited period.

Benefits:

- Faster API responses.
- Reduced external API calls.
- Lower API usage costs.

### 5.3 Website Caching

Websites cache resources such as:

- Images.
- CSS files.
- JavaScript files.
- HTML pages.

When users revisit a website, their browsers may reuse cached resources instead of downloading everything again.

Benefits:

- Faster page loading.
- Reduced bandwidth usage.
- Better user experience.

### 5.4 Machine Learning Caching

Machine learning applications sometimes perform expensive computations.

For example, a recommendation system may repeatedly calculate recommendations for the same user.

Instead of calculating them every time, the results can be cached for a limited period.

Benefits:

- Reduced computation.
- Faster recommendations.
- Lower server workload.

### 5.5 Authentication and Session Caching

Applications frequently verify authentication information.

Some session or token-related information can be stored in a fast cache such as Redis.

Benefits:

- Faster session lookups.
- Reduced database access.
- Better performance under high traffic.

Security note: Sensitive authentication data must be protected with appropriate expiration, access controls, and storage policies.

### 5.6 DNS Caching

DNS translates domain names into IP addresses.

For example:

```text
google.com -> IP Address
```

Instead of repeatedly querying DNS servers, the resolved information can be cached for a specified time.

Benefits:

- Faster domain resolution.
- Reduced DNS queries.
- Lower network overhead.

## 6. Types of Caching

### 6.1 In-Memory Caching

Data is stored directly in the application's memory.

Python dictionaries can be used for simple in-memory caching.

Example:

```python
cache = {}

def get_data(key):

    if key in cache:
        return cache[key]

    value = key * 10

    cache[key] = value

    return value


print(get_data(5))
print(get_data(5))
```

Output:

```text
50
50
```

Advantages:

- Very fast access.
- Simple implementation.
- No external service required.

Disadvantages:

- Data may disappear when the application stops.
- Memory is limited.
- Separate application instances may have separate caches.

### 6.2 Distributed Caching

Distributed caching stores data in a cache service that can be accessed by multiple application instances.

Popular technologies include:

- Redis
- Memcached

Example architecture:

```text
             User
               |
               v
         Application
               |
               v
          Redis Cache
           /       \
       Hit           Miss
        |              |
        v              v
      Return         Database
      Result            |
                        v
                   Store in Redis
                        |
                        v
                    Return Data
```

Advantages:

- Shared cache across multiple application instances.
- Fast access to frequently requested data.
- Reduces database load.

Disadvantages:

- Requires additional infrastructure.
- Network communication is involved.
- Cache consistency must be managed.

### 6.3 Browser Caching

Browsers store resources locally.

For example:

- Images.
- CSS.
- JavaScript.
- Other static resources.

HTTP caching headers such as `Cache-Control` and `ETag` help control how browsers reuse cached resources.

### 6.4 CPU Caching

Processors use small, fast memory locations called CPU caches.

Common levels include:

- L1 Cache
- L2 Cache
- L3 Cache

They store frequently accessed instructions and data to reduce the time required to access main memory.

## 7. Cache Eviction Strategies

A cache has limited storage capacity.

When it becomes full, some existing entries may need to be removed to make room for new entries.

This is called cache eviction.

Important eviction strategies include:

### 7.1 LRU – Least Recently Used

LRU removes the item that has not been accessed for the longest time.

Example:

Cache capacity = 3

Insert:

```text
10, 20, 30
```

Cache:

```text
[10, 20, 30]
```

Now access 10.

The recent usage order becomes:

```text
[20, 30, 10]
```

Insert 40.

The least recently used item is 20.

It is removed.

Final cache:

```text
[30, 10, 40]
```

**Python Implementation Using OrderedDict:**

```python
from collections import OrderedDict

class LRUCache:

    def __init__(self, capacity):
        self.capacity = capacity
        self.cache = OrderedDict()

    def get(self, key):

        if key not in self.cache:
            return -1

        self.cache.move_to_end(key)

        return self.cache[key]

    def put(self, key, value):

        if key in self.cache:
            self.cache.move_to_end(key)

        self.cache[key] = value

        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)


cache = LRUCache(2)

cache.put(1, 100)
cache.put(2, 200)

print(cache.get(1))

cache.put(3, 300)

print(cache.get(2))
print(cache.get(3))
```

Output:

```text
100
-1
300
```

Explanation:

- Key 1 is accessed.
- Key 1 becomes recently used.
- Inserting key 3 exceeds capacity.
- Key 2 is removed because it is least recently used.

### 7.2 FIFO – First In, First Out

FIFO removes the element that was inserted first.

Example:

```text
Cache Capacity = 3

Insert: 10, 20, 30

Cache: [10, 20, 30]

Insert: 40

Remove: 10

Cache: [20, 30, 40]
```

FIFO does not consider how recently an item was accessed.

### 7.3 LFU – Least Frequently Used

LFU removes the element that has been accessed the fewest times.

Example:

```text
Key 10 -> Accessed 5 times
Key 20 -> Accessed 2 times
Key 30 -> Accessed 1 time
```

If an item must be removed, key 30 is the LFU candidate.

If multiple keys have the same lowest frequency, an additional tie-breaking rule is required.

### Comparison

| Strategy | Removal Rule |
|---|---|
| LRU | Least recently accessed |
| FIFO | Earliest inserted |
| LFU | Least frequently accessed |

## 8. Time Complexity of Caching

The complexity depends on the cache implementation.

For a dictionary-based cache:

| Operation | Average Time |
|---|---|
| Insert | O(1) |
| Search | O(1) |
| Update | O(1) |
| Delete | O(1) |

For an LRU cache implemented using a hash map and doubly linked list:

| Operation | Time |
|---|---|
| Get | O(1) |
| Put | O(1) |
| Eviction | O(1) |

The LRU implementation above uses Python's `OrderedDict`, which provides efficient operations for these tasks.

## 9. Python Caching with functools.lru_cache

Python provides a built-in caching decorator called `lru_cache`.

It is available in the `functools` module.

A decorator allows us to add caching behavior to a function without manually maintaining a dictionary.

### Example: Fibonacci Without Caching

```python
def fibonacci(n):

    if n <= 1:
        return n

    return fibonacci(n - 1) + fibonacci(n - 2)


print(fibonacci(10))
```

Output:

```text
55
```

This function repeatedly calculates the same Fibonacci values.

Its time complexity is exponential, approximately O(2^n).

### Example: Fibonacci With Caching

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fibonacci(n):

    if n <= 1:
        return n

    return fibonacci(n - 1) + fibonacci(n - 2)


print(fibonacci(10))

print(fibonacci.cache_info())
```

Output:

```text
55
CacheInfo(hits=8, misses=11, maxsize=None, currsize=11)
```

The exact cache statistics can depend on the calls made.

### Explanation

- `@lru_cache` enables caching.
- `maxsize=None` allows unlimited cached entries.
- Previously calculated results are reused.
- Repeated calculations are avoided.

Time Complexity: O(n) for calculating Fibonacci from 0 to n with memoization.

Space Complexity: O(n).

### Clearing the Cache

```python
fibonacci.cache_clear()
```

This removes all cached results.

## 10. Caching vs Memoization

Caching and Memoization are closely related but are not exactly the same.

### Caching

Caching is a general technique for storing previously retrieved or calculated data for reuse.

It can be used for:

- API responses.
- Database queries.
- Images.
- Web pages.
- Function results.

### Memoization

Memoization is a specific form of caching used to store the results of function calls.

It is especially useful in recursive and dynamic programming problems.

### Difference

| Feature | Caching | Memoization |
|---|---|---|
| Meaning | General data reuse technique | Caching function results |
| Scope | Broad | More specific |
| Common Usage | APIs, databases, websites | Recursion, dynamic programming |
| Example | Redis | `functools.lru_cache` |

## 11. Cache Expiration and TTL

TTL stands for Time To Live.

It determines how long a cached item remains valid.

After the TTL expires, the cached item should no longer be served as valid data.

### Example

Suppose a weather application caches weather information for 5 minutes.

```text
10:00 AM -> Weather data retrieved
10:00 AM -> Stored in cache

10:02 AM -> Cached data reused

10:05 AM -> Cache expires

10:06 AM -> Fresh weather data retrieved
```

TTL is useful when data changes over time.

### Python Example

```python
import time

cache = {}

def get_data(key):

    current_time = time.time()

    if key in cache:

        value, expiry = cache[key]

        if current_time < expiry:
            print("Cache Hit")
            return value

        del cache[key]

    print("Cache Miss")

    value = key * 10

    ttl = 5

    cache[key] = (value, current_time + ttl)

    return value


print(get_data(5))

time.sleep(2)

print(get_data(5))
```

Output:

```text
Cache Miss
50
Cache Hit
50
```

Here, the cached result remains valid for five seconds.

## 12. Cache Invalidation

Cache invalidation means removing or updating cached data when the original data changes.

This is important because cached data can become outdated.

### Example

Suppose a product has the following price:

```text
Database Price = ₹500
Cache Price = ₹500
```

The product price changes:

```text
Database Price = ₹600
Cache Price = ₹500
```

Now the cache contains outdated information.

Possible solutions:

1. Delete the cached product entry.
2. Update the cached value.
3. Use a TTL so the entry eventually expires.
4. Use event-based invalidation when the original data changes.

### Why Is Cache Invalidation Difficult?

Because an application may have multiple copies of the same data in different caches.

Keeping all those copies consistent is challenging.

## 13. Practical Example: Product Caching

Imagine an e-commerce application.

A user requests product information.

Instead of querying the database for every request, we can cache the product details.

```python
products = {
    101: {
        "name": "Laptop",
        "price": 50000
    },
    102: {
        "name": "Mobile",
        "price": 20000
    }
}

cache = {}

def get_product(product_id):

    if product_id in cache:

        print("Cache Hit")
        return cache[product_id]

    print("Cache Miss")

    product = products.get(product_id)

    if product is not None:
        cache[product_id] = product

    return product


print(get_product(101))
print(get_product(101))
```

Output:

```text
Cache Miss
{'name': 'Laptop', 'price': 50000}

Cache Hit
{'name': 'Laptop', 'price': 50000}
```

This example simulates database retrieval using a dictionary.

In a real application, the original product data could come from MySQL or another database, while Redis could store cached product information.

## 14. Advantages and Disadvantages of Caching

### Advantages

1. Faster data retrieval.
2. Reduced database load.
3. Reduced repeated computation.
4. Improved application performance.
5. Reduced network requests.
6. Better user experience.
7. Lower infrastructure costs in suitable workloads.

### Disadvantages

1. Requires additional memory.
2. Cached data can become outdated.
3. Cache invalidation is difficult.
4. Cache misses still require the original operation.
5. Distributed caches introduce network and infrastructure complexity.
6. Poor cache design can create performance problems.

## 18. Final Summary

Caching is one of the most important performance optimization techniques in software development.

Instead of repeatedly retrieving or calculating the same information, an application stores frequently needed results and reuses them.

**Most Important Interview Concept:**

A Hash Map provides the foundation for many simple caching implementations because it offers O(1) average lookup and insertion.

For advanced caching systems, techniques such as LRU, LFU, TTL, and distributed caching are used to manage memory and maintain performance.
