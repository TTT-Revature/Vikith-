# AVL Trees – Conceptual Understanding

## 1. Introduction to AVL Trees

An **AVL Tree (Adelson-Velsky and Landis Tree)** is a self-balancing Binary Search Tree (BST).

It follows all the rules of a normal BST, but it automatically maintains its balance after insertion and deletion.

In a normal BST, inserting sorted values can create a skewed tree, which makes searching inefficient.

AVL Trees solve this problem by performing rotations whenever the tree becomes unbalanced.

### Why Do We Need AVL Trees?

Consider inserting the following values into a normal BST:

```python
values = [10, 20, 30, 40, 50]
```

The resulting tree:

```text
10
  \
   20
     \
      30
        \
         40
           \
            50
```

This is a right-skewed tree.

Searching for 50 may require visiting every node.

Time Complexity = O(n)

### How Does an AVL Tree Solve This?

An AVL Tree automatically rearranges nodes to maintain balance.

For the same values:

```text
          20
         /  \
        10   40
            /  \
           30   50
```

Now the tree is balanced.

Searching takes O(log n) time.

**Important:** AVL Trees maintain a height-balanced structure, which ensures efficient searching, insertion and deletion.

---

## 2. Properties of AVL Trees

An AVL Tree follows these important properties:

1. It is a Binary Search Tree.
2. Every node can have at most two children.
3. The height difference between the left and right subtrees of every node must be at most 1.
4. It uses rotations to restore balance.
5. Search, insertion and deletion take O(log n) time.

### Example of a Balanced AVL Tree

```text
          30
         /  \
        20   40
       /       \
      10        50
```

This tree satisfies the AVL balance condition.

### Example of an Unbalanced Tree

```text
          30
         /
        20
       /
      10
```

The root node has a left subtree significantly taller than its right subtree.

A rotation is needed to restore balance.

---

## 3. Understanding Balance Factor

The **Balance Factor (BF)** determines whether a node is balanced or unbalanced.

It is calculated using:

```text
Balance Factor = Height of Left Subtree - Height of Right Subtree
```

Mathematically:

```text
BF = Height(Left) - Height(Right)
```

### Possible Balance Factor Values

| Balance Factor | Meaning |
|---|---|
| 0 | Both subtrees have equal height |
| +1 | Left subtree is one level taller |
| -1 | Right subtree is one level taller |
| +2 | Left-heavy and unbalanced |
| -2 | Right-heavy and unbalanced |

For an AVL Tree, every node must have a balance factor of:

```text
-1, 0, +1
```

### Example 1: Balance Factor = 0

```text
          30
         /  \
        20   40
```

Left height = 0

Right height = 0

```text
BF = 0 - 0 = 0
```

The node is balanced.

### Example 2: Balance Factor = +1

```text
          30
         /
        20
```

Left height = 0

Right height = -1 (empty subtree)

```text
BF = 0 - (-1) = +1
```

The node is balanced.

### Example 3: Balance Factor = +2

```text
          30
         /
        20
       /
      10
```

Left height = 1

Right height = -1

```text
BF = 1 - (-1) = +2
```

The node is unbalanced.

A rotation is required.

---

## 4. AVL Tree Rotations

Rotations are operations used to restore balance in an AVL Tree.

There are four types of rotations:

1. LL Rotation (Left-Left)
2. RR Rotation (Right-Right)
3. LR Rotation (Left-Right)
4. RL Rotation (Right-Left)

Understanding these four rotations is the most important part of AVL Trees.

---

## 5. LL Rotation – Left-Left Case

This case occurs when a node becomes unbalanced because a new node is inserted into the left subtree of its left child.

### Example

Insert:

```python
[30, 20, 10]
```

Before rotation:

```text
          30
         /
        20
       /
      10
```

The root node 30 becomes left-heavy.

Balance Factor of 30 = +2.

### Solution: Right Rotation

Perform a right rotation around node 30.

After rotation:

```text
          20
         /  \
        10   30
```

Now the tree is balanced.

**Remember:**

LL Case → Right Rotation.

---

## 6. RR Rotation – Right-Right Case

This case occurs when a node becomes unbalanced because a new node is inserted into the right subtree of its right child.

### Example

Insert:

```python
[10, 20, 30]
```

Before rotation:

```text
    10
      \
       20
         \
          30
```

The root node 10 becomes right-heavy.

Balance Factor of 10 = -2.

### Solution: Left Rotation

Perform a left rotation around node 10.

After rotation:

```text
          20
         /  \
        10   30
```

Now the tree is balanced.

**Remember:**

RR Case → Left Rotation.

---

## 7. LR Rotation – Left-Right Case

This case occurs when a node becomes unbalanced because a new node is inserted into the right subtree of its left child.

### Example

Insert:

```python
[30, 10, 20]
```

Before rotation:

```text
          30
         /
        10
          \
           20
```

The root node 30 becomes unbalanced.

### Solution: Two Rotations

Step 1: Perform a left rotation on node 10.

```text
          30
         /
        20
       /
      10
```

Step 2: Perform a right rotation on node 30.

Final Tree:

```text
          20
         /  \
        10   30
```

Now the tree is balanced.

**Remember:**

LR Case → Left Rotation + Right Rotation.

---

## 8. RL Rotation – Right-Left Case

This case occurs when a node becomes unbalanced because a new node is inserted into the left subtree of its right child.

### Example

Insert:

```python
[10, 30, 20]
```

Before rotation:

```text
    10
      \
       30
      /
     20
```

The root node 10 becomes unbalanced.

### Solution: Two Rotations

Step 1: Perform a right rotation on node 30.

```text
    10
      \
       20
         \
          30
```

Step 2: Perform a left rotation on node 10.

Final Tree:

```text
          20
         /  \
        10   30
```

Now the tree is balanced.

**Remember:**

RL Case → Right Rotation + Left Rotation.

---

## 9. Summary of AVL Rotations

| Case | Insertion Direction | Rotation |
|---|---|---|
| LL | Left of Left | Right Rotation |
| RR | Right of Right | Left Rotation |
| LR | Right of Left | Left + Right |
| RL | Left of Right | Right + Left |

### Easy Way to Remember

- LL → Rotate Right.
- RR → Rotate Left.
- LR → Rotate Left, then Right.
- RL → Rotate Right, then Left.

## 10. Height of an AVL Tree

Height is an important factor in determining the performance of an AVL Tree.

An AVL Tree maintains its height close to logarithmic growth.

For an AVL Tree containing n nodes:

```text
Height = O(log n)
```

This ensures that searching, insertion and deletion remain efficient.

### Why Is Height Important?

Consider:

Balanced Tree:

```text
          40
         /  \
        20   60
       / \   / \
      10 30 50 70
```

Height = 2

Skewed Tree:

```text
10
  \
   20
     \
      30
        \
         40
```

Height = 3

As the number of nodes increases, a skewed tree can grow to height O(n), whereas an AVL Tree maintains O(log n) height.

## 11. AVL Tree vs Binary Search Tree

| Feature | Normal BST | AVL Tree |
|---|---|---|
| Structure | Binary Search Tree | Self-balancing BST |
| Balance | Not guaranteed | Maintained automatically |
| Height | Can be O(n) | O(log n) |
| Searching | Average O(log n), worst O(n) | O(log n) worst case |
| Insertion | Average O(log n), worst O(n) | O(log n) worst case |
| Deletion | Average O(log n), worst O(n) | O(log n) worst case |
| Rotations | Not required | Required when unbalanced |
| Implementation | Simpler | More complex |

---

## 12. Advantages of AVL Trees

1. Maintains balance automatically.
2. Guarantees O(log n) search complexity.
3. Prevents the tree from becoming skewed.
4. Provides efficient searching for large datasets.
5. Useful when search operations are frequent.

## 13. Disadvantages of AVL Trees

1. More complicated to implement than normal BSTs.
2. Rotations add implementation overhead.
3. Insertion and deletion require balance-factor updates.
4. Maintaining balance can make updates more expensive than in some other balanced trees.

---

## 14. Applications of AVL Trees

AVL Trees are useful in:

1. Database indexing and in-memory search structures.
2. Memory management systems.
3. Dictionary and lookup implementations.
4. Applications requiring frequent searching.
5. Maintaining dynamically changing sorted data.

---

## 15. Time and Space Complexity

| Operation | Time Complexity |
|---|---|
| Search | O(log n) |
| Insertion | O(log n) |
| Deletion | O(log n) |
| Find Minimum | O(log n) |
| Find Maximum | O(log n) |
| Single Rotation | O(1) |
| Traversal | O(n) |

### Space Complexity

- Recursive operations: O(log n) auxiliary stack space.
- Iterative search: O(1) auxiliary space.
- Storing the AVL Tree: O(n).

## 16. Conceptual Interview Questions

**Q1. What is an AVL Tree?**

An AVL Tree is a self-balancing Binary Search Tree that maintains a height difference of at most 1 between the left and right subtrees of every node.

**Q2. Why do we need AVL Trees?**

To prevent a normal BST from becoming skewed and to maintain efficient O(log n) operations.

**Q3. What is a Balance Factor?**

The difference between the heights of the left and right subtrees of a node.

**Q4. What are the valid balance factors in an AVL Tree?**

-1, 0 and +1.

**Q5. What happens when the balance factor becomes +2 or -2?**

The node becomes unbalanced, and a suitable rotation is required.

**Q6. How many types of rotations are there?**

Four: LL, RR, LR and RL.

**Q7. Which rotation is used for LL imbalance?**

Right Rotation.

**Q8. Which rotation is used for RR imbalance?**

Left Rotation.

**Q9. What is the time complexity of searching in an AVL Tree?**

O(log n).

**Q10. What is the main difference between an AVL Tree and a normal BST?**

An AVL Tree automatically maintains balance, whereas a normal BST does not.

## 18. Key Takeaways

- AVL Trees are self-balancing Binary Search Trees.
- Every node must have a balance factor of -1, 0 or +1.
- Balance Factor = Left Subtree Height - Right Subtree Height.
- LL requires a right rotation.
- RR requires a left rotation.
- LR requires left rotation followed by right rotation.
- RL requires right rotation followed by left rotation.
- AVL Trees maintain O(log n) worst-case search, insertion and deletion complexity.
- Rotations restore balance after updates.
