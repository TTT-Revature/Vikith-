# BFS – Breadth First Search: Implementation and Problem Solving

## 1. What is BFS?

**Breadth First Search (BFS)** is a graph traversal algorithm used to visit all reachable vertices of a graph level by level.

It starts from a selected vertex and explores all its immediate neighbors before moving to the next level.

BFS uses a **Queue (FIFO – First In, First Out)** data structure.

### Real-world examples

- Finding the shortest route in an unweighted map.
- Finding people within a certain connection distance in a social network.
- Searching nearby locations.
- Finding the minimum number of moves in a game.
- Exploring connected components in a graph.

---

## 2. Understanding BFS with an Example

Consider the following graph:

```text
          A
        /   \
       B     C
      / \     \
     D   E     F
```

Starting vertex: `A`

BFS visits vertices level by level:

```text
Level 0:       A

Level 1:     B   C

Level 2:   D  E   F
```

**BFS Traversal:**

```text
A → B → C → D → E → F
```

Notice that BFS visits all the vertices at the current level before moving to the next level.

---

## 3. Why Does BFS Use a Queue?

A queue follows the FIFO principle.

**FIFO = First In, First Out**

The element inserted first is removed first.

Example:

```python
queue = []

queue.append("A")
queue.append("B")
queue.append("C")

print(queue)

first = queue.pop(0)

print(first)
print(queue)
```

Output:

```text
['A', 'B', 'C']
A
['B', 'C']
```

BFS uses this behavior to process vertices in the order they are discovered.

> Note: Python's `list.pop(0)` takes O(n) time because the remaining elements need to shift. We will use `collections.deque` for an efficient implementation.

## 4. Understanding the Visited Set

Why do we need a `visited` set?

Consider a graph containing a cycle:

```text
    A
   / \
  B---C
```

Connections:

```text
A → B
A → C
B → C
C → A
```

Without tracking visited vertices, BFS may repeatedly visit the same vertices.

A `visited` set stores the vertices that have already been discovered.

```python
visited = set()

visited.add("A")

if "A" not in visited:
    print("Visit A")
else:
    print("Already visited")
```

Output:

```text
Already visited
```

**Important:** Mark a vertex as visited when adding it to the queue, not when removing it. This prevents the same vertex from being added multiple times.

## 6. BFS Implementation Using Python

### Complete code

```python
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["A", "D", "E"],
    "C": ["A", "F"],
    "D": ["B"],
    "E": ["B"],
    "F": ["C"]
}

def bfs(graph, start):

    visited = set()
    queue = deque()

    visited.add(start)
    queue.append(start)

    while queue:

        current = queue.popleft()

        print(current, end=" ")

        for neighbor in graph[current]:

            if neighbor not in visited:

                visited.add(neighbor)
                queue.append(neighbor)


bfs(graph, "A")
```

Output:

```text
A B C D E F
```

### Understanding each step

**Step 1: Import deque**

```python
from collections import deque
```

`deque` stands for double-ended queue. It allows efficient insertion and removal from both ends.

**Step 2: Create visited and queue**

```python
visited = set()
queue = deque()
```

- `visited` keeps track of discovered vertices.
- `queue` stores vertices waiting to be processed.

**Step 3: Add the starting vertex**

```python
visited.add(start)
queue.append(start)
```

We mark the starting vertex as visited and add it to the queue.

**Step 4: Continue while the queue is not empty**

```python
while queue:
```

As long as vertices are waiting in the queue, the algorithm continues.

**Step 5: Remove the first vertex**

```python
current = queue.popleft()
```

The oldest vertex in the queue is removed.

**Step 6: Explore its neighbors**

```python
for neighbor in graph[current]:
```

We check every neighbor of the current vertex.

**Step 7: Add unvisited neighbors**

```python
if neighbor not in visited:

    visited.add(neighbor)
    queue.append(neighbor)
```

If a neighbor has not been discovered:
1. Mark it as visited.
2. Add it to the queue.

## 7. Dry Run – Step-by-Step Execution

Let's trace the same graph starting from `A`.

```text
          A
        /   \
       B     C
      / \     \
     D   E     F
```

Initially:

```text
Queue   = [A]
Visited = {A}
```

| Step | Current vertex | Newly discovered | Queue after processing |
|---|---|---|---|
| 1 | A | B, C | [B, C] |
| 2 | B | D, E | [C, D, E] |
| 3 | C | F | [D, E, F] |
| 4 | D | None | [E, F] |
| 5 | E | None | [F] |
| 6 | F | None | [] |

Final traversal:

```text
A → B → C → D → E → F
```

Final visited set:

```python
{"A", "B", "C", "D", "E", "F"}
```

### Important observation

When processing `B`, the algorithm finds `A`, `D`, and `E`.

- `A` is already visited.
- `D` is not visited, so it enters the queue.
- `E` is not visited, so it enters the queue.

This is how BFS avoids revisiting vertices.

## 8. BFS Using a Queue Without deque

We can also implement BFS using a normal Python list.

```python
def bfs(graph, start):

    visited = {start}
    queue = [start]

    while queue:

        current = queue.pop(0)

        print(current, end=" ")

        for neighbor in graph[current]:

            if neighbor not in visited:

                visited.add(neighbor)
                queue.append(neighbor)
```

This implementation is logically correct.

However:

```python
queue.pop(0)
```

takes O(n) time because Python shifts the remaining elements.

For efficient BFS, prefer:

```python
from collections import deque

queue = deque()
queue.popleft()
```

## 9. BFS Traversal for a Disconnected Graph

What happens if a graph contains multiple disconnected components?

Example:

```text
Component 1:

A ---- B
|      |
C ---- D


Component 2:

E ---- F
```

If we start BFS from `A`, only the first component is visited.

To visit every vertex in the graph, we need an outer loop.

### Implementation

```python
from collections import deque

def bfs_all(graph):

    visited = set()

    for vertex in graph:

        if vertex not in visited:

            queue = deque([vertex])
            visited.add(vertex)

            while queue:

                current = queue.popleft()

                print(current, end=" ")

                for neighbor in graph[current]:

                    if neighbor not in visited:

                        visited.add(neighbor)
                        queue.append(neighbor)


graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "D"],
    "D": ["B", "C"],
    "E": ["F"],
    "F": ["E"]
}

bfs_all(graph)
```

Possible output:

```text
A B C D E F
```

The order within each component depends on the order of neighbors in the adjacency list.

## 10. Finding the Shortest Path Using BFS

One of the most important applications of BFS is finding the shortest path in an **unweighted graph**.

Why does BFS work?

Because BFS explores vertices level by level.

The first time we reach a vertex, we have found a path with the minimum number of edges from the starting vertex.

Consider:

```text
       A
      / \
     B   C
    /     \
   D       E
    \     /
       F
```

There are multiple possible paths from `A` to `F`.

BFS finds a path with the minimum number of edges.

### Implementation – Shortest Distance

```python
from collections import deque

def shortest_distance(graph, start, target):

    queue = deque([(start, 0)])
    visited = {start}

    while queue:

        current, distance = queue.popleft()

        if current == target:
            return distance

        for neighbor in graph[current]:

            if neighbor not in visited:

                visited.add(neighbor)

                queue.append((neighbor, distance + 1))

    return -1


graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "D"],
    "D": ["B", "C", "F"],
    "F": ["D"]
}

print(shortest_distance(graph, "A", "F"))
```

Output:

```text
3
```

Explanation:

```text
A → B → D → F
```

Number of edges = `3`.

### Returning the Actual Shortest Path

Instead of returning only the distance, we can reconstruct the path using a parent dictionary.

```python
from collections import deque

def shortest_path(graph, start, target):

    queue = deque([start])

    visited = {start}

    parent = {start: None}

    while queue:

        current = queue.popleft()

        if current == target:
            break

        for neighbor in graph[current]:

            if neighbor not in visited:

                visited.add(neighbor)

                parent[neighbor] = current

                queue.append(neighbor)

    if target not in parent:
        return None

    path = []
    current = target

    while current is not None:

        path.append(current)
        current = parent[current]

    path.reverse()

    return path


graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "D"],
    "D": ["B", "C", "F"],
    "F": ["D"]
}

print(shortest_path(graph, "A", "F"))
```

Output:

```text
['A', 'B', 'D', 'F']
```

Note: If multiple shortest paths exist, the returned path depends on neighbor ordering.

## 11. BFS Level Order Traversal

BFS naturally processes vertices level by level.

We can use this property to group vertices by their distance from the starting vertex.

### Implementation

```python
from collections import deque

def bfs_levels(graph, start):

    queue = deque([start])
    visited = {start}

    level = 0

    while queue:

        size = len(queue)

        print(f"Level {level}:", end=" ")

        for _ in range(size):

            current = queue.popleft()

            print(current, end=" ")

            for neighbor in graph[current]:

                if neighbor not in visited:

                    visited.add(neighbor)
                    queue.append(neighbor)

        print()

        level += 1


graph = {
    "A": ["B", "C"],
    "B": ["A", "D", "E"],
    "C": ["A", "F"],
    "D": ["B"],
    "E": ["B"],
    "F": ["C"]
}

bfs_levels(graph, "A")
```

Output:

```text
Level 0: A
Level 1: B C
Level 2: D E F
```

### How does `size = len(queue)` help?

Suppose the queue contains:

```text
[B, C]
```

The current level contains two vertices.

```python
size = len(queue)
```

The `for` loop processes exactly those two vertices.

Any newly discovered vertices are added to the queue for the next level.

This technique is frequently used in tree and graph problems.

## 12. BFS in Binary Trees

BFS is also used in binary trees.

In trees, BFS is commonly called **Level Order Traversal**.

Example:

```text
          1
        /   \
       2     3
      / \   / \
     4   5 6   7
```

Expected traversal:

```text
1 → 2 → 3 → 4 → 5 → 6 → 7
```

### Python Implementation

```python
from collections import deque

class Node:

    def __init__(self, value):

        self.value = value
        self.left = None
        self.right = None


def level_order(root):

    if root is None:
        return

    queue = deque([root])

    while queue:

        current = queue.popleft()

        print(current.value, end=" ")

        if current.left:
            queue.append(current.left)

        if current.right:
            queue.append(current.right)


root = Node(1)

root.left = Node(2)
root.right = Node(3)

root.left.left = Node(4)
root.left.right = Node(5)

root.right.left = Node(6)
root.right.right = Node(7)

level_order(root)
```

Output:

```text
1 2 3 4 5 6 7
```

## 13. Time and Space Complexity of BFS

Let:

- V = Number of vertices.
- E = Number of edges.

For a graph represented using an adjacency list:

| Operation | Complexity |
|---|---|
| Visit each vertex | O(V) |
| Explore all adjacency lists | O(E) |
| Queue operations | O(V) |
| Total time complexity | O(V + E) |
| Auxiliary space complexity | O(V) |

### Why O(V + E)?

Each vertex is added to the queue at most once.

Each vertex is removed from the queue at most once.

Every edge is examined a constant number of times in an adjacency-list representation.

Therefore:

```text
Time Complexity = O(V + E)
Space Complexity = O(V)
```

For an adjacency matrix, checking all possible neighbors of each vertex takes O(V²), so BFS takes O(V²) time.

## 14. BFS vs DFS

Both BFS and DFS are graph traversal algorithms, but they explore graphs differently.

| Feature | BFS | DFS |
|---|---|---|
| Full form | Breadth First Search | Depth First Search |
| Approach | Level by level | Go deep first |
| Data structure | Queue | Stack / Recursion |
| Shortest path | Yes, for unweighted graphs | Not guaranteed |
| Traversal style | Explores neighbors first | Explores one path deeply |
| Complexity | O(V + E) | O(V + E) |
| Common use | Minimum number of edges | Backtracking and cycle-related problems |

### Visual comparison

```text
        A
       / \
      B   C
     / \   \
    D   E   F
```

BFS:

```text
A → B → C → D → E → F
```

One possible DFS traversal:

```text
A → B → D → E → C → F
```

The exact DFS order depends on the neighbor ordering and implementation.

## 15. Common Mistakes in BFS

### Mistake 1: Forgetting the visited set

Without a visited set, cycles can cause repeated processing.

### Mistake 2: Marking visited too late

Incorrect:

```python
current = queue.popleft()
visited.add(current)
```

If a vertex is discovered through multiple neighbors before it is removed from the queue, it can be inserted multiple times.

Better:

```python
visited.add(neighbor)
queue.append(neighbor)
```

Mark it when discovered.

### Mistake 3: Using `pop()` instead of `popleft()`

```python
current = queue.pop()
```

This removes the last element and behaves like stack-based traversal.

For BFS, use:

```python
current = queue.popleft()
```

### Mistake 4: Assuming BFS always finds the shortest weighted path

BFS finds shortest paths by number of edges in an unweighted graph, or when all edges have equal cost.

For graphs with different non-negative edge weights, use Dijkstra's algorithm instead.

### Mistake 5: Forgetting disconnected components

A single BFS starting from one vertex cannot visit vertices in other disconnected components.

Use an outer loop to traverse all components.
