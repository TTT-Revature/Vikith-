# BST Complexity and Problem Solving

## 1. Introduction

A **Binary Search Tree (BST)** is a hierarchical data structure where:

- Left subtree contains values smaller than the current node.
- Right subtree contains values greater than the current node.
- Both subtrees follow the same BST property.

Example:

```text
             50
           /    \
         30      70
        /  \    /  \
       20  40  60  80
```

BSTs are useful for efficient searching, insertion, deletion and maintaining sorted data.

However, the performance of a BST depends heavily on its structure.

---

## 2. Understanding BST Height

The height of a BST is the number of edges in the longest path from the root to a leaf.

Example of a balanced BST:

```text
             50
           /    \
         30      70
        /  \    /  \
       20  40  60  80
```

Height = 2

Example of a skewed BST:

```text
10
  \
   20
     \
      30
        \
         40
           \
            50
```

Height = 4

### Important Relationship

The height of a BST determines the number of nodes we may need to visit during searching, insertion or deletion.

- Smaller height = Faster operations.
- Greater height = Slower operations.

---

## 3. Time Complexity of BST Operations

Let:

- n = Number of nodes.
- h = Height of the BST.

The time complexity of the main BST operations is generally O(h).

### Complexity Table

| Operation | Best Case | Average Case | Worst Case |
|---|---|---|---|
| Search | O(1) | O(log n) | O(n) |
| Insert | O(1)* | O(log n) | O(n) |
| Delete | O(1)* | O(log n) | O(n) |
| Find Minimum | O(1)* | O(log n) | O(n) |
| Find Maximum | O(1)* | O(log n) | O(n) |
| Inorder Traversal | O(n) | O(n) | O(n) |

*Best-case O(1) applies when the required node or insertion position is immediately accessible, such as finding the root or inserting into an empty tree.*

### Why Is Searching O(log n) in a Balanced BST?

Consider a BST with 15 nodes.

```text
                 50
              /      \
            30        70
           /  \      /  \
         20   40    60   80
        / \   / \   / \  / \
       10 25 35 45 55 65 75 85
```

At each comparison, we eliminate approximately half of the remaining search space.

For example, searching for 65:

1. Compare 65 with 50.
2. Move right because 65 > 50.
3. Compare 65 with 70.
4. Move left because 65 < 70.
5. Compare 65 with 60.
6. Move right and find 65.

The search follows only one path instead of visiting every node.

This is why balanced BST searching takes O(log n).

---

## 4. Why Does BST Become O(n)?

Consider inserting sorted values:

```python
values = [10, 20, 30, 40, 50]
```

The resulting BST:

```text
10
  \
   20
     \
      30
        \
         40
           \
            50
```

This is called a Right-Skewed BST.

If we search for 50, we may need to visit all five nodes.

Therefore:

- Number of nodes = 5
- Number of comparisons = 5
- Time Complexity = O(n)

The same problem occurs with a left-skewed BST.

### Important Interview Question

**Why is a BST not always O(log n)?**

Because a normal BST does not automatically maintain its balance. If values are inserted in sorted order, it can become skewed, resulting in O(n) operations.

## 5. Space Complexity of BST Operations

Space complexity measures how much additional memory an algorithm uses.

### Recursive Search

```python
def search(root, key):

    if root is None:
        return False

    if root.data == key:
        return True

    if key < root.data:
        return search(root.left, key)

    return search(root.right, key)
```

Each recursive call uses stack memory.

Space Complexity = O(h)

### Iterative Search

```python
def search(root, key):

    while root is not None:

        if root.data == key:
            return True

        elif key < root.data:
            root = root.left

        else:
            root = root.right

    return False
```

Space Complexity = O(1)

Why?

Because it uses a loop instead of recursive function calls and does not create additional data structures.

### Space Complexity Table

| Operation | Recursive | Iterative |
|---|---|---|
| Search | O(h) | O(1) |
| Insert | O(h) | O(1) |
| Delete | O(h) | O(1) with iterative implementation |
| Inorder Traversal | O(h) | O(h) using a stack |

Note: The tree itself occupies O(n) memory, which is not included in the auxiliary space calculations above.

## 6. BST Problem Solving – Important Patterns

When solving BST problems, understanding the following patterns will help.

### Pattern 1: Compare and Move

Used in:
- Searching
- Insertion
- Finding minimum and maximum

Logic:

```python
if key < root.data:
    root = root.left

elif key > root.data:
    root = root.right
```

### Pattern 2: Inorder Traversal

Used in:
- Finding kth smallest element.
- Checking sorted order.
- Finding minimum and maximum.
- Validating BSTs.

Logic:

```python
def inorder(root):

    if root is None:
        return

    inorder(root.left)

    print(root.data)

    inorder(root.right)
```

### Pattern 3: Minimum and Maximum

Minimum: Keep moving left.

Maximum: Keep moving right.

```python
def find_min(root):

    while root.left is not None:
        root = root.left

    return root.data


def find_max(root):

    while root.right is not None:
        root = root.right

    return root.data
```

### Pattern 4: Recursive Subtree Processing

Used in:
- Height calculation.
- Deletion.
- Validation.
- Lowest Common Ancestor.

Understand how to solve a problem for the current node and then apply the same logic to its subtrees.

# 7. Important BST Coding Problems

## Problem 1: Find Minimum Value in BST

**Task:** Given a BST, return the smallest value.

Example:

```text
          50
         /  \
        30   70
       /
      20
```

Expected Output:

```text
20
```

Python Solution:

```python
def find_min(root):

    if root is None:
        return None

    while root.left is not None:
        root = root.left

    return root.data
```

Time Complexity: O(h)

Space Complexity: O(1)

---

## Problem 2: Find Maximum Value in BST

**Task:** Find the largest value in a BST.

Example:

```text
          50
         /  \
        30   70
               \
                80
```

Expected Output:

```text
80
```

Python Solution:

```python
def find_max(root):

    if root is None:
        return None

    while root.right is not None:
        root = root.right

    return root.data
```

Time Complexity: O(h)

Space Complexity: O(1)

---

## Problem 3: Validate Binary Search Tree

**Task:** Given a binary tree, determine whether it is a valid BST.

Example 1:

```text
          50
         /  \
        30   70
```

Output:

```text
True
```

Example 2:

```text
          50
         /  \
        30   70
            /
           40
```

Output:

```text
False
```

Why is Example 2 invalid?

40 is the left child of 70, but it is located in the right subtree of 50.

Every value in the right subtree of 50 must be greater than 50.

### Python Solution

```python
def is_valid_bst(root, low=float('-inf'), high=float('inf')):

    if root is None:
        return True

    if root.data <= low or root.data >= high:
        return False

    return (
        is_valid_bst(root.left, low, root.data)
        and
        is_valid_bst(root.right, root.data, high)
    )
```

Time Complexity: O(n)

Space Complexity: O(h)

Important: Checking only the immediate left and right children is not sufficient. Every node must satisfy the range inherited from all its ancestors.

## Problem 4: Find Kth Smallest Element in BST

**Task:** Find the kth smallest element in a BST.

Example:

```text
          50
         /  \
        30   70
       / \   / \
      20 40 60 80
```

If k = 3:

Sorted order:

```text
20, 30, 40, 50, 60, 70, 80
```

Expected Output:

```text
40
```

### Python Solution

```python
def kth_smallest(root, k):

    stack = []
    current = root
    count = 0

    while current is not None or stack:

        while current is not None:
            stack.append(current)
            current = current.left

        current = stack.pop()

        count += 1

        if count == k:
            return current.data

        current = current.right

    return None
```

Time Complexity: O(h + k) for a successful search.

Worst-case Time Complexity: O(n).

Space Complexity: O(h).

## Problem 5: Lowest Common Ancestor in BST

**Task:** Find the lowest common ancestor (LCA) of two nodes in a BST.

The LCA is the lowest node in the tree that has both target nodes as descendants. A node can also be a descendant of itself.

Example:

```text
             50
           /    \
         30      70
        /  \
       20  40
```

Find LCA of 20 and 40.

Expected Output:

```text
30
```

Why?

Both 20 and 40 are located in the subtree of 30.

### Python Solution

```python
def lowest_common_ancestor(root, p, q):

    while root is not None:

        if p < root.data and q < root.data:
            root = root.left

        elif p > root.data and q > root.data:
            root = root.right

        else:
            return root.data

    return None
```

Time Complexity: O(h)

Space Complexity: O(1)
