# Algorithm Analysis – Why and How Algorithms Are Evaluated

## 1. What is Algorithm Analysis?

Algorithm Analysis is the process of evaluating an algorithm to understand how efficiently it uses computational resources.

It mainly focuses on:

- **Time Complexity:** How execution time grows with input size.
- **Space Complexity:** How memory usage grows with input size.

The main goal is to identify efficient algorithms that solve problems using fewer resources.

## 2. Why Do We Analyze Algorithms?

Algorithm analysis helps us:

1. Compare different algorithms solving the same problem.
2. Understand performance for large inputs.
3. Reduce execution time.
4. Optimize memory usage.
5. Select the most efficient solution.
6. Predict how an algorithm performs as input size increases.

### Example

Consider finding an element in a list.

**Method 1: Linear Search**

Checks elements one by one.

**Method 2: Binary Search**

Repeatedly divides a sorted search space into two halves.

For large sorted datasets, Binary Search is generally more efficient.

## 3. How Are Algorithms Evaluated?

Algorithms are mainly evaluated using two measures:

### A. Time Complexity

Time Complexity describes how the number of operations performed by an algorithm grows with input size.

Example:

```python
numbers = [10, 20, 30, 40, 50]

for num in numbers:
    print(num)
```

The loop executes 5 times for 5 elements.

If there are `n` elements, the loop executes `n` times.

**Time Complexity: O(n)**

### B. Space Complexity

Space Complexity describes how much memory an algorithm requires as input size increases.

Example:

```python
numbers = [10, 20, 30, 40, 50]

total = 0

for num in numbers:
    total += num

print(total)
```

The input list contains `n` elements, but the algorithm uses only one additional variable (`total`).

**Auxiliary Space Complexity: O(1)**

Note: Auxiliary space measures extra memory used by the algorithm, excluding the input itself.

## 4. Types of Algorithm Analysis

### 1. Best Case Analysis

The minimum number of operations required for an input of a given size.

Example: In Linear Search, the element is found at the first position.

**Complexity: O(1)**

### 2. Average Case Analysis

The expected number of operations for typical inputs, based on an assumed input distribution.

Example: In Linear Search, the element is found somewhere in the middle on average.

**Complexity: O(n)**

### 3. Worst Case Analysis

The maximum number of operations required for an input of a given size.

Example: In Linear Search, the element is at the last position or is not present.

**Complexity: O(n)**

## 5. Asymptotic Notations

Asymptotic notations describe how an algorithm's resource requirements grow as input size approaches infinity.

### A. Big O – O()

Describes an asymptotic upper bound.

Commonly used to express worst-case growth.

Example:

```python
for i in range(n):
    print(i)
```

Time Complexity: **O(n)**

### B. Omega – Ω()

Describes an asymptotic lower bound.

Example:

In Linear Search, if the element is at the first position, only one comparison is needed.

Best-case complexity: **Ω(1)**

### C. Theta – Θ()

Describes a tight asymptotic bound when upper and lower bounds grow at the same rate.

Example:

```python
for i in range(n):
    print(i)
```

The loop always executes `n` times.

Complexity: **Θ(n)**

## 6. Common Time Complexities

| Complexity | Name | Example |
|---|---|---|
| O(1) | Constant | Array element access |
| O(log n) | Logarithmic | Binary Search |
| O(n) | Linear | Linear Search |
| O(n log n) | Linearithmic | Merge Sort |
| O(n²) | Quadratic | Nested loops |
| O(2ⁿ) | Exponential | Recursive subset generation |
| O(n!) | Factorial | Generating permutations |

### Growth Order

From generally more efficient to less efficient:

`O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)`

## 7. Counting Operations

We can estimate time complexity by counting how many times statements execute.

### Example 1: Constant Time – O(1)

```python
a = 10
b = 20

print(a + b)
```

The number of operations does not depend on input size.

### Example 2: Linear Time – O(n)

```python
for i in range(n):
    print(i)
```

The loop executes `n` times.

### Example 3: Quadratic Time – O(n²)

```python
for i in range(n):
    for j in range(n):
        print(i, j)
```

Outer loop executes `n` times.

Inner loop executes `n` times for every outer iteration.

Total operations = `n × n = n²`.

Time Complexity: **O(n²)**

### Example 4: Logarithmic Time – O(log n)

```python
i = 1

while i < n:
    print(i)
    i *= 2
```

The value doubles during every iteration.

For example: 1, 2, 4, 8, 16, 32...

Time Complexity: **O(log n)**

## 8. Rules for Calculating Time Complexity

1. Ignore constant values.

   `O(2n)` becomes `O(n)`.

2. Ignore lower-order terms.

   `O(n² + n + 10)` becomes `O(n²)`.

3. Sequential loops are added.

   `O(n) + O(n)` becomes `O(n)`.

4. Nested loops are multiplied.

   `O(n) × O(n)` becomes `O(n²)`.

5. If an algorithm has different branches, analyze the relevant branch and input cases.

## 9. Time Complexity vs Space Complexity

| Time Complexity | Space Complexity |
|---|---|
| Measures execution-time growth | Measures memory usage growth |
| Focuses on operations | Focuses on memory |
| Helps optimize speed | Helps optimize memory |
| Example: O(n) | Example: O(1) auxiliary space |

## 10. Practical Importance

Algorithm analysis is useful in:

- Search engines
- Database systems
- Banking applications
- Social media platforms
- E-commerce applications
- Machine learning
- Large-scale data processing

Efficient algorithms help applications handle increasing amounts of data without unnecessary performance problems.

## Key Takeaways

- Algorithm analysis evaluates efficiency.
- Time Complexity measures execution-time growth.
- Space Complexity measures memory usage.
- Best, Average and Worst cases describe different performance scenarios.
- Big O, Omega and Theta are asymptotic notations.
- Nested loops commonly result in quadratic complexity.
- Efficient algorithms are important when working with large datasets.
