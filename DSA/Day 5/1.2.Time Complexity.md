# Time Complexity – Big O and Best/Average/Worst Case

## 1. What is Time Complexity?

Time Complexity measures how the number of operations performed by an algorithm increases as the input size increases.

It helps us understand how efficiently an algorithm performs, especially when working with large datasets.

**Example:**

```python
numbers = [10, 20, 30, 40, 50]

for num in numbers:
    print(num)
```

If the list contains:
- 5 elements → 5 iterations
- 100 elements → 100 iterations
- 1000 elements → 1000 iterations

The number of iterations increases with input size.

**Time Complexity: O(n)**

Here, `n` represents the input size.

---

## 2. What is Big O Notation?

Big O notation describes the asymptotic upper bound of an algorithm's growth rate.

It is commonly used to express worst-case time complexity.

It helps us compare algorithms without depending on a particular computer, processor, or programming language.

### Common Big O Complexities

| Big O | Name | Description |
|---|---|---|
| O(1) | Constant | Execution does not depend on input size |
| O(log n) | Logarithmic | Input is reduced by a constant factor |
| O(n) | Linear | Operations grow proportionally with input |
| O(n log n) | Linearithmic | Common in efficient sorting |
| O(n²) | Quadratic | Often occurs with nested loops |
| O(n³) | Cubic | Often occurs with three nested loops |
| O(2ⁿ) | Exponential | Growth doubles with each additional input |
| O(n!) | Factorial | Growth occurs through permutations |

### Growth Order

From generally most efficient to least efficient:

`O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)`

---

## 3. Understanding Different Time Complexities

### A. O(1) – Constant Time

The execution requires a constant number of operations regardless of input size.

```python
numbers = [10, 20, 30, 40, 50]

print(numbers[0])
```

Accessing an element using its index takes constant time.

**Time Complexity: O(1)**

### B. O(log n) – Logarithmic Time

The input size is reduced by a constant factor in each iteration.

```python
n = 100

while n > 1:
    print(n)
    n //= 2
```

Values: 100 → 50 → 25 → 12 → 6 → 3 → 1

The number of iterations grows logarithmically.

**Time Complexity: O(log n)**

### C. O(n) – Linear Time

The number of operations grows proportionally with the input size.

```python
numbers = [10, 20, 30, 40, 50]

for num in numbers:
    print(num)
```

For `n` elements, the loop executes `n` times.

**Time Complexity: O(n)**

### D. O(n log n) – Linearithmic Time

Commonly found in efficient sorting algorithms.

Examples:
- Merge Sort
- Heap Sort
- Average-case Quick Sort

```python
# Merge Sort follows O(n log n) time complexity.
```

### E. O(n²) – Quadratic Time

Usually occurs when one loop runs inside another loop.

```python
numbers = [1, 2, 3, 4]

for i in numbers:
    for j in numbers:
        print(i, j)
```

For 4 elements:
- Outer loop: 4 iterations
- Inner loop: 4 iterations per outer iteration
- Total: 4 × 4 = 16 iterations

For `n` elements, total operations grow as `n²`.

**Time Complexity: O(n²)**

### F. O(2ⁿ) – Exponential Time

The number of operations grows exponentially with input size.

Example: Generating all subsets of a collection.

### G. O(n!) – Factorial Time

The number of operations grows according to the factorial of input size.

Example: Generating all possible permutations of `n` elements.

## 4. Best Case, Average Case and Worst Case

An algorithm can perform differently depending on the arrangement of input data.

These three cases help us understand its performance.

### A. Best Case

The minimum number of operations needed for an input of a given size.

Example: Searching for an element that is at the first position.

### B. Average Case

The expected number of operations for typical inputs under a specified input distribution.

Example: Searching for an element that is somewhere in the middle of a list.

### C. Worst Case

The maximum number of operations required for an input of a given size.

Example: Searching for an element at the last position or an element that does not exist.

## 5. Practical Example – Linear Search

```python
def linear_search(numbers, target):

    for i in range(len(numbers)):
        if numbers[i] == target:
            return i

    return -1


numbers = [10, 20, 30, 40, 50]

print(linear_search(numbers, 10))
```

### Case Analysis

**Best Case: O(1)**

Target = 10

The element is found at index 0.

Only one comparison is required.

**Average Case: O(n)**

Target = 30

The algorithm checks multiple elements before finding the target.

**Worst Case: O(n)**

Target = 100

The algorithm checks every element and returns -1.

### Complexity Summary

| Case | Time Complexity |
|---|---|
| Best Case | O(1) |
| Average Case | O(n) |
| Worst Case | O(n) |

---

## 6. Practical Example – Binary Search

Binary Search works only on sorted data.

It repeatedly divides the search range into two halves.

```python
def binary_search(numbers, target):

    left = 0
    right = len(numbers) - 1

    while left <= right:

        mid = (left + right) // 2

        if numbers[mid] == target:
            return mid

        elif numbers[mid] < target:
            left = mid + 1

        else:
            right = mid - 1

    return -1


numbers = [10, 20, 30, 40, 50]

print(binary_search(numbers, 30))
```

### Case Analysis

- Best Case: O(1) – Target is found at the middle during the first comparison.
- Average Case: O(log n) – Search range is repeatedly divided.
- Worst Case: O(log n) – The algorithm continues dividing until the target is found or the range becomes empty.

### Complexity Summary

| Case | Time Complexity |
|---|---|
| Best Case | O(1) |
| Average Case | O(log n) |
| Worst Case | O(log n) |

## 7. Rules for Calculating Big O

### Rule 1: Ignore Constants

```python
for i in range(n):
    print(i)

for j in range(n):
    print(j)
```

Total operations = `n + n = 2n`

Big O = **O(n)**

### Rule 2: Ignore Lower-Order Terms

If the complexity is:

`O(n² + n + 10)`

The dominant term is `n²`.

Big O = **O(n²)**

### Rule 3: Nested Loops

```python
for i in range(n):
    for j in range(n):
        print(i, j)
```

Big O = **O(n²)**

### Rule 4: Independent Loops

```python
for i in range(n):
    print(i)

for j in range(n):
    print(j)
```

Big O = **O(n)**, not O(n²).

### Rule 5: Different Input Sizes

```python
def example(a, b):

    for i in range(a):
        print(i)

    for j in range(b):
        print(j)
```

Time Complexity = **O(a + b)**

We keep separate input variables when their sizes are independent.
