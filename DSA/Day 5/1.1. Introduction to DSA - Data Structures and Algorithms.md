# Introduction to DSA (Data Structures and Algorithms)

## 1. What is DSA?

DSA stands for **Data Structures and Algorithms**.

- **Data Structures:** Ways of organizing and storing data efficiently.
- **Algorithms:** Step-by-step instructions used to solve a particular problem.

DSA helps us write programs that are efficient in terms of execution time and memory usage.

## 2. Why is DSA Important?

- Improves problem-solving skills.
- Helps write efficient code.
- Reduces execution time and memory usage.
- Helps handle large amounts of data.
- Important for technical interviews and competitive programming.

## 3. What are Data Structures?

A data structure is a way of organizing and storing data so that it can be accessed and modified efficiently.

### Types of Data Structures

**1. Linear Data Structures**

Elements are arranged sequentially.

| Data Structure | Description |
|---|---|
| Array | Stores elements in indexed positions |
| Linked List | Stores elements using connected nodes |
| Stack | Follows LIFO (Last In, First Out) |
| Queue | Follows FIFO (First In, First Out) |

**2. Non-Linear Data Structures**

Elements are arranged hierarchically or through connections.

| Data Structure | Description |
|---|---|
| Tree | Stores data in a hierarchical structure |
| Graph | Represents connections between vertices |
| Heap | A specialized tree-based data structure |
| Hash Table | Stores key-value pairs for efficient lookup |

## 4. What are Algorithms?

An algorithm is a finite sequence of well-defined steps used to solve a problem.

### Example: Find the Largest Number

```python
numbers = [10, 25, 5, 40, 15]

largest = numbers[0]

for num in numbers:
    if num > largest:
        largest = num

print(largest)

# Output: 40
```

### Characteristics of an Algorithm

1. **Input:** Accepts zero or more inputs.
2. **Output:** Produces at least one result.
3. **Definiteness:** Every step must be clear.
4. **Finiteness:** Must terminate after a finite number of steps.
5. **Effectiveness:** Every operation must be basic and executable.

## 5. Types of Algorithms

| Algorithm | Purpose |
|---|---|
| Searching | Finds an element in a collection |
| Sorting | Arranges elements in a specific order |
| Recursion | Solves problems by calling itself |
| Greedy | Makes the best local choice at each step |
| Divide and Conquer | Divides problems into smaller subproblems |
| Dynamic Programming | Stores previous results to avoid repeated calculations |
| Backtracking | Explores possible solutions and reverses unsuccessful choices |

## 6. Introduction to Algorithm Complexity

Algorithm complexity measures how much time and memory an algorithm requires as the input size increases.

There are two major types:

### Time Complexity

Measures how the execution time grows with input size.

### Space Complexity

Measures how much additional memory an algorithm requires.

## 7. Big O Notation

Big O notation describes the upper-bound growth rate of an algorithm.

| Complexity | Name | Example |
|---|---|---|
| O(1) | Constant | Accessing an array element |
| O(log n) | Logarithmic | Binary Search |
| O(n) | Linear | Linear Search |
| O(n log n) | Linearithmic | Merge Sort |
| O(n²) | Quadratic | Bubble Sort |
| O(2ⁿ) | Exponential | Some recursive problems |
| O(n!) | Factorial | Generating all permutations |

## 8. Best, Average and Worst Case

- **Best Case:** Minimum time required for an algorithm.
- **Average Case:** Expected time for typical inputs.
- **Worst Case:** Maximum time required for an algorithm under a given input size.

Example: Linear Search

```python
numbers = [10, 20, 30, 40, 50]

target = 10

for num in numbers:
    if num == target:
        print("Found")
        break
```

- Best Case: O(1) – Element found at the first position.
- Average Case: O(n) – Element found somewhere in the middle.
- Worst Case: O(n) – Element found at the last position or not found.
