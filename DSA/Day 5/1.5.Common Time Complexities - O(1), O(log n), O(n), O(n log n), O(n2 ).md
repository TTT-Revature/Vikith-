# Common Time Complexities in DSA

## 1. Introduction

Time Complexity describes how the number of operations performed by an algorithm grows as the input size (`n`) increases.

The five commonly used time complexities are:

1. O(1) – Constant Time
2. O(log n) – Logarithmic Time
3. O(n) – Linear Time
4. O(n log n) – Linearithmic Time
5. O(n²) – Quadratic Time

Understanding these complexities helps us identify efficient and inefficient algorithms.

---

## 2. O(1) – Constant Time

Constant time means the number of operations does not depend on the input size.

### Example

```python
numbers = [10, 20, 30, 40, 50]

print(numbers[0])
```

**Output:**
```text
10
```

Regardless of whether the list contains 5 or 1 million elements, accessing an element by index takes constant time.

**Time Complexity: O(1)**

### Another Example

```python
def add(a, b):
    return a + b

print(add(10, 20))
```

Only a constant number of operations are performed.

**Real-world examples:**
- Accessing an array element by index.
- Updating a variable.
- Accessing a dictionary value by key (average case).

---

## 3. O(log n) – Logarithmic Time

Logarithmic time occurs when the input size is repeatedly reduced by a constant factor.

A common example is dividing the search space into two halves.

### Example: Binary Search

```python
def binary_search(numbers, target):

    left = 0
    right = len(numbers) - 1

    while left <= right:

        mid = (left + right) // 2

        if numbers[mid] == target:
            return mid

        elif numbers[mid] < target:
            left = mid + 1

        else:
            right = mid - 1

    return -1


numbers = [10, 20, 30, 40, 50, 60, 70]

print(binary_search(numbers, 50))
```

**Output:**
```text
4
```

The search space is divided into halves in each iteration.

Example:

```text
64 → 32 → 16 → 8 → 4 → 2 → 1
```

For 64 elements, approximately 6 halvings are needed.

**Time Complexity: O(log n)**

Important: Binary Search requires sorted data.

**Real-world examples:**
- Binary Search.
- Searching in balanced Binary Search Trees.
- Operations in balanced search structures.

---

## 4. O(n) – Linear Time

Linear time means the number of operations increases proportionally with the input size.

If the input doubles, the number of operations approximately doubles.

### Example: Traversing a List

```python
numbers = [10, 20, 30, 40, 50]

for num in numbers:
    print(num)
```

**Output:**
```text
10
20
30
40
50
```

For 5 elements, the loop executes 5 times.

For 100 elements, the loop executes 100 times.

For `n` elements, the loop executes `n` times.

**Time Complexity: O(n)**

### Another Example: Finding Maximum

```python
numbers = [10, 50, 20, 80, 30]

largest = numbers[0]

for num in numbers:
    if num > largest:
        largest = num

print(largest)
```

**Output:**
```text
80
```

Every element must be checked.

**Time Complexity: O(n)**

**Real-world examples:**
- Linear Search.
- Traversing an array.
- Finding the maximum or minimum element.
- Calculating the sum of a list.

---

## 5. O(n log n) – Linearithmic Time

Linearithmic time commonly occurs in efficient sorting algorithms.

It combines linear processing with logarithmic division.

### Example: Merge Sort

Merge Sort divides an array into smaller parts, sorts them and merges the results.

```python
def merge_sort(arr):

    if len(arr) <= 1:
        return arr

    mid = len(arr) // 2

    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])

    return merge(left, right)


def merge(left, right):

    result = []

    i = j = 0

    while i < len(left) and j < len(right):

        if left[i] < right[j]:
            result.append(left[i])
            i += 1

        else:
            result.append(right[j])
            j += 1

    result.extend(left[i:])
    result.extend(right[j:])

    return result


numbers = [50, 20, 40, 10, 30]

print(merge_sort(numbers))
```

**Output:**
```text
[10, 20, 30, 40, 50]
```

### How does it work?

- The array is repeatedly divided into two halves.
- There are approximately `log n` levels of division.
- At each level, merging processes approximately `n` elements.

Therefore:

**Time Complexity: O(n log n)**

**Real-world examples:**
- Merge Sort.
- Heap Sort.
- Average-case Quick Sort.

---

## 6. O(n²) – Quadratic Time

Quadratic time usually occurs when a loop executes inside another loop, and both depend on the same input size.

### Example: Nested Loops

```python
numbers = [1, 2, 3, 4]

for i in numbers:

    for j in numbers:
        print(i, j)
```

**Output:**
```text
1 1
1 2
1 3
1 4
2 1
2 2
2 3
2 4
3 1
3 2
3 3
3 4
4 1
4 2
4 3
4 4
```

### How does it work?

- Outer loop executes 4 times.
- Inner loop executes 4 times for every outer iteration.
- Total operations = 4 × 4 = 16.

For `n` elements:

Total operations = `n × n = n²`

**Time Complexity: O(n²)**

### Another Example: Bubble Sort

```python
def bubble_sort(numbers):

    n = len(numbers)

    for i in range(n):

        for j in range(0, n - i - 1):

            if numbers[j] > numbers[j + 1]:

                numbers[j], numbers[j + 1] = numbers[j + 1], numbers[j]

    return numbers


numbers = [5, 2, 8, 1, 3]

print(bubble_sort(numbers))
```

**Output:**
```text
[1, 2, 3, 5, 8]
```

Worst-case time complexity: **O(n²)**

**Real-world examples:**
- Bubble Sort (worst case).
- Selection Sort.
- Comparing every element with every other element.

## 7. Comparison of Time Complexities

| Complexity | Name | Example |
|---|---|---|
| O(1) | Constant | Array indexing |
| O(log n) | Logarithmic | Binary Search |
| O(n) | Linear | Linear Search |
| O(n log n) | Linearithmic | Merge Sort |
| O(n²) | Quadratic | Bubble Sort |

### Order of Efficiency

From generally faster growth to slower growth:

```text
O(1)
  ↓
O(log n)
  ↓
O(n)
  ↓
O(n log n)
  ↓
O(n²)
```

## 9. Important Rules to Remember

**Rule 1: Single Loop**

```python
for i in range(n):
    print(i)
```

Complexity: O(n)

**Rule 2: Nested Loops**

```python
for i in range(n):
    for j in range(n):
        print(i, j)
```

Complexity: O(n²)

**Rule 3: Two Independent Loops**

```python
for i in range(n):
    print(i)

for j in range(n):
    print(j)
```

Complexity: O(n + n) = O(n)

**Rule 4: Loop Dividing by Two**

```python
while n > 1:
    n //= 2
```

Complexity: O(log n)

**Rule 5: Loop Followed by Nested Loop**

```python
for i in range(n):
    print(i)

for i in range(n):
    for j in range(n):
        print(i, j)
```

Complexity: O(n + n²) = O(n²)

## Key Takeaways

- O(1): Constant number of operations.
- O(log n): Repeatedly reduces the input size.
- O(n): Processes each element once.
- O(n log n): Common in efficient sorting algorithms.
- O(n²): Commonly occurs with nested loops.
- Always analyze how the number of operations changes when input size increases.
