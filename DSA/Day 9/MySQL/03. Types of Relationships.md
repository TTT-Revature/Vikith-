
# Types of Relationships in Database Design

## 1. What is a Relationship?

A relationship describes how two or more entities are associated with each other in a database.

In a relational database, relationships connect tables using Primary Keys and Foreign Keys.

### Real-world Examples

- A customer places orders.
- An employee works in a department.
- A student enrolls in courses.
- A person owns a passport.

Relationships help organize data and avoid unnecessary duplication.

---

## 2. Types of Relationships

There are three major types of relationships in relational database design:

1. One-to-One (1:1)
2. One-to-Many (1:M)
3. Many-to-Many (M:N)

---

# 3. One-to-One Relationship (1:1)

A One-to-One relationship means one record in Table A is associated with only one record in Table B, and vice versa.

### Real-world Example

Consider a Person and Passport.

- One person has one passport.
- One passport belongs to one person.

### ER Diagram

```text
+----------------+       +----------------+
|     Person     |       |    Passport    |
+----------------+       +----------------+
| person_id (PK) |  1:1  | passport_id(PK)|
| name           |-------| person_id (FK) |
| age            |       | passport_no    |
+----------------+       +----------------+
```

### SQL Implementation

Create the Person table:

```sql
CREATE TABLE Person (
    person_id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT
);
```

Create the Passport table:

```sql
CREATE TABLE Passport (
    passport_id INT PRIMARY KEY,
    person_id INT UNIQUE,
    passport_no VARCHAR(20),

    FOREIGN KEY (person_id)
        REFERENCES Person(person_id)
);
```

### Why UNIQUE?

The `UNIQUE` constraint ensures that the same person_id cannot appear multiple times in the Passport table.

Without UNIQUE, one person could have multiple passport records in this table.

### Insert Records

```sql
INSERT INTO Person VALUES
(1, 'Rahul', 25),
(2, 'Priya', 23);

INSERT INTO Passport VALUES
(101, 1, 'P12345'),
(102, 2, 'P67890');
```

### Output

Person Table:

| person_id | name | age |
|---|---|---|
| 1 | Rahul | 25 |
| 2 | Priya | 23 |

Passport Table:

| passport_id | person_id | passport_no |
|---|---|---|
| 101 | 1 | P12345 |
| 102 | 2 | P67890 |

### Important Points

- One record corresponds to one record in the other table.
- A Foreign Key establishes the relationship.
- UNIQUE enforces the one-to-one restriction on the foreign key.
- NOT NULL can be added if every passport must belong to a person.

# 4. One-to-Many Relationship (1:M)

A One-to-Many relationship means one record in Table A can be associated with multiple records in Table B.

However, each record in Table B is associated with only one record in Table A.

### Real-world Example

Consider a Department and Employees.

- One department can have many employees.
- Each employee belongs to one department.

### ER Diagram

```text
+---------------------+
|     Department      |
+---------------------+
| department_id (PK)  |
| department_name     |
+---------------------+
           |
           | 1
           |
           | M
           |
+---------------------+
|      Employees      |
+---------------------+
| employee_id (PK)    |
| employee_name       |
| department_id (FK)  |
+---------------------+
```

### SQL Implementation

Create the Departments table:

```sql
CREATE TABLE Departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(50)
);
```

Create the Employees table:

```sql
CREATE TABLE Employees (
    employee_id INT PRIMARY KEY,
    employee_name VARCHAR(50),
    salary DECIMAL(10,2),
    department_id INT,

    FOREIGN KEY (department_id)
        REFERENCES Departments(department_id)
);
```

### Insert Records

```sql
INSERT INTO Departments VALUES
(101, 'IT'),
(102, 'HR'),
(103, 'Finance');

INSERT INTO Employees VALUES
(1, 'Rahul', 45000, 101),
(2, 'Priya', 50000, 101),
(3, 'Amit', 40000, 102),
(4, 'Sneha', 55000, 103),
(5, 'Arjun', 60000, 101);
```

### Departments Table

| department_id | department_name |
|---|---|
| 101 | IT |
| 102 | HR |
| 103 | Finance |

### Employees Table

| employee_id | employee_name | salary | department_id |
|---|---|---|---|
| 1 | Rahul | 45000 | 101 |
| 2 | Priya | 50000 | 101 |
| 3 | Amit | 40000 | 102 |
| 4 | Sneha | 55000 | 103 |
| 5 | Arjun | 60000 | 101 |

### Understanding the Relationship

Department 101 (IT) has three employees:

- Rahul
- Priya
- Arjun

Department 102 (HR) has one employee:

- Amit

Department 103 (Finance) has one employee:

- Sneha

### Important Points

- One parent record can have multiple child records.
- The Foreign Key is placed in the Many-side table.
- Multiple employees can share the same department_id.
- The department_id references a valid department.

# 5. Many-to-Many Relationship (M:N)

A Many-to-Many relationship means multiple records in Table A can be associated with multiple records in Table B.

### Real-world Example

Consider Students and Courses.

- One student can enroll in multiple courses.
- One course can have multiple students.

### ER Diagram

```text
+------------------+       +------------------+
|     Students     |       |     Courses      |
+------------------+       +------------------+
| student_id (PK)  |       | course_id (PK)   |
| student_name     |       | course_name      |
+------------------+       +------------------+
         |                         |
         | 1                       | 1
         |                         |
         | M                       | M
         +----------+--------------+
                    |
           +-------------------+
           |    Enrollment     |
           +-------------------+
           | enrollment_id(PK) |
           | student_id (FK)   |
           | course_id (FK)    |
           +-------------------+
```

### Why Do We Need a Junction Table?

In relational databases, a Many-to-Many relationship is normally implemented using an intermediate table called:

- Junction Table
- Bridge Table
- Associative Table

The Enrollment table connects Students and Courses.

### SQL Implementation

Create Students:

```sql
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(50)
);
```

Create Courses:

```sql
CREATE TABLE Courses (
    course_id INT PRIMARY KEY,
    course_name VARCHAR(50)
);
```

Create Enrollment:

```sql
CREATE TABLE Enrollment (
    enrollment_id INT PRIMARY KEY,
    student_id INT,
    course_id INT,

    FOREIGN KEY (student_id)
        REFERENCES Students(student_id),

    FOREIGN KEY (course_id)
        REFERENCES Courses(course_id),

    UNIQUE (student_id, course_id)
);
```

The UNIQUE constraint prevents the same student from being enrolled in the same course more than once.

### Insert Records

```sql
INSERT INTO Students VALUES
(1, 'Rahul'),
(2, 'Priya'),
(3, 'Amit');

INSERT INTO Courses VALUES
(101, 'Java'),
(102, 'Python'),
(103, 'SQL');

INSERT INTO Enrollment VALUES
(1, 1, 101),
(2, 1, 102),
(3, 2, 101),
(4, 2, 103),
(5, 3, 102);
```

### Students Table

| student_id | student_name |
|---|---|
| 1 | Rahul |
| 2 | Priya |
| 3 | Amit |

### Courses Table

| course_id | course_name |
|---|---|
| 101 | Java |
| 102 | Python |
| 103 | SQL |

### Enrollment Table

| enrollment_id | student_id | course_id |
|---|---|---|
| 1 | 1 | 101 |
| 2 | 1 | 102 |
| 3 | 2 | 101 |
| 4 | 2 | 103 |
| 5 | 3 | 102 |

### Understanding the Relationship

Rahul is enrolled in:

- Java
- Python

Priya is enrolled in:

- Java
- SQL

Amit is enrolled in:

- Python

Java has two students:

- Rahul
- Priya

Python has two students:

- Rahul
- Amit

SQL has one student:

- Priya

This demonstrates a Many-to-Many relationship.

# 6. Difference Between Relationship Types

| Relationship | Meaning | Example |
|---|---|---|
| One-to-One | One record relates to one record | Person - Passport |
| One-to-Many | One record relates to multiple records | Department - Employees |
| Many-to-Many | Multiple records relate to multiple records | Students - Courses |

### Where is the Foreign Key Stored?

| Relationship | Foreign Key Location |
|---|---|
| One-to-One | Usually on one side, with UNIQUE |
| One-to-Many | On the Many side |
| Many-to-Many | In an intermediate junction table |

# 7. SQL Queries to Understand Relationships

### Query 1: Display employees with department names

```sql
SELECT
    e.employee_name,
    d.department_name
FROM Employees e
INNER JOIN Departments d
ON e.department_id = d.department_id;
```

### Query 2: Display students with their courses

```sql
SELECT
    s.student_name,
    c.course_name
FROM Students s
INNER JOIN Enrollment e
ON s.student_id = e.student_id
INNER JOIN Courses c
ON e.course_id = c.course_id;
```

### Query 3: Find all courses enrolled by Rahul

```sql
SELECT
    s.student_name,
    c.course_name
FROM Students s
INNER JOIN Enrollment e
ON s.student_id = e.student_id
INNER JOIN Courses c
ON e.course_id = c.course_id
WHERE s.student_name = 'Rahul';
```

# 10. Key Takeaways

- Relationships connect entities in a database.
- One-to-One connects one record to one record.
- One-to-Many connects one parent record to multiple child records.
- Many-to-Many connects multiple records from both tables.
- Foreign Keys establish relationships.
- A UNIQUE constraint can enforce One-to-One cardinality.
- A junction table is used to implement Many-to-Many relationships.
- Relationships help organize data and maintain referential integrity.
