# Python Reading Tracebacks and Debugging

## 1. What Is a Traceback?

A traceback is an error report generated by Python when an exception occurs.

It shows:
- Where the error occurred.
- Which function calls led to the error.
- The line number responsible.
- The type of exception.
- The error message.

**Example:**

```python
def calculate():
    a = 10
    b = 0
    return a / b

calculate()
```

**Output:**

```text
Traceback (most recent call last):
  File "main.py", line 7, in <module>
    calculate()
  File "main.py", line 4, in calculate
    return a / b
ZeroDivisionError: division by zero
```

The traceback tells us that the error occurred because Python attempted to divide a number by zero.

## 2. Understanding the Structure of a Traceback

Consider this traceback:

```text
Traceback (most recent call last):
  File "main.py", line 10, in <module>
    result = calculate()
  File "main.py", line 6, in calculate
    return 10 / 0
ZeroDivisionError: division by zero
```

Understanding each part:

| Part | Meaning |
|---|---|
| `Traceback (most recent call last)` | Beginning of the error report |
| `File "main.py"` | File where execution occurred |
| `line 10` | Line number |
| `in <module>` | Code executed at the module level |
| `in calculate` | Function where execution continued |
| `ZeroDivisionError` | Exception type |
| `division by zero` | Explanation of the error |

**Important:** Read the traceback from the bottom to identify the exception type and message first. Then inspect the stack entries above it to follow how execution reached the failing code. The final stack entry normally points to where the exception was raised.

## 3. Understanding Function Calls in a Traceback

When one function calls another, Python records the call sequence.

```python
def divide(a, b):
    return a / b


def calculate():
    return divide(10, 0)


def main():
    result = calculate()
    print(result)


main()
```

**Simplified traceback:**

```text
Traceback (most recent call last):
  File "main.py", line 14, in <module>
    main()
  File "main.py", line 10, in main
    result = calculate()
  File "main.py", line 6, in calculate
    return divide(10, 0)
  File "main.py", line 2, in divide
    return a / b
ZeroDivisionError: division by zero
```

The execution flow is:

```text
main()
   |
   v
calculate()
   |
   v
divide(10, 0)
   |
   v
ZeroDivisionError
```

This helps identify which function caused the problem and how it was called.

## 4. Common Python Errors and Their Tracebacks

### SyntaxError

Occurs when Python code violates syntax rules.

```python
if 10 > 5
    print("Hello")
```

**Error:**

```text
SyntaxError: expected ':'
```

### NameError

Occurs when a variable or name is not defined.

```python
print(username)
```

**Error:**

```text
NameError: name 'username' is not defined
```

### TypeError

Occurs when an operation is performed on incompatible types.

```python
result = "10" + 5
```

**Error:**

```text
TypeError: can only concatenate str (not "int") to str
```

### ValueError

Occurs when a function receives an appropriate type but an invalid value.

```python
number = int("hello")
```

**Error:**

```text
ValueError: invalid literal for int() with base 10: 'hello'
```

### IndexError

Occurs when accessing an invalid sequence index.

```python
numbers = [10, 20, 30]
print(numbers[5])
```

**Error:**

```text
IndexError: list index out of range
```

### KeyError

Occurs when accessing a dictionary key that does not exist.

```python
student = {"name": "Vikith"}

print(student["age"])
```

**Error:**

```text
KeyError: 'age'
```

## 5. What Is Debugging?

Debugging is the process of identifying, understanding, and fixing errors in a program.

A bug is a problem that causes a program to behave incorrectly or unexpectedly.

Common types of bugs:

| Bug Type | Meaning |
|---|---|
| Syntax bug | Incorrect Python syntax |
| Runtime bug | Error occurring during execution |
| Logical bug | Program runs but produces incorrect results |

### Example of a Logical Bug

```python
price = 100
quantity = 5

total = price + quantity

print(total)
```

**Output:**

```text
105
```

The code executes without an exception, but the calculation is incorrect.

**Correct code:**

```python
price = 100
quantity = 5

total = price * quantity

print(total)
```

**Output:**

```text
500
```

Debugging is not limited to fixing exceptions. It also involves finding logical mistakes.

## 6. Debugging Using print()

The simplest debugging technique is printing variable values at different stages.

```python
def calculate_total(price, quantity):
    print("Price:", price)
    print("Quantity:", quantity)

    total = price * quantity

    print("Calculated total:", total)

    return total


result = calculate_total(100, 5)
print("Final result:", result)
```

**Output:**

```text
Price: 100
Quantity: 5
Calculated total: 500
Final result: 500
```

This helps us understand how values change during execution.

## 7. Debugging Using the pdb Module

Python provides a built-in debugger called `pdb`.

It allows us to:
- Execute code step by step.
- Inspect variable values.
- Set breakpoints.
- Follow function execution.
- Find logical errors.

**Example:**

```python
import pdb

def calculate(a, b):
    pdb.set_trace()

    result = a + b

    return result


print(calculate(10, 20))
```

When Python reaches `pdb.set_trace()`, execution pauses and opens the debugger.

### Common pdb Commands

| Command | Purpose |
|---|---|
| `n` | Execute the next line |
| `s` | Step into a function |
| `c` | Continue execution |
| `l` | Display nearby source code |
| `p variable` | Print a variable value |
| `q` | Quit the debugger |
| `h` | Display help |

**Example debugger commands:**

```text
(Pdb) n
(Pdb) p a
(Pdb) p b
(Pdb) p result
(Pdb) c
```

## 8. Debugging Using breakpoint()

Python provides the built-in `breakpoint()` function as a convenient way to start debugging.

```python
def calculate(a, b):
    breakpoint()

    result = a * b

    return result


print(calculate(10, 5))
```

When execution reaches `breakpoint()`, Python enters the configured debugger. By default, this uses `pdb`.

It is similar to:

```python
import pdb
pdb.set_trace()
```

## 9. Using Logging for Debugging

Logging is useful for understanding program execution without repeatedly adding print statements.

```python
import logging

logging.basicConfig(
    level=logging.DEBUG,
    format="%(levelname)s - %(message)s"
)

def calculate_total(price, quantity):
    logging.debug(f"Price: {price}")
    logging.debug(f"Quantity: {quantity}")

    total = price * quantity

    logging.info(f"Total calculated: {total}")

    return total


calculate_total(100, 5)
```

**Output:**

```text
DEBUG - Price: 100
DEBUG - Quantity: 5
INFO - Total calculated: 500
```

Logging is especially useful in larger applications.

## 10. Getting Traceback Information Programmatically

Python provides the built-in `traceback` module to work with traceback information.

```python
import traceback

try:
    result = 10 / 0

except ZeroDivisionError:
    traceback.print_exc()
```

**Output:**

```text
Traceback (most recent call last):
  ...
ZeroDivisionError: division by zero
```

We can also convert traceback information into a string using `format_exc()`.

```python
import traceback

try:
    result = 10 / 0

except ZeroDivisionError:
    error_details = traceback.format_exc()
    print(error_details)
```

This is useful when saving error details to a log file or reporting them.

## 11. A Systematic Debugging Process

Follow these steps when an error occurs:

1. Read the exception type and message.
2. Locate the final traceback entry.
3. Open the file and inspect the reported line.
4. Check the variables used in that line.
5. Trace the function calls if necessary.
6. Identify the root cause.
7. Correct the code.
8. Run the program again and verify the result.

## 12. Important Differences

| Concept | Purpose |
|---|---|
| Traceback | Shows the sequence of calls leading to an exception |
| Debugging | Process of finding and fixing problems |
| `print()` | Displays variable values |
| `pdb` | Interactive Python debugger |
| `breakpoint()` | Starts the configured debugger |
| `logging` | Records application events |
| `traceback` module | Retrieves and formats traceback information |


- `breakpoint()` pauses execution for debugging.
- `logging` records application events.
- The `traceback` module helps retrieve and format error details.
