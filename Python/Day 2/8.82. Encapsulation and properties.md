# Python Encapsulation and Properties

## 1. What Is Encapsulation?

Encapsulation is one of the four main principles of Object-Oriented Programming (OOP).

It means combining data (attributes) and methods into a single class and controlling how that data is accessed or modified.

It helps:
- Protect object data from unintended changes.
- Control access to attributes.
- Apply validation before modifying values.
- Keep code organized and maintainable.

**Example without encapsulation:**

```python
class BankAccount:
    def __init__(self, balance):
        self.balance = balance


account = BankAccount(10000)

account.balance = -5000

print(account.balance)
```

**Output:**

```text
-5000
```

The balance can be changed directly to an invalid value.

Encapsulation allows us to control such modifications.

## 2. Access Modifiers in Python

Python uses naming conventions to indicate the intended accessibility of attributes and methods.

There are three common categories:

1. Public
2. Protected
3. Private

### Public Attributes

Public attributes can be accessed from anywhere.

They are defined without leading underscores.

```python
class Student:
    def __init__(self, name):
        self.name = name


student1 = Student("Vikith")

print(student1.name)
```

**Output:**

```text
Vikith
```

### Protected Attributes

Protected attributes use a single leading underscore (`_`).

They indicate that an attribute is intended for internal use within the class and its subclasses.

```python
class Student:
    def __init__(self, name):
        self._name = name


student1 = Student("Vikith")

print(student1._name)
```

**Output:**

```text
Vikith
```

Python does not prevent direct access to protected attributes. The underscore is a convention.

### Private Attributes

Private attributes use two leading underscores (`__`).

Python applies name mangling to these attributes to reduce accidental access from outside the class.

```python
class Student:
    def __init__(self, name):
        self.__name = name


student1 = Student("Vikith")

print(student1.__name)
```

**Output:**

```text
AttributeError
```

The attribute cannot normally be accessed using its original name from outside the class.

### Understanding Name Mangling

Python internally transforms a private attribute name.

For example:

```python
class Student:
    def __init__(self, name):
        self.__name = name


student1 = Student("Vikith")

print(student1._Student__name)
```

**Output:**

```text
Vikith
```

Here, `__name` is transformed into `_Student__name`.

**Important:** Name mangling is not strict security or true privacy. It mainly prevents accidental name conflicts and unintended access.

## 3. Difference Between Public, Protected and Private

| Type | Naming | Intended Access |
|---|---|---|
| Public | `name` | Anywhere |
| Protected | `_name` | Internal use and subclasses |
| Private | `__name` | Internal class use through its mangled name |

## 4. Accessing Private Attributes Through Methods

Instead of directly accessing private attributes, we can provide public methods to read or modify them.

These methods are commonly called getters and setters.

```python
class Student:
    def __init__(self, name):
        self.__name = name

    def get_name(self):
        return self.__name

    def set_name(self, name):
        self.__name = name


student1 = Student("Vikith")

print(student1.get_name())

student1.set_name("Rahul")

print(student1.get_name())
```

**Output:**

```text
Vikith
Rahul
```

Here:
- `__name` is a private attribute.
- `get_name()` retrieves its value.
- `set_name()` modifies its value.

## 5. What Are Properties in Python?

Properties allow us to access methods like attributes.

Python provides the `@property` decorator to create a getter.

Properties are useful because they allow us to control attribute access without changing how the attribute is used.

**Example:**

```python
class Student:
    def __init__(self, name):
        self.__name = name

    @property
    def name(self):
        return self.__name


student1 = Student("Vikith")

print(student1.name)
```

**Output:**

```text
Vikith
```

Notice:

```python
student1.name
```

We access the property like an attribute, not like a method.

Python internally calls the `name()` getter.

## 6. Using @property as a Getter

A getter retrieves the value of an attribute.

```python
class Employee:
    def __init__(self, salary):
        self.__salary = salary

    @property
    def salary(self):
        return self.__salary


emp1 = Employee(30000)

print(emp1.salary)
```

**Output:**

```text
30000
```

The `@property` decorator makes the method behave like a read-only attribute.

## 7. Using @property.setter

A setter allows us to modify a property while applying validation.

**Syntax:**

```python
@property
def attribute(self):
    return self.__attribute

@attribute.setter
def attribute(self, value):
    # Validation
    self.__attribute = value
```

**Example:**

```python
class Employee:
    def __init__(self, salary):
        self.__salary = salary

    @property
    def salary(self):
        return self.__salary

    @salary.setter
    def salary(self, value):
        if value < 0:
            raise ValueError("Salary cannot be negative")

        self.__salary = value


emp1 = Employee(30000)

print(emp1.salary)

emp1.salary = 40000

print(emp1.salary)
```

**Output:**

```text
30000
40000
```

If we try:

```python
emp1.salary = -5000
```

**Output:**

```text
ValueError: Salary cannot be negative
```

The setter validates the value before updating the private attribute.

## 8. Using @property.deleter

Python also provides a deleter to control deletion of a property.

```python
class Student:
    def __init__(self, name):
        self.__name = name

    @property
    def name(self):
        return self.__name

    @name.deleter
    def name(self):
        del self.__name


student1 = Student("Vikith")

print(student1.name)

del student1.name
```

**Output:**

```text
Vikith
```

After deletion, accessing `student1.name` raises an `AttributeError` because the underlying attribute no longer exists.

## 9. Complete Example: Bank Account Using Encapsulation and Properties

```python
class BankAccount:

    def __init__(self, account_holder, balance):
        self.account_holder = account_holder
        self.__balance = balance

    @property
    def balance(self):
        return self.__balance

    @balance.setter
    def balance(self, amount):
        if amount < 0:
            raise ValueError("Balance cannot be negative")

        self.__balance = amount

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Deposit must be positive")

        self.__balance += amount

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("Withdrawal must be positive")

        if amount > self.__balance:
            raise ValueError("Insufficient balance")

        self.__balance -= amount


account = BankAccount("Vikith", 10000)

print("Balance:", account.balance)

account.deposit(2000)
print("After deposit:", account.balance)

account.withdraw(3000)
print("After withdrawal:", account.balance)
```

**Output:**

```text
Balance: 10000
After deposit: 12000
After withdrawal: 9000
```

The private balance is controlled through methods and a property setter.

## 10. Property vs Getter and Setter Methods

| Getter and Setter Methods | Properties |
|---|---|
| Use separate method calls | Accessed like attributes |
| Example: `get_salary()` | Example: `salary` |
| Example: `set_salary(40000)` | Example: `salary = 40000` |
| Explicit method-based access | Attribute-style access |
| Can require changing calling code when introduced later | Can preserve attribute-style access while adding validation |

Both approaches can be useful. Properties are especially convenient when you want attribute-style access with controlled behavior.

## 11. Important Points

- Encapsulation combines data and related methods inside a class.
- Public attributes have no leading underscore.
- Protected attributes use one leading underscore.
- Private attributes use two leading underscores.
- Python uses name mangling for double-underscore attributes.
- Python does not enforce strict private or protected access.
- `@property` creates a getter.
- `@attribute.setter` creates a setter.
- `@attribute.deleter` creates a deleter.
- Properties allow validation when accessing or modifying attributes.
- Avoid using private naming as a substitute for actual security controls.

## 12. Real-World Use Cases

| Situation | Encapsulation technique |
|---|---|
| Bank account balance | Private attribute and validation |
| Employee salary | Property setter |
| Student marks | Validate marks before updating |
| Product price | Prevent negative values |
| User profile | Control attribute modification |
| Application configuration | Restrict unintended changes |

## Quick Summary

- **Encapsulation:** Combines data and methods and controls access.
- **Public:** `name`
- **Protected:** `_name`
- **Private:** `__name`
- **Name mangling:** Transforms double-underscore attribute names.
- **Getter:** Retrieves an attribute value.
- **Setter:** Updates an attribute with validation.
- **`@property`:** Provides attribute-style access to a getter.
- **`@property.setter`:** Controls attribute modification.
- **`@property.deleter`:** Controls attribute deletion.
