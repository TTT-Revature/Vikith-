# Function Documentation and Type Hints

## 1. Function Documentation

Function documentation explains what a function does, what arguments it accepts, and what it returns.

Python uses **docstrings** to document functions.

A docstring is a string written as the first statement inside a function.

### Example

```python
def greet():
    """Display a greeting message."""
    print("Hello, Python!")

greet()
```

**Output:**

```text
Hello, Python!
```

## 2. Accessing Docstrings

Python provides the `__doc__` attribute to access a function's docstring.

```python
def add(a, b):
    """Return the sum of two numbers."""
    return a + b

print(add.__doc__)
```

**Output:**

```text
Return the sum of two numbers.
```

We can also use the built-in `help()` function.

```python
help(add)
```

It displays the function's documentation in the terminal.

## 3. Writing Multi-Line Docstrings

For functions with multiple parameters or complex logic, use multi-line docstrings.

```python
def calculate_area(length, width):
    """
    Calculate the area of a rectangle.

    Args:
        length: Length of the rectangle.
        width: Width of the rectangle.

    Returns:
        The calculated area.
    """
    return length * width

print(calculate_area(10, 5))
```

**Output:**

```text
50
```

### Common Docstring Sections

| Section | Purpose |
|---|---|
| Description | Explains what the function does |
| Args | Describes function parameters |
| Returns | Describes the returned value |
| Raises | Documents exceptions that may occur |
| Examples | Shows how to use the function |

The exact format depends on the documentation style used by a project.

## 4. Type Hints

Type hints specify the expected types of function parameters and return values.

They make code easier to understand and help IDEs and static type checkers identify possible type errors.

### Example Without Type Hints

```python
def add(a, b):
    return a + b
```

It is not immediately clear what types `a` and `b` should have.

### Example With Type Hints

```python
def add(a: int, b: int) -> int:
    return a + b

print(add(10, 20))
```

**Output:**

```text
30
```

Explanation:

- `a: int` means `a` is expected to be an integer.
- `b: int` means `b` is expected to be an integer.
- `-> int` indicates that the function is expected to return an integer.

**Important:** Python does not automatically enforce type hints at runtime. They are mainly used by developers, IDEs, and static type checkers.

## 5. Type Hints for Different Data Types

### Integer

```python
def square(number: int) -> int:
    return number * number

print(square(5))
```

**Output:**

```text
25
```

### String

```python
def greet(name: str) -> str:
    return "Hello " + name

print(greet("Vikith"))
```

**Output:**

```text
Hello Vikith
```

### Float

```python
def calculate_price(price: float) -> float:
    return price * 1.18

print(calculate_price(100.0))
```

**Output:**

```text
118.0
```

### Boolean

```python
def is_adult(age: int) -> bool:
    return age >= 18

print(is_adult(24))
```

**Output:**

```text
True
```

## 6. Type Hints for Collections

Python supports type hints for lists, tuples, sets, and dictionaries.

Modern Python supports built-in collection generics such as `list[int]` and `dict[str, int]`.

### List

```python
def calculate_total(numbers: list[int]) -> int:
    return sum(numbers)

print(calculate_total([10, 20, 30]))
```

**Output:**

```text
60
```

### Tuple

```python
def get_student() -> tuple[str, int]:
    return ("Vikith", 24)

print(get_student())
```

**Output:**

```text
('Vikith', 24)
```

### Set

```python
def get_unique_numbers(numbers: set[int]) -> set[int]:
    return numbers

print(get_unique_numbers({10, 20, 30}))
```

**Output:**

```text
{10, 20, 30}
```

### Dictionary

```python
def get_student() -> dict[str, int]:
    return {"Maths": 90, "Python": 95}

print(get_student())
```

**Output:**

```text
{'Maths': 90, 'Python': 95}
```

## 7. Optional Values and Union Types

Sometimes a function can accept more than one type or return `None`.

Use `|` to specify a union of types.

### Union Type

```python
def display(value: int | str) -> None:
    print(value)

display(100)
display("Python")
```

**Output:**

```text
100
Python
```

Here, `value` can be either an integer or a string.

### Optional Return Value

```python
def find_user(user_id: int) -> str | None:
    if user_id == 1:
        return "Vikith"

    return None

print(find_user(1))
print(find_user(2))
```

**Output:**

```text
Vikith
None
```

`str | None` means the function can return either a string or `None`.

## 8. Default Arguments with Type Hints

Type hints can also be used with default parameter values.

```python
def greet(name: str = "Guest") -> str:
    return "Hello " + name

print(greet())
print(greet("Vikith"))
```

**Output:**

```text
Hello Guest
Hello Vikith
```

## 9. Combining Docstrings and Type Hints

Using both makes functions easier to understand and maintain.

```python
def calculate_discount(price: float, discount: float) -> float:
    """
    Calculate the discounted price.

    Args:
        price: Original product price.
        discount: Discount percentage.

    Returns:
        Final price after applying the discount.
    """
    return price - (price * discount / 100)


result = calculate_discount(1000.0, 10.0)
print(result)
```

**Output:**

```text
900.0
```

## 10. Type Hints vs Docstrings

| Feature | Type Hints | Docstrings |
|---|---|---|
| Purpose | Specify expected data types | Explain function behavior |
| Syntax | `name: str` | Triple-quoted string |
| Return information | `-> int` | Returns section |
| Helps IDEs | Yes | Provides documentation |
| Runtime enforcement | No, not by default | No |
| Main benefit | Type clarity | Code understanding |

## 11. Complete Example

```python
def calculate_average(numbers: list[int]) -> float:
    """
    Calculate the average of a list of numbers.

    Args:
        numbers: A list of integer values.

    Returns:
        The average as a float.

    Raises:
        ZeroDivisionError: If the list is empty.
    """
    return sum(numbers) / len(numbers)


marks = [80, 90, 85, 95]

average = calculate_average(marks)

print("Average:", average)
print(calculate_average.__doc__)
```

**Output:**

```text
Average: 87.5

    Calculate the average of a list of numbers.

    Args:
        numbers: A list of integer values.

    Returns:
        The average as a float.

    Raises:
        ZeroDivisionError: If the list is empty.
```

## 12. Important Points

- A docstring documents a function, class, or module.
- Use triple quotes (`"""`) for docstrings.
- A docstring must be the first statement inside the function to be recognized as its documentation.
- Use `__doc__` or `help()` to access documentation.
- Type hints specify expected parameter and return types.
- Use `-> None` when a function is not intended to return a meaningful value.
- Type hints do not enforce types automatically at runtime.
- Docstrings explain what the function does; type hints explain the expected data types.

## 13. Real-World Use Cases

- **Team development:** Help other developers understand functions.
- **API development:** Document expected inputs and outputs.
- **IDE support:** Get better autocomplete and type information.
- **Code maintenance:** Understand existing functions without reading every implementation detail.
- **Static type checking:** Tools such as mypy can identify potential type-related errors before execution.
