# Python Logging and Log Levels

## 1. What Is Logging?

Logging is the process of recording messages about what happens during program execution.

It helps developers:
- Identify errors.
- Debug applications.
- Monitor program execution.
- Track warnings and important events.
- Understand application behavior.

Python provides a built-in `logging` module for logging messages.

## 2. Logging vs print()

Both `print()` and logging can display messages, but they serve different purposes.

| print() | logging |
|---|---|
| Displays messages | Records application events |
| Mainly used for simple output | Used for debugging and monitoring |
| No built-in severity levels | Provides multiple log levels |
| No built-in file logging | Can write logs to files |
| Limited configuration | Supports formatting and configuration |

**Example using print():**

```python
print("Application started")
print("An error occurred")
```

**Example using logging:**

```python
import logging

logging.warning("Application started")
logging.error("An error occurred")
```

## 3. Importing the Logging Module

Python provides the `logging` module in its standard library. No installation is required.

```python
import logging
```

The simplest way to create a log message is:

```python
import logging

logging.warning("This is a warning message")
```

**Output:**

```text
WARNING:root:This is a warning message
```

Here:
- `WARNING` is the log level.
- `root` is the default logger name.
- The remaining text is the log message.

## 4. Logging Levels

Python provides five standard logging levels.

| Level | Numeric Value | Purpose |
|---|---:|---|
| `DEBUG` | 10 | Detailed information for debugging |
| `INFO` | 20 | General information about execution |
| `WARNING` | 30 | Something unexpected may happen |
| `ERROR` | 40 | A problem occurred |
| `CRITICAL` | 50 | A serious problem that may stop the application |

### DEBUG

Used for detailed information during development.

```python
logging.debug("Variable value is 100")
```

### INFO

Used to confirm that something is working normally.

```python
logging.info("Application started successfully")
```

### WARNING

Used when something unexpected happens, but the application can continue.

```python
logging.warning("Disk space is getting low")
```

### ERROR

Used when an operation fails.

```python
logging.error("Unable to connect to database")
```

### CRITICAL

Used for serious errors that may prevent the application from continuing.

```python
logging.critical("Application cannot continue")
```

## 5. Understanding the Default Logging Level

By default, Python's root logger displays messages at `WARNING` level and above.

```python
import logging

logging.debug("Debug message")
logging.info("Information message")
logging.warning("Warning message")
logging.error("Error message")
logging.critical("Critical message")
```

**Output:**

```text
WARNING:root:Warning message
ERROR:root:Error message
CRITICAL:root:Critical message
```

`DEBUG` and `INFO` are not displayed because they are below the default logging threshold.

## 6. Configuring Logging Using basicConfig()

The `basicConfig()` function configures the logging system.

It can set:
- Minimum logging level.
- Output format.
- Log file.
- File mode.
- Date and time format.

**Example:**

```python
import logging

logging.basicConfig(level=logging.DEBUG)

logging.debug("Debug message")
logging.info("Information message")
logging.warning("Warning message")
logging.error("Error message")
logging.critical("Critical message")
```

**Output:**

```text
DEBUG:root:Debug message
INFO:root:Information message
WARNING:root:Warning message
ERROR:root:Error message
CRITICAL:root:Critical message
```

## 7. Logging to a File

Instead of displaying logs in the terminal, we can save them in a file.

```python
import logging

logging.basicConfig(
    filename="application.log",
    level=logging.DEBUG
)

logging.info("Application started")
logging.warning("Low disk space")
logging.error("Database connection failed")
```

The messages are stored in `application.log`.

**Example file content:**

```text
INFO:root:Application started
WARNING:root:Low disk space
ERROR:root:Database connection failed
```

## 8. Formatting Log Messages

We can customize how log messages appear using the `format` parameter.

```python
import logging

logging.basicConfig(
    level=logging.DEBUG,
    format="%(asctime)s - %(levelname)s - %(message)s"
)

logging.info("Application started")
logging.error("Something went wrong")
```

**Example output:**

```text
2026-11-17 10:30:15,123 - INFO - Application started
2026-11-17 10:30:15,124 - ERROR - Something went wrong
```

The timestamp shown is an example; the actual value depends on execution time.

### Common Formatting Attributes

| Attribute | Meaning |
|---|---|
| `%(asctime)s` | Date and time |
| `%(levelname)s` | Logging level name |
| `%(message)s` | Actual log message |
| `%(name)s` | Logger name |
| `%(filename)s` | Source filename |
| `%(lineno)d` | Line number |
| `%(funcName)s` | Function name |
| `%(process)d` | Process ID |
| `%(thread)d` | Thread ID |

## 9. Logging with Date and Time Format

We can customize the timestamp using `datefmt`.

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s - %(levelname)s - %(message)s",
    datefmt="%d-%m-%Y %H:%M:%S"
)

logging.info("User logged in")
```

**Example output:**

```text
17-11-2026 10:30:15 - INFO - User logged in
```

## 10. Logging Exceptions Using exception()

The `logging.exception()` method records an error message along with the exception traceback.

It should normally be called inside an `except` block.

```python
import logging

logging.basicConfig(level=logging.ERROR)

try:
    result = 10 / 0

except ZeroDivisionError:
    logging.exception("Division failed")
```

**Example output:**

```text
ERROR:root:Division failed
Traceback (most recent call last):
  ...
ZeroDivisionError: division by zero
```

The traceback helps identify where the exception occurred.

## 11. Using a Named Logger

Instead of always using the default root logger, we can create our own logger using `getLogger()`.

```python
import logging

logger = logging.getLogger("MyApplication")

logging.basicConfig(level=logging.DEBUG)

logger.info("Application started")
logger.warning("Low memory")
logger.error("Connection failed")
```

**Example output:**

```text
INFO:MyApplication:Application started
WARNING:MyApplication:Low memory
ERROR:MyApplication:Connection failed
```

Named loggers are useful for organizing logs in larger applications.

## 12. Logging to Both Console and File

A logger can send messages to multiple destinations using handlers.

- `StreamHandler` sends logs to the console.
- `FileHandler` sends logs to a file.

```python
import logging

logger = logging.getLogger("Application")
logger.setLevel(logging.DEBUG)

console_handler = logging.StreamHandler()

file_handler = logging.FileHandler("application.log")

formatter = logging.Formatter(
    "%(asctime)s - %(levelname)s - %(message)s"
)

console_handler.setFormatter(formatter)
file_handler.setFormatter(formatter)

logger.addHandler(console_handler)
logger.addHandler(file_handler)

logger.info("Application started")
logger.error("An error occurred")
```

The messages are sent to both the console and `application.log`.

## 13. Logging Levels vs Logger Methods

Each logging level has a corresponding method.

| Method | Purpose |
|---|---|
| `logging.debug()` | Record debug messages |
| `logging.info()` | Record informational messages |
| `logging.warning()` | Record warnings |
| `logging.error()` | Record errors |
| `logging.critical()` | Record critical errors |
| `logging.exception()` | Record an error with traceback |
| `logging.log()` | Record a message at a specified level |

**Example using log():**

```python
import logging

logging.basicConfig(level=logging.DEBUG)

logging.log(logging.INFO, "User logged in")
logging.log(logging.ERROR, "Database failed")
```

## 14. Important Points

- Python provides logging through the built-in `logging` module.
- The default logging level is `WARNING`.
- `basicConfig()` configures basic logging settings.
- `filename` specifies a file for storing logs.
- `format` controls the structure of log messages.
- `datefmt` controls timestamp formatting.
- `getLogger()` creates or retrieves a named logger.
- Handlers determine where log messages are sent.
- `logging.exception()` includes traceback information.
- `basicConfig()` generally has no effect once the root logger has handlers configured, unless `force=True` is used.

## 15. Real-World Use Cases

| Situation | Logging level |
|---|---|
| Tracking variable values | DEBUG |
| Application startup | INFO |
| Low disk space | WARNING |
| Database connection failure | ERROR |
| Critical application failure | CRITICAL |
| Recording exception traceback | EXCEPTION |

## Quick Summary

- `DEBUG` → Detailed debugging information.
- `INFO` → Normal application events.
- `WARNING` → Unexpected situations.
- `ERROR` → Operation failures.
- `CRITICAL` → Serious application failures.
- `basicConfig()` → Configure logging.
- `getLogger()` → Create or retrieve a named logger.
- `FileHandler` → Save logs to a file.
- `StreamHandler` → Display logs in the console.
- `logging.exception()` → Log an exception with its traceback.
