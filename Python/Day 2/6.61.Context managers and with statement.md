# Python Context Managers and With Statement

## 1. What Is a Context Manager?

A context manager is an object that manages resources automatically.

It handles two important operations:

1. Setup – Prepare a resource before using it.
2. Cleanup – Release the resource after using it.

Examples of resources:

- Files
- Database connections
- Network connections
- Locks in multithreading

Python uses the `with` statement to work with context managers.

## 2. Understanding the with Statement

The `with` statement automatically manages resources and ensures cleanup.

**Syntax:**

```python
with expression as variable:
    # Perform operations
```

### Example: Opening a File

```python
with open("sample.txt", "r") as file:
    content = file.read()
    print(content)
```

**Output:**

```text
Hello Python
Welcome to File Handling
```

What happens internally?

1. Python opens the file.
2. The file object is assigned to `file`.
3. The statements inside the block execute.
4. Python automatically closes the file when the block exits.

We don't need to call `file.close()` manually.

## 3. Without with vs With with

### Without with

```python
file = open("sample.txt", "r")

try:
    content = file.read()
    print(content)

finally:
    file.close()
```

Here, we manually ensure that the file is closed using `finally`.

### With with

```python
with open("sample.txt", "r") as file:
    content = file.read()
    print(content)
```

Python automatically handles the cleanup.

**Important:** The `with` statement also performs cleanup when an exception occurs inside the block.

## 4. How Does a Context Manager Work Internally?

A context manager generally implements two special methods:

| Method | Purpose |
|---|---|
| `__enter__()` | Executes when entering the `with` block |
| `__exit__()` | Executes when leaving the `with` block |

### Understanding __enter__()

- Runs when the `with` statement begins.
- Performs setup operations.
- Its return value is assigned to the variable after `as`.

### Understanding __exit__()

- Runs when the `with` block finishes.
- Performs cleanup operations.
- Also runs when an exception occurs inside the block.

## 5. Creating Our Own Context Manager Using a Class

We can create a custom context manager by defining `__enter__()` and `__exit__()`.

### Example

```python
class MyContext:
    def __enter__(self):
        print("Entering the context")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("Exiting the context")


with MyContext() as obj:
    print("Inside the with block")
```

**Output:**

```text
Entering the context
Inside the with block
Exiting the context
```

### Understanding the Execution

1. `MyContext()` creates an object.
2. `__enter__()` executes.
3. Its returned object is assigned to `obj`.
4. The code inside the `with` block executes.
5. `__exit__()` executes when the block finishes.

## 6. Understanding the Parameters of __exit__()

The `__exit__()` method receives three arguments related to an exception.

```python
def __exit__(self, exc_type, exc_value, traceback):
    pass
```

| Parameter | Meaning |
|---|---|
| `exc_type` | Type of exception |
| `exc_value` | Exception object or message |
| `traceback` | Traceback information |

If no exception occurs, all three values are `None`.

### Example: Handling an Exception

```python
class MyContext:
    def __enter__(self):
        print("Entering context")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("Exiting context")

        if exc_type:
            print("Exception:", exc_type.__name__)
            print("Message:", exc_value)

        return False


with MyContext():
    print("Inside context")
    result = 10 / 0
```

**Output:**

```text
Entering context
Inside context
Exiting context
Exception: ZeroDivisionError
Message: division by zero
```

The exception is still raised after `__exit__()` finishes because it returns `False`.

**Important:**

- Returning `True` suppresses the exception.
- Returning `False` or `None` allows the exception to propagate.
- `__exit__()` is called when the block exits, including during exception handling.

## 7. Creating Context Managers Using contextlib

Python provides a built-in module called `contextlib`.

It allows us to create context managers using a generator function and the `@contextmanager` decorator.

### Example

```python
from contextlib import contextmanager

@contextmanager
def my_context():
    print("Entering context")

    yield

    print("Exiting context")


with my_context():
    print("Inside with block")
```

**Output:**

```text
Entering context
Inside with block
Exiting context
```

### Understanding yield

The `yield` statement separates setup and cleanup operations.

- Code before `yield` runs when entering the context.
- The `with` block executes when the generator is paused at `yield`.
- Code after `yield` runs when the context exits.

## 8. Practical Example: Managing a File

We can create our own context manager to manage a file.

```python
class FileManager:
    def __init__(self, filename, mode):
        self.filename = filename
        self.mode = mode

    def __enter__(self):
        print("Opening file")
        self.file = open(self.filename, self.mode)
        return self.file

    def __exit__(self, exc_type, exc_value, traceback):
        print("Closing file")
        self.file.close()


with FileManager("sample.txt", "w") as file:
    file.write("Hello Python")
```

**Output:**

```text
Opening file
Closing file
```

The file is automatically closed when the `with` block exits.

## 9. Multiple Context Managers

We can use multiple context managers in a single `with` statement.

### Example

```python
with open("input.txt", "r") as source, open("output.txt", "w") as destination:
    content = source.read()
    destination.write(content)
```

This reads content from one file and writes it into another file.

Both files are automatically closed when the block exits.

## 10. Important Context Manager Methods

| Method / Tool | Purpose |
|---|---|
| `__enter__()` | Performs setup |
| `__exit__()` | Performs cleanup |
| `with` | Uses a context manager |
| `@contextmanager` | Creates a context manager from a generator |
| `yield` | Separates setup and cleanup in a generator context manager |
| `contextlib` | Provides utilities for context management |

## 11. Context Manager vs Normal File Handling

| Feature | Normal File Handling | Context Manager |
|---|---|---|
| Opening | `open()` | `with open()` |
| Closing | Manually using `close()` | Automatically |
| Exception cleanup | Requires careful handling | Handled automatically |
| Resource management | Manual | Automatic |
| Recommended | Less preferred | Yes |
