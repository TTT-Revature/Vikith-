
# Python Shallow Copy, Deep Copy and Garbage Collection

## 1. Introduction

Python manages objects in memory automatically. Understanding how objects are copied and removed from memory helps prevent unexpected changes and unnecessary memory usage.

Three important concepts are:

- **Shallow Copy:** Creates a new outer object but shares nested objects.
- **Deep Copy:** Recursively copies nested objects.
- **Garbage Collection:** Reclaims memory occupied by objects that are no longer needed.

## 2. Assignment vs Copying

Assigning one variable to another does not create a new object.

```python
original = [10, 20, 30]

copied = original

copied.append(40)

print(original)
print(copied)
print(original is copied)
```

**Output:**
```text
[10, 20, 30, 40]
[10, 20, 30, 40]
True
```

Both variables refer to the same list object.

```text
original ──┐
           ├──> [10, 20, 30, 40]
copied ────┘
```

## 3. Shallow Copy

A shallow copy creates a new outer object but does not recursively copy nested objects.

### Using `copy.copy()`

```python
import copy

original = [[10, 20], [30, 40]]

copied = copy.copy(original)

print(original is copied)
print(original[0] is copied[0])
```

**Output:**
```text
False
True
```

**Explanation:**
- `original` and `copied` are different outer lists.
- Their nested lists are shared.
- Modifying a nested list affects both.

### Example: Modifying Nested Objects

```python
import copy

original = [[10, 20], [30, 40]]

copied = copy.copy(original)

copied[0].append(50)

print(original)
print(copied)
```

**Output:**
```text
[[10, 20, 50], [30, 40]]
[[10, 20, 50], [30, 40]]
```

Both outer lists reference the same first nested list.

### Other Ways to Create a Shallow List Copy

```python
original = [10, 20, 30]

copy1 = original.copy()
copy2 = original[:]
copy3 = list(original)

print(original is copy1)
print(original is copy2)
print(original is copy3)
```

**Output:**
```text
False
False
False
```

These methods create new outer lists. Nested mutable objects, if present, remain shared.

## 4. Deep Copy

A deep copy recursively copies nested objects.

Python provides `copy.deepcopy()` for this purpose.

```python
import copy

original = [[10, 20], [30, 40]]

copied = copy.deepcopy(original)

copied[0].append(50)

print(original)
print(copied)
```

**Output:**
```text
[[10, 20], [30, 40]]
[[10, 20, 50], [30, 40]]
```

The original nested list remains unchanged.

### Checking Object Identity

```python
import copy

original = [[1, 2], [3, 4]]

copied = copy.deepcopy(original)

print(original is copied)
print(original[0] is copied[0])
```

**Output:**
```text
False
False
```

The outer lists and their nested lists are separate objects.

**Note:** `deepcopy()` does not necessarily duplicate every object. Immutable objects may be reused, and custom classes can control copying behavior.

## 5. Shallow Copy vs Deep Copy

| Feature | Shallow Copy | Deep Copy |
|---|---|---|
| Function | `copy.copy()` | `copy.deepcopy()` |
| Outer object | New object | New object |
| Nested mutable objects | Usually shared | Recursively copied |
| Memory usage | Generally lower | Generally higher |
| Performance | Generally faster | Generally slower |
| Nested modifications | May affect original | Usually independent |

## 6. Shallow Copy with Dictionaries

```python
import copy

student = {
    "name": "John",
    "marks": [80, 90]
}

copied = copy.copy(student)

copied["marks"].append(100)
copied["name"] = "David"

print(student)
print(copied)
```

**Output:**
```text
{'name': 'John', 'marks': [80, 90, 100]}
{'name': 'David', 'marks': [80, 90, 100]}
```

The `name` assignment affects only the copied dictionary, while the shared `marks` list changes in both.

## 7. What Is Garbage Collection?

Garbage collection is Python's automatic memory management mechanism that helps reclaim memory occupied by objects that are no longer reachable or needed.

In CPython, memory management primarily uses:

1. **Reference counting**
2. **Cyclic garbage collection**

## 8. Reference Counting

Reference counting tracks how many references point to an object.

When an object's reference count reaches zero, CPython normally destroys it immediately.

```python
a = [10, 20, 30]

b = a
c = a

print(a is b)
print(b is c)

del b
del c

print(a)
```

**Output:**
```text
True
True
[10, 20, 30]
```

Deleting `b` and `c` removes those variable bindings, but the object remains accessible through `a`.

### Using `sys.getrefcount()`

```python
import sys

numbers = []

print(sys.getrefcount(numbers))
```

**Typical Output in CPython:**
```text
2
```

`sys.getrefcount()` includes a temporary reference created when passing the object to the function. The result can vary depending on the Python implementation and execution environment.

## 9. The `del` Statement

The `del` statement removes a variable binding or an item from a container.

```python
numbers = [10, 20, 30]

another = numbers

del numbers

print(another)
```

**Output:**
```text
[10, 20, 30]
```

**Important:** `del` does not necessarily destroy the object. If another reference exists, the object remains accessible.

## 10. Cyclic References

A cyclic reference occurs when objects reference each other, directly or indirectly.

Example:

```python
a = []
b = []

a.append(b)
b.append(a)

print(a[0] is b)
print(b[0] is a)
```

**Output:**
```text
True
True
```

Conceptually:

```text
Object A ───> Object B
   ^             |
   |_____________|
```

Even if the external references are removed, the objects still reference each other.

CPython's cyclic garbage collector can detect and reclaim many unreachable reference cycles.

## 11. The `gc` Module

Python provides the built-in `gc` module to interact with the cyclic garbage collector.

### Manually Triggering Garbage Collection

```python
import gc

collected = gc.collect()

print("Unreachable objects collected:", collected)
```

**Example Output:**
```text
Unreachable objects collected: 0
```

The number varies depending on the objects awaiting collection.

### Enabling and Disabling Automatic Cyclic Collection

```python
import gc

print(gc.isenabled())

gc.disable()
print(gc.isenabled())

gc.enable()
print(gc.isenabled())
```

**Output in a typical environment:**
```text
True
False
True
```

Disabling the cyclic collector does not disable CPython's reference counting.

### Checking Garbage Collection Statistics

```python
import gc

print(gc.get_count())
print(gc.get_threshold())
print(gc.get_stats())
```

These functions provide information about the collector's activity and configuration. Exact results depend on the Python version and runtime.

## 12. Garbage Collection with Cyclic Objects

```python
import gc

class Node:
    def __init__(self):
        self.reference = None


def create_cycle():
    a = Node()
    b = Node()

    a.reference = b
    b.reference = a


gc.collect()

create_cycle()

collected = gc.collect()

print("Collected:", collected)
```

**Typical CPython Output:**
```text
Collected: 2
```

The two objects form a reference cycle. After the function finishes, they are no longer reachable from outside the cycle.

The garbage collector can reclaim them. The exact collection count may vary.

## 13. Object Destruction and `__del__()`

Python classes can define a `__del__()` method, which may be called when an object is being finalized.

```python
class Student:
    def __init__(self, name):
        self.name = name

    def __del__(self):
        print("Student object finalized")


student = Student("John")

del student
```

**Typical CPython Output:**
```text
Student object finalized
```

**Important:**
- The exact timing of finalization is not guaranteed across Python implementations.
- `__del__()` is not a reliable replacement for explicit resource cleanup.
- Prefer `with` statements and context managers for files, connections, and other resources.

## 14. Important Differences

| Concept | Explanation |
|---|---|
| Assignment | Creates another reference to the same object |
| Shallow copy | Copies the outer object |
| Deep copy | Recursively copies nested objects |
| Reference counting | Tracks references to objects |
| Garbage collection | Reclaims unreachable objects |
| `del` | Removes a reference or container item |
| `gc.collect()` | Requests a garbage collection |
| `__del__()` | Defines object finalization behavior |

## 15. Real-World Use Cases

- **Data processing:** Use deep copies when modifying nested records without affecting original data.
- **Application configuration:** Use shallow copies when only top-level values need to change.
- **Memory management:** Understand object references to avoid retaining unnecessary objects.
- **Long-running applications:** Identify reference cycles and memory retention problems.
- **Resource handling:** Use context managers to release files and database connections predictably.
