

# Python `__init__.py`

## 1. What is `__init__.py`?

`__init__.py` is a special Python file used to initialize a package.

It is executed when the package is first imported.

It helps us:
- Initialize package-level variables.
- Import classes and functions from modules.
- Control what is exposed through wildcard imports using `__all__`.
- Organize package-level functionality.

## 2. Basic Package Structure

```text
my_project/
│
├── school/
│   ├── __init__.py
│   ├── student.py
│   └── teacher.py
│
└── main.py
```

Here:
- `school` is the package.
- `__init__.py` initializes the package.
- `student.py` and `teacher.py` are modules.
- `main.py` is the main application file.

## 3. How Does `__init__.py` Work?

**File: `school/__init__.py`**

```python
print("School package initialized")

school_name = "ABC School"
```

**File: `main.py`**

```python
import school

print(school.school_name)
```

**Output:**

```text
School package initialized
ABC School
```

When Python imports `school` for the first time, it executes the code inside `__init__.py`.

## 4. Importing Classes Through `__init__.py`

Instead of importing classes directly from individual modules, we can expose them through `__init__.py`.

**File: `school/student.py`**

```python
class Student:
    def __init__(self, name):
        self.name = name

    def display(self):
        print(self.name)
```

**File: `school/teacher.py`**

```python
class Teacher:
    def __init__(self, name):
        self.name = name

    def display(self):
        print(self.name)
```

**File: `school/__init__.py`**

```python
from .student import Student
from .teacher import Teacher
```

Now we can import directly from the package.

**File: `main.py`**

```python
from school import Student, Teacher

s1 = Student("Vikith")
t1 = Teacher("Rahul")

s1.display()
t1.display()
```

**Output:**

```text
Vikith
Rahul
```

The dot (`.`) represents a relative import from the current package.

## 5. Using `__all__`

`__all__` controls which names are imported when using `from package import *`.

**File: `school/__init__.py`**

```python
from .student import Student
from .teacher import Teacher

__all__ = ["Student"]
```

Now:

```python
from school import *

s1 = Student("Vikith")
s1.display()
```

**Output:**

```text
Vikith
```

`Student` is included in the wildcard import, but `Teacher` is not.

**Important:** `__all__` does not prevent explicit imports of other names.

## 6. `__init__.py` with Package Variables

You can define variables inside `__init__.py`.

```python
# school/__init__.py

SCHOOL_NAME = "ABC School"
VERSION = "1.0"
```

Access them using:

```python
import school

print(school.SCHOOL_NAME)
print(school.VERSION)
```

**Output:**

```text
ABC School
1.0
```

## 7. Nested Packages and `__init__.py`

A package can contain subpackages, and each regular subpackage can have its own `__init__.py`.

```text
company/
│
├── __init__.py
│
├── employees/
│   ├── __init__.py
│   ├── manager.py
│   └── developer.py
│
└── accounts/
    ├── __init__.py
    ├── salary.py
    └── payments.py
```

Each `__init__.py` can initialize its own package and expose selected functionality.

For example:

```python
# company/employees/__init__.py

from .manager import Manager
from .developer import Developer
```

Now:

```python
from company.employees import Manager, Developer
```

## 8. Does Every Package Need `__init__.py`?

No.

Modern Python supports **namespace packages**, which can exist without an `__init__.py` file.

However, `__init__.py` is commonly used when creating regular packages because it provides a convenient place for initialization and package-level imports.

## 9. Important Points

| Concept | Explanation |
|---|---|
| `__init__.py` | Package initialization file |
| Execution | Runs when the package is first imported |
| Relative imports | Uses dots to import within packages |
| Package variables | Can define variables accessible through the package |
| `__all__` | Controls wildcard imports |
| Subpackages | Can have their own `__init__.py` |
| Namespace packages | Can exist without `__init__.py` |

## 10. Real-World Use Cases

- **Package initialization:** Set up package-level configuration.
- **Clean imports:** Expose selected classes directly from a package.
- **API organization:** Provide a simple public interface for a package.
- **Subpackage management:** Organize imports in large applications.
- **Wildcard imports:** Control which names are exposed through `__all__`.
