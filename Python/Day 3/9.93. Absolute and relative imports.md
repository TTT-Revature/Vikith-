# Absolute and Relative Imports in Python

## 1. Introduction

Python allows us to import functions, classes and variables from other modules.

There are two main ways to import from packages:

1. **Absolute imports** – Use the complete package path.
2. **Relative imports** – Use the current package location as a reference.

Before understanding imports, let's understand what absolute and relative mean.

## 2. What Is a Path?

A path is the location or address of a file or folder.

### Absolute Path

An absolute path provides the complete location of a file, starting from the root location.

Example:

```text
C:/Users/Vikith/Python/ecommerce/products.py
```

It gives the complete address, regardless of the current folder.

### Relative Path

A relative path provides a file's location based on the current folder.

Example:

```text
ecommerce/
├── products.py
└── orders.py
```

If we are inside the `ecommerce` folder and want to locate `products.py`:

```text
./products.py
```

Here:

- `.` means the current directory.
- `..` means the parent directory.

## 3. Project Structure

Consider this project:

```text
my_project/
│
├── main.py
│
└── ecommerce/
    ├── __init__.py
    ├── products.py
    ├── orders.py
    │
    └── payments/
        ├── __init__.py
        └── payment.py
```

Inside `products.py`:

```python
def add_product():
    print("Product added")
```

Inside `orders.py`:

```python
def create_order():
    print("Order created")
```

## 4. Absolute Imports

An absolute import uses the complete package and module path to import something.

### Syntax

```python
from package.module import name
```

### Example

Inside `main.py`:

```python
from ecommerce.products import add_product

add_product()
```

Output:

```text
Product added
```

Explanation:

- `ecommerce` → Package
- `products` → Module
- `add_product` → Function

We provide the complete package path to locate the function.

### Another Example

```python
import ecommerce.products

ecommerce.products.add_product()
```

We can also import a complete module and access its members using dot notation.

## 5. Relative Imports

A relative import uses dots (`.`) to locate modules relative to the current package.

### Syntax

```python
from .module import name
```

### Example: Import from the Same Package

Inside `orders.py`:

```python
from .products import add_product

def create_order():
    add_product()
    print("Order created")
```

Output:

```text
Product added
Order created
```

Explanation:

- `orders.py` and `products.py` are inside the same package.
- A single dot (`.`) represents the current package.
- Python locates `products.py` relative to the current package.

## 6. Understanding Relative Import Dots

Consider this structure:

```text
ecommerce/
│
├── products.py
├── orders.py
│
└── payments/
    ├── __init__.py
    └── payment.py
```

Suppose we are inside `payment.py`.

### Single Dot (.)

A single dot represents the current package.

```python
from .payment_helper import process_payment
```

This looks for `payment_helper.py` inside the current `payments` package.

### Double Dots (..)

Two dots represent the parent package.

```python
from ..products import add_product
```

Here:

- Current package → `payments`
- Parent package → `ecommerce`
- Module → `products`

### Triple Dots (...)

Three dots move two package levels upwards.

For example:

```text
my_project/
│
├── common.py
│
└── ecommerce/
    └── payments/
        └── gateways/
            └── gateway.py
```

Inside `gateway.py`:

```python
from ...common import some_function
```

This moves from `gateways` to `payments`, then to `ecommerce`.

**Remember:**

| Syntax | Meaning |
|---|---|
| `.` | Current package |
| `..` | One package level up |
| `...` | Two package levels up |
| `....` | Three package levels up |

## 7. Absolute vs Relative Imports

| Absolute Import | Relative Import |
|---|---|
| Uses the complete package path | Uses the current package as a reference |
| Does not use relative dots | Uses `.`, `..`, `...` |
| Easy to understand across packages | Convenient for related modules |
| Example: `from ecommerce.products import add_product` | Example: `from .products import add_product` |

### Example Comparison

Inside `ecommerce/orders.py`:

```python
# Absolute import
from ecommerce.products import add_product

# Relative import
from .products import add_product
```

Both can import the same function when the package is set up correctly.

## 8. How Python Executes Imports

Consider this `main.py`:

```python
from ecommerce.orders import create_order
from ecommerce.products import add_product

add_product()
create_order()
```

Python processes the statements in order.

### Step 1: Import orders

```python
from ecommerce.orders import create_order
```

Python:

1. Finds the `ecommerce` package.
2. Executes `ecommerce/__init__.py` when initializing a regular package for the first time.
3. Loads `orders.py`.
4. Executes its top-level statements.
5. Makes `create_order` available in `main.py`.

Defining a function does not execute its function body.

### Step 2: Import products

```python
from ecommerce.products import add_product
```

Python loads `products.py` and executes its top-level statements.

The `add_product()` function is defined but not called yet.

### Step 3: Execute function calls

```python
add_product()
create_order()
```

Now the function bodies execute because we explicitly call them.

**Important:** Python caches imported modules in `sys.modules`. If a module has already been imported, Python normally reuses the cached module instead of executing it again.

## 9. Running Modules Directly vs Using -m

Relative imports generally require a module to be executed as part of a package.

Suppose `orders.py` contains:

```python
from .products import add_product
```

Running it directly:

```bash
python ecommerce/orders.py
```

May produce:

```text
ImportError: attempted relative import with no known parent package
```

Instead, execute it from the project root:

```bash
python -m ecommerce.orders
```

The `-m` option runs the module as part of its package.

## 10. What Happens Without __init__.py?

In modern Python (3.3 and later), a directory can work as a namespace package without an `__init__.py` file, provided its location is available on Python's import path.

Example:

```text
my_project/
│
├── main.py
│
└── ecommerce/
    ├── products.py
    └── orders.py
```

This import can still work:

```python
from ecommerce.products import add_product
```

### With and Without __init__.py

| With `__init__.py` | Without `__init__.py` |
|---|---|
| Can be a regular package | Can be a namespace package |
| Supports package initialization code | No `__init__.py` initialization code |
| Can define package-level `__all__` | No `__init__.py` to define package-level `__all__` |

## 11. Understanding __all__

`__all__` is a list of names that controls what gets imported when using:

```python
from package import *
```

Consider this structure:

```text
ecommerce/
│
├── __init__.py
├── products.py
└── orders.py
```

Inside `products.py`:

```python
class Product:
    pass

def add_product():
    print("Product added")

def delete_product():
    print("Product deleted")
```

Inside `orders.py`:

```python
def create_order():
    print("Order created")
```

Inside `__init__.py`:

```python
from .products import Product, add_product, delete_product
from .orders import create_order

__all__ = ["Product", "add_product", "create_order"]
```

Now inside `main.py`:

```python
from ecommerce import *

add_product()
create_order()
```

Output:

```text
Product added
Order created
```

`delete_product` is not imported through the wildcard import because it is not included in `__all__`.

### Important Points About __all__

1. `__all__` is a list, not a dictionary.
2. It can contain function, class and variable names.
3. It controls wildcard imports.
4. It does not prevent explicit imports.
5. The names must be available in the package namespace for the wildcard import to import them.

For example, this explicit import can still work:

```python
from ecommerce import delete_product

delete_product()
```

`__all__` is not a security feature.

## 12. Important Rules to Remember

1. Absolute imports use the complete package path.
2. Relative imports use dots to navigate packages.
3. A single dot represents the current package.
4. Two dots represent the parent package.
5. Relative imports should be used inside packages.
6. Directly executing a module can cause relative import errors.
7. Use `python -m package.module` to execute a module as part of its package.
8. Python normally caches imported modules in `sys.modules`.
9. `__init__.py` can initialize a regular package.
10. `__all__` controls wildcard imports, not explicit imports.

## 13. Quick Revision

```python
# Absolute import
from ecommerce.products import add_product

# Relative import from the current package
from .products import add_product

# Relative import from the parent package
from ..products import add_product

# Importing a subpackage module
from .payments.payment import process_payment

# Wildcard import
from ecommerce import *
```
