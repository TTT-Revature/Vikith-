# Virtual Environments and venv in Python

## 1. Introduction

A virtual environment is an isolated Python environment that allows each project to maintain its own installed libraries and dependencies.

It helps avoid conflicts between different projects.

Python provides a built-in module called `venv` to create virtual environments.

## 2. Why Do We Need Virtual Environments?

Imagine you are working on three Python projects:

```text
MyProjects/
│
├── Instagram_Project/
├── Ecommerce_Project/
└── Data_Analytics_Project/
```

Each project requires different libraries or versions.

| Project | Required Libraries |
|---|---|
| Instagram | Django 5.0 |
| Ecommerce | Django 4.2 |
| Data Analytics | Pandas, NumPy |

If all projects use the same global Python environment, different dependency versions can conflict.

**Solution:** Create a separate virtual environment for each project.

## 3. What Is a Virtual Environment?

A virtual environment is an isolated environment containing its own Python interpreter references and installed packages.

Each project can install and manage dependencies independently.

### Without Virtual Environments

```text
MyProjects/
│
├── Instagram_Project/
├── Ecommerce_Project/
└── Data_Analytics_Project/
       |
       v
Global Python Environment
       |
       ├── Django
       ├── Pandas
       ├── NumPy
       └── Other Packages
```

All projects share the same global package environment.

### With Virtual Environments

```text
MyProjects/
│
├── Instagram_Project/
│   └── venv/
│       └── Django 5.0
│
├── Ecommerce_Project/
│   └── venv/
│       └── Django 4.2
│
└── Data_Analytics_Project/
    └── venv/
        ├── Pandas
        └── NumPy
```

Each project manages its own dependencies.

## 4. What Is venv?

`venv` is a built-in Python module used to create virtual environments.

It is included with standard Python installations, so it usually does not require a separate installation.

### Syntax

```bash
python -m venv environment_name
```

Explanation:

| Part | Meaning |
|---|---|
| `python` | Runs the Python interpreter |
| `-m` | Runs a Python module |
| `venv` | Virtual environment module |
| `environment_name` | Name of the environment folder |

## 5. Creating a Virtual Environment

### Step 1: Create a project folder

```bash
mkdir ecommerce
cd ecommerce
```

### Step 2: Create the virtual environment

```bash
python -m venv venv
```

This creates a folder named `venv`.

### Step 3: Project Structure

On Windows, the structure generally looks like:

```text
ecommerce/
│
└── venv/
    │
    ├── Include/
    ├── Lib/
    │   └── site-packages/
    │
    ├── Scripts/
    │
    └── pyvenv.cfg
```

Explanation:

| Folder/File | Purpose |
|---|---|
| `Include/` | Header files used by some packages |
| `Lib/` | Python libraries and installed packages |
| `site-packages/` | Third-party packages installed in the environment |
| `Scripts/` | Python executable and activation scripts on Windows |
| `pyvenv.cfg` | Virtual environment configuration |

On Linux and macOS, the environment generally uses a `bin/` directory instead of `Scripts/`.

## 6. Activating a Virtual Environment

Creating an environment does not automatically activate it.

We need to activate it before installing project dependencies.

### Windows CMD

```bash
venv\Scripts\activate.bat
```

### Windows PowerShell

```powershell
.\venv\Scripts\Activate.ps1
```

### Linux / macOS

```bash
source venv/bin/activate
```

After activation, the terminal displays the environment name.

Example:

```text
(venv) C:\Users\Vikith\ecommerce>
```

`(venv)` indicates that the virtual environment is active.

## 7. Installing Packages Inside a Virtual Environment

After activation, install the required libraries.

Example:

```bash
pip install django
```

The package gets installed inside the active virtual environment.

### Check Installed Packages

```bash
pip list
```

Example output:

```text
Package    Version
---------- -------
Django     5.0
pip        24.0
```

### Check Django Version

```bash
python -m django --version
```

### Check Python Executable

```bash
python -c "import sys; print(sys.executable)"
```

This displays the Python interpreter being used.

It should point to your virtual environment.

## 8. Installing Multiple Packages

You can install multiple packages in one command.

```bash
pip install django pandas numpy
```

All these packages are installed into the currently active environment.

## 9. Deactivating a Virtual Environment

When you finish working on your project, deactivate the environment.

```bash
deactivate
```

The `(venv)` prefix disappears from the terminal.

Deactivation does not delete the virtual environment or its installed packages.

## 10. What Is requirements.txt?

`requirements.txt` is a file used to list the dependencies required by a Python project.

It helps other developers install the same package versions.

### Step 1: Install Packages

```bash
pip install django pandas numpy
```

### Step 2: Generate requirements.txt

```bash
pip freeze > requirements.txt
```

This saves the installed package names and versions.

Example:

```text
Django==5.0
numpy==2.0.0
pandas==2.2.0
```

The exact versions depend on what is installed in your environment.

### Step 3: Install Dependencies From requirements.txt

Another developer can create and activate a virtual environment, then run:

```bash
pip install -r requirements.txt
```

This installs the listed dependencies.

## 11. Removing a Virtual Environment

If you no longer need an environment:

1. Deactivate it.
2. Delete its environment folder.

For example:

```text
ecommerce/
│
└── venv/
```

You can delete the `venv` folder.

This removes the virtual environment and its installed packages, but it does not delete your project source files.

You can create a fresh environment whenever required.

## 12. Should We Upload venv to GitHub?

No. Normally, we should not upload the virtual environment folder to GitHub.

It can contain many files and is specific to the local machine and platform.

Instead, upload:

- Python source files
- `requirements.txt`
- Project documentation

Add this to `.gitignore`:

```text
venv/
.venv/
__pycache__/
*.pyc
```

Another developer can recreate the environment using `venv` and `requirements.txt`.

## 13. Complete Workflow

Here is the typical workflow for a new Python project.

```bash
# 1. Create project folder
mkdir ecommerce

# 2. Enter project folder
cd ecommerce

# 3. Create virtual environment
python -m venv venv

# 4. Activate environment (Windows CMD)
venv\Scripts\activate.bat

# 5. Install dependencies
pip install django pandas

# 6. Save dependencies
pip freeze > requirements.txt

# 7. Deactivate environment
deactivate
```

## 14. Important Commands

| Command | Purpose |
|---|---|
| `python -m venv venv` | Create a virtual environment |
| `venv\Scripts\activate.bat` | Activate on Windows CMD |
| `.\venv\Scripts\Activate.ps1` | Activate on Windows PowerShell |
| `source venv/bin/activate` | Activate on Linux/macOS |
| `pip install django` | Install a package |
| `pip list` | List installed packages |
| `pip freeze` | Display installed packages and versions |
| `pip freeze > requirements.txt` | Save dependencies |
| `pip install -r requirements.txt` | Install dependencies from a file |
| `deactivate` | Deactivate the environment |

## 15. Important Points to Remember

1. A virtual environment isolates project dependencies.
2. `venv` is a built-in Python module.
3. Creating an environment does not automatically activate it.
4. Packages are installed inside the active environment.
5. Different projects can use different versions of the same library.
6. `requirements.txt` records project dependencies.
7. Do not normally upload `venv/` to GitHub.
8. Deactivating an environment does not delete it.
9. Deleting the environment folder removes that environment.
