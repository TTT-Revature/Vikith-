# 91. Python Project Structure

## 1. What is Project Structure?

Project Structure means organizing the files and folders of a project in a proper way.

Instead of writing all code in a single Python file, we divide the project into multiple files and folders based on their responsibilities.

**Why do we need it?**

- Keeps code organized.
- Makes debugging easier.
- Improves code reusability.
- Makes collaboration easier.
- Helps maintain large projects.

## 2. Basic Python Project Structure

Example: Student Management System

```text
StudentManagement/
│
├── main.py
├── students.py
├── database.py
├── requirements.txt
├── README.md
└── .gitignore
```

### File Responsibilities

| File | Purpose |
|---|---|
| `main.py` | Main entry point of the application |
| `students.py` | Student-related functions and classes |
| `database.py` | Database operations |
| `requirements.txt` | Lists project dependencies |
| `README.md` | Project documentation |
| `.gitignore` | Specifies files Git should ignore |

## 3. Understanding main.py

`main.py` is commonly used as the entry point of a Python application.

It connects different modules and starts the application.

Example:

```python
from students import add_student

def main():
    add_student("Rahul")

if __name__ == "__main__":
    main()
```

## 4. Organizing Code into Multiple Files

Instead of writing everything inside `main.py`, we can separate functionality.

### students.py

```python
def add_student(name):
    print(f"Student added: {name}")
```

### main.py

```python
from students import add_student

add_student("Rahul")
```

Output:

```text
Student added: Rahul
```

Here, `main.py` imports and reuses the function from `students.py`.

## 5. Project Structure with Packages

When a project becomes larger, we can organize related modules into folders called packages.

Example:

```text
StudentManagement/
│
├── main.py
│
├── models/
│   ├── __init__.py
│   └── student.py
│
├── services/
│   ├── __init__.py
│   └── student_service.py
│
├── database/
│   ├── __init__.py
│   └── connection.py
│
├── requirements.txt
├── README.md
└── .gitignore
```

### Folder Responsibilities

| Folder | Purpose |
|---|---|
| `models/` | Contains data models and classes |
| `services/` | Contains business logic |
| `database/` | Contains database-related operations |

### Understanding __init__.py

`__init__.py` is used to initialize a regular Python package.

It can also expose selected classes and functions from the package.

Example:

```text
models/
│
├── __init__.py
└── student.py
```

Note: Modern Python also supports namespace packages without `__init__.py`.

## 6. Importing Modules from Project Folders

Suppose we have:

```text
StudentManagement/
│
├── main.py
│
└── models/
    ├── __init__.py
    └── student.py
```

### student.py

```python
class Student:
    def __init__(self, name):
        self.name = name
```

### main.py

```python
from models.student import Student

student = Student("Rahul")

print(student.name)
```

Output:

```text
Rahul
```

Here:

- `models` is the package.
- `student` is the module.
- `Student` is the class.

## 7. Understanding requirements.txt

This file contains the external packages required by the project.

Example:

```text
requests==2.32.3
pandas==2.2.3
numpy==2.2.0
```

Generate it using:

```bash
pip freeze > requirements.txt
```

Install dependencies using:

```bash
pip install -r requirements.txt
```

## 8. Understanding README.md

`README.md` provides information about the project.

It usually contains:

- Project name.
- Project description.
- Features.
- Technologies used.
- Installation instructions.
- How to run the project.

Example:

```markdown
# Student Management System

A Python application to manage student records.

## Features
- Add students
- View students
- Delete students

## Installation

pip install -r requirements.txt

## Run

python main.py
```

## 9. Understanding .gitignore

`.gitignore` specifies which files and folders Git should ignore.

Example:

```gitignore
venv/
.venv/
__pycache__/
*.pyc
.env
```

### Why ignore these files?

| File or Folder | Reason |
|---|---|
| `venv/` | Local virtual environment |
| `.venv/` | Local virtual environment |
| `__pycache__/` | Generated Python bytecode cache |
| `*.pyc` | Compiled Python bytecode files |
| `.env` | May contain sensitive environment variables |

Never upload passwords, API keys or other secrets to GitHub.

## 10. Virtual Environment in Project Structure

A typical local project may look like this:

```text
StudentManagement/
│
├── .venv/
│
├── main.py
│
├── models/
│   ├── __init__.py
│   └── student.py
│
├── services/
│   ├── __init__.py
│   └── student_service.py
│
├── requirements.txt
├── README.md
└── .gitignore
```

The `.venv/` folder contains the isolated Python environment and installed packages.

It is normally excluded from GitHub using `.gitignore`.

## 11. Best Practices

1. Keep related code in separate modules.
2. Use meaningful file and folder names.
3. Keep `main.py` focused on starting the application.
4. Use packages to organize large projects.
5. Maintain a `requirements.txt` file.
6. Write project instructions in `README.md`.
7. Add unnecessary generated files and local environments to `.gitignore`.
8. Avoid putting the entire application into one file.

## 12. Important Differences

| Term | Meaning |
|---|---|
| Project | Complete application or codebase |
| Project Structure | Arrangement of project files and folders |
| Module | A Python file containing reusable code |
| Package | A collection of related Python modules |
| `main.py` | Common application entry point |
| `requirements.txt` | Dependency list |
| `README.md` | Project documentation |
| `.gitignore` | Git ignore rules |
