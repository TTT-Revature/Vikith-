# Locks in Python – Thread Synchronization

## 1. What is a Lock?

A Lock is a synchronization mechanism used to control access to shared resources when multiple threads are running.

It ensures that only one thread at a time can execute a protected section of code.

**Why do we need Locks?**

Without locks, multiple threads can modify shared data simultaneously, causing race conditions and incorrect results.

---

## 2. Creating a Lock

Python provides the `Lock()` method through the `threading` module.

```python
import threading

lock = threading.Lock()
```

Here:
- `threading.Lock()` creates a Lock object.
- The lock controls access to a critical section.
- Other threads must wait while the lock is held.

---

## 3. Lock Methods

| Method | Description |
|---|---|
| `acquire()` | Acquires the lock |
| `release()` | Releases the lock |
| `locked()` | Checks whether the lock is currently acquired |

### A. acquire()

The `acquire()` method attempts to acquire a lock.

If another thread already holds it, the calling thread waits by default.

```python
import threading

lock = threading.Lock()

lock.acquire()

print("Lock acquired")

lock.release()
```

Output:

```text
Lock acquired
```

### B. release()

The `release()` method releases an acquired lock so another thread can acquire it.

```python
import threading

lock = threading.Lock()

lock.acquire()

print("Inside critical section")

lock.release()

print("Lock released")
```

### C. locked()

The `locked()` method returns `True` if the lock is currently acquired; otherwise, it returns `False`.

```python
import threading

lock = threading.Lock()

print(lock.locked())

lock.acquire()

print(lock.locked())

lock.release()

print(lock.locked())
```

Output:

```text
False
True
False
```

---

## 4. Using Lock with a Context Manager

Python provides a cleaner way to use locks with the `with` statement.

```python
import threading

lock = threading.Lock()

with lock:
    print("Inside critical section")
```

**How it works:**

1. The `with` statement acquires the lock.
2. The code inside the block executes.
3. The lock is automatically released when the block exits, including when an exception occurs.

This is generally safer than manually calling `acquire()` and `release()`.

---

## 5. Real-World Example: Bank Account

Imagine a bank account with ₹1,000.

Two threads want to withdraw ₹500 each.

We use a Lock to protect the shared balance.

```python
import threading
import time

balance = 1000

lock = threading.Lock()

def withdraw():
    global balance

    with lock:
        if balance >= 500:
            print("Withdrawal started")

            time.sleep(1)

            balance -= 500

            print("Withdrawal successful")
        else:
            print("Insufficient balance")

t1 = threading.Thread(target=withdraw)
t2 = threading.Thread(target=withdraw)

t1.start()
t2.start()

t1.join()
t2.join()

print("Final balance:", balance)
```

Output:

```text
Withdrawal started
Withdrawal successful
Withdrawal started
Withdrawal successful
Final balance: 0
```

**Explanation:**

- Both threads share the same `balance` variable.
- Thread 1 acquires the lock and checks the balance.
- Thread 2 waits until Thread 1 releases the lock.
- Thread 1 withdraws ₹500.
- Thread 2 then checks the updated balance and withdraws the remaining ₹500.
- Final balance becomes ₹0.

## 6. Manual Lock vs Context Manager

### Manual approach

```python
lock.acquire()

try:
    print("Critical section")
finally:
    lock.release()
```

### Context manager approach

```python
with lock:
    print("Critical section")
```

**Difference:**

- Manual approach requires explicit lock release.
- Context manager automatically releases the lock.
- `with lock:` is generally preferred because it is cleaner and safer.

---

## 7. Important Points About Locks

- Locks prevent multiple threads from entering the same protected section simultaneously.
- Always release locks after acquiring them.
- Prefer `with lock:` for automatic release.
- Keep critical sections as small as practical.
- Avoid acquiring multiple locks in inconsistent orders because this can cause deadlocks.
- Locks protect shared data only when all relevant threads follow the same synchronization rules.

## 9. Practice Questions

### Q1. Why do we use Locks in Python?

**Answer:** To protect shared resources and prevent race conditions when multiple threads access shared data.

### Q2. Which method acquires a lock?

**Answer:** `acquire()`.

### Q3. Which method releases a lock?

**Answer:** `release()`.

### Q4. What happens if a thread tries to acquire a lock that another thread already holds?

**Answer:** By default, the thread waits until the lock becomes available.

### Q5. Why is `with lock:` preferred?

**Answer:** It automatically releases the lock when the protected block exits, even if an exception occurs.
