# 88. Python pip and Package Installation

## 1. What is a Python Package?

A package is a collection of reusable Python code that helps us perform specific tasks without writing everything from scratch.

Examples:

| Package | Purpose |
|---|---|
| `requests` | Sending HTTP requests |
| `numpy` | Mathematical calculations |
| `pandas` | Data analysis |
| `flask` | Building web applications |
| `django` | Building web applications |

Example:

```python
import requests

response = requests.get("https://api.github.com")
print(response.status_code)
```

Here, we use the `requests` package to send an HTTP request.

## 2. What is pip?

`pip` is Python's package installer.

It helps us:

- Install packages.
- Uninstall packages.
- Update packages.
- Check installed packages.
- Manage package versions.

Example:

```bash
pip install requests
```

This command installs the `requests` package.

## 3. How Does pip Work?

When we execute:

```bash
pip install requests
```

The process is approximately:

1. pip checks the package information from the configured package index.
2. It finds a compatible package version.
3. It downloads the package.
4. It installs the package and its required dependencies.
5. The package becomes available to the selected Python environment.

By default, pip commonly uses the Python Package Index (PyPI).

Website: https://pypi.org/

## 4. Where Are Packages Installed?

Python packages are installed inside a directory called `site-packages`.

When using a virtual environment, packages are installed inside that environment.

Windows example:

```text
MyProject/
│
├── main.py
│
└── venv/
    │
    ├── Scripts/
    │
    └── Lib/
        └── site-packages/
            ├── requests/
            ├── numpy/
            └── pandas/
```

**Important:**

- `site-packages` stores installed Python packages.
- Each virtual environment has its own package installation location.
- Packages installed in one virtual environment are not automatically available in another.

## 5. Installing Packages

### Install a Package

```bash
pip install requests
```

Installs the latest version compatible with the current environment.

### Install a Specific Version

```bash
pip install requests==2.31.0
```

Installs the specified version if it is compatible.

### Install Multiple Packages

```bash
pip install requests numpy pandas
```

Installs multiple packages in one command.

### Install Packages from a Virtual Environment

First activate the environment.

Windows CMD:

```bash
venv\Scripts\activate.bat
```

Windows PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

Then install:

```bash
python -m pip install requests
```

Using `python -m pip` helps ensure pip belongs to the Python interpreter selected by `python`.

## 6. Important pip Commands

| Command | Purpose |
|---|---|
| `pip install package` | Install a package |
| `pip uninstall package` | Uninstall a package |
| `pip list` | Display installed packages |
| `pip show package` | Display package information |
| `pip freeze` | Display installed packages with versions |
| `pip install --upgrade package` | Upgrade a package |
| `pip check` | Check dependency compatibility |
| `python -m pip --version` | Display pip version and location |

### Check Installed Packages

```bash
pip list
```

Example output:

```text
Package    Version
---------- -------
numpy      2.2.0
pandas     2.2.3
requests   2.32.3
```

### Display Package Information

```bash
pip show requests
```

Displays details such as version, installation location and dependencies.

### Uninstall a Package

```bash
pip uninstall requests
```

pip asks for confirmation before uninstalling.

## 7. Understanding Package Versions

Packages have different versions because developers release updates containing new features, improvements and bug fixes.

Example:

```bash
pip install django==4.2
```

Installs Django 4.2 if compatible.

```bash
pip install django==5.0
```

Installs Django 5.0 if compatible.

### Version Operators

| Operator | Meaning |
|---|---|
| `==` | Exact version |
| `>=` | Greater than or equal to |
| `<=` | Less than or equal to |
| `>` | Greater than |
| `<` | Less than |
| `!=` | Not equal to |
| `~=` | Compatible release constraint |

Example:

```bash
pip install "django>=4.2"
```

Installs a version satisfying the specified minimum version constraint.

## 8. What Are Dependencies?

A dependency is another package required by a package to work correctly.

Example:

```text
Your Project
     |
     v
   pandas
     |
     v
   numpy
```

Here, pandas depends on NumPy for some of its functionality.

When you install a package using pip, pip normally installs its required dependencies automatically.

## 9. What Is requirements.txt?

`requirements.txt` is a text file used to list the Python packages required by a project.

It helps other developers install the project's dependencies.

### Generate requirements.txt

```bash
pip freeze > requirements.txt
```

Example output:

```text
numpy==2.2.0
pandas==2.2.3
requests==2.32.3
```

### Install Packages from requirements.txt

```bash
pip install -r requirements.txt
```

The `-r` option tells pip to read package requirements from a file.

### Why Is It Important?

Suppose you share your project with another developer.

Instead of asking them to install every package separately, you can share `requirements.txt`.

They can create their own virtual environment and install the listed dependencies using one command.

## 10. Global Installation vs Virtual Environment Installation

### Global Installation

```bash
pip install requests
```

When pip is associated with the global Python installation, the package is installed into that Python environment.

### Virtual Environment Installation

```bash
python -m venv venv
```

Activate the environment:

```bash
venv\Scripts\activate.bat
```

Install:

```bash
pip install requests
```

Now the package is installed inside the virtual environment.

| Global Installation | Virtual Environment |
|---|---|
| Uses the selected global Python environment | Uses an isolated project environment |
| Packages can be shared by projects using that environment | Packages are managed separately |
| Can cause dependency conflicts between projects | Helps avoid conflicts between projects |

## 11. Understanding pip and Python Versions

pip does not automatically install a different Python version.

Suppose:

- Project A needs Python 3.12.
- Project B needs Python 3.15.

First, install both Python versions on your computer.

Then create separate environments:

```bash
py -3.12 -m venv projectA_env
```

```bash
py -3.15 -m venv projectB_env
```

Each environment uses the Python interpreter selected when it was created.

Install project-specific packages inside each environment.

**Remember:**

- Python installation provides the Python interpreter.
- `venv` creates an isolated environment using a Python interpreter.
- `pip` installs and manages packages.

## 12. Project Structure

A typical Python project may look like this:

```text
MyProject/
│
├── venv/
│
├── main.py
│
├── requirements.txt
│
└── .gitignore
```

Example `.gitignore`:

```gitignore
venv/
.venv/
__pycache__/
*.pyc
```

Do not upload the virtual environment folder to GitHub. Share the source code and dependency information instead.
