# Race Conditions and Shared Data in Python

## 1. What is Shared Data?

Shared data is data that can be accessed or modified by multiple threads within the same process.

### Real-world example: Bank Account

Imagine a bank account with a balance of ₹1,000.

- Thread 1 wants to withdraw ₹500.
- Thread 2 also wants to withdraw ₹500.
- Both threads access the same balance variable.

```python
balance = 1000
```

Here, `balance` is shared data because multiple threads can access it.

---

## 2. What is a Race Condition?

A race condition occurs when multiple threads access or modify shared data concurrently, and the final result depends on the timing or order of execution.

### Example

Imagine two threads withdrawing ₹500 from an account containing ₹1,000.

**Possible execution:**

1. Thread 1 reads balance = 1000.
2. Thread 2 also reads balance = 1000.
3. Thread 1 calculates 1000 - 500 = 500.
4. Thread 2 calculates 1000 - 500 = 500.
5. Both threads write 500 into the balance.

**Expected balance:** ₹0

**Incorrect balance:** ₹500

One withdrawal update gets overwritten by the other.

---

## 3. Python Example: Race Condition

```python
import threading
import time

balance = 1000

def withdraw():
    global balance

    current = balance

    time.sleep(0.1)

    balance = current - 500

t1 = threading.Thread(target=withdraw)
t2 = threading.Thread(target=withdraw)

t1.start()
t2.start()

t1.join()
t2.join()

print("Final balance:", balance)
```

Possible output:

```text
Final balance: 500
```

### Explanation

- Both threads read the same initial balance.
- Both calculate the new balance independently.
- One thread can overwrite the update made by the other.
- This can cause an incorrect final balance.

**Note:** The `sleep()` deliberately creates an opportunity for the race condition. The output is not guaranteed to be 500 on every execution.

---

## 4. What is Thread Synchronization?

Thread synchronization means coordinating multiple threads to safely access shared resources.

Python provides synchronization tools through the `threading` module.

One important tool is `Lock`.

---

## 5. What is Lock in Python?

A Lock ensures that only one thread at a time can execute a protected section of code.

### Real-world example

Imagine a bathroom with one key.

- Person 1 takes the key and enters.
- Person 2 waits outside.
- Person 1 exits and releases the key.
- Person 2 can now enter.

A Lock works similarly.

### Creating a Lock

```python
import threading

lock = threading.Lock()
```

### Using Lock

```python
import threading
import time

balance = 1000

lock = threading.Lock()

def withdraw():
    global balance

    with lock:
        current = balance

        time.sleep(0.1)

        balance = current - 500

t1 = threading.Thread(target=withdraw)
t2 = threading.Thread(target=withdraw)

t1.start()
t2.start()

t1.join()
t2.join()

print("Final balance:", balance)
```

Output:

```text
Final balance: 0
```

### Explanation

- `threading.Lock()` creates a Lock object.
- `with lock:` acquires the lock before entering the block.
- Other threads wait until the lock is released.
- The lock is automatically released when the `with` block exits.

Now each thread reads and updates the latest balance safely.

## 6. Important Terms

| Term | Meaning |
|---|---|
| Shared Data | Data accessed by multiple threads |
| Race Condition | Incorrect or unpredictable result due to concurrent access |
| Lock | Controls access to shared resources |
| Synchronization | Coordinates thread execution |
| Critical Section | Code that accesses or modifies shared data |

## 7. Practice Questions with Answers

### Q1. What is shared data?

**Answer:** Shared data is data that can be accessed or modified by multiple threads.

Example:

```python
balance = 1000
```

If multiple threads access `balance`, it becomes shared data.

### Q2. What is a race condition?

**Answer:** A race condition occurs when multiple threads access or modify shared data concurrently, and the result depends on their execution timing or order.

### Q3. What happens when two threads overwrite each other's updates?

**Answer:** A race condition can occur, resulting in incorrect data.

### Q4. How can we prevent race conditions?

**Answer:** We can use synchronization mechanisms such as `threading.Lock()` to protect shared data.

### Q5. What is a critical section?

**Answer:** A critical section is a part of the code that accesses or modifies shared resources and may need protection using a lock.

### Q6. What does `with lock:` do?

**Answer:** It acquires the lock before executing the block and automatically releases it when the block exits.
