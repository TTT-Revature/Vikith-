# Python Refactoring and Avoiding Duplicate Code

## 1. What is Refactoring?

Refactoring means improving the internal structure of existing code without changing its external behaviour or output.

The goal is to make code:
- Cleaner and simpler.
- Easier to understand.
- Easier to maintain.
- Reusable and testable.

### Example: Before Refactoring

```python
price1 = 100
quantity1 = 5
total1 = price1 * quantity1
print(total1)

price2 = 200
quantity2 = 3
total2 = price2 * quantity2
print(total2)
```

**Output:**
```text
500
600
```

### After Refactoring

```python
def calculate_total(price, quantity):
    return price * quantity


print(calculate_total(100, 5))
print(calculate_total(200, 3))
```

**Output:**
```text
500
600
```

Both programs produce the same output, but the second version is cleaner and reusable.

## 2. What is Duplicate Code?

Duplicate code means writing the same or very similar logic multiple times in a program.

### Example

```python
student1_marks = [80, 90, 70]
student1_average = sum(student1_marks) / len(student1_marks)

student2_marks = [60, 75, 85]
student2_average = sum(student2_marks) / len(student2_marks)

student3_marks = [90, 95, 85]
student3_average = sum(student3_marks) / len(student3_marks)
```

The average calculation is repeated three times.

### Solution: Create a Reusable Function

```python
def calculate_average(marks):
    return sum(marks) / len(marks)


student1 = [80, 90, 70]
student2 = [60, 75, 85]
student3 = [90, 95, 85]

print(calculate_average(student1))
print(calculate_average(student2))
print(calculate_average(student3))
```

Now the calculation is written in one place and reused whenever required.

## 3. DRY Principle

DRY stands for **Don't Repeat Yourself**.

It is a programming principle that encourages developers to avoid repeating the same logic.

### Main Ideas

- Avoid repeating the same code.
- Create reusable functions.
- Keep business logic in one place.
- Make future changes easier.

### Example

Suppose a tax calculation is written in multiple places.

Instead, create one reusable function:

```python
def calculate_tax(amount):
    tax_rate = 0.18
    return amount * tax_rate


print(calculate_tax(1000))
print(calculate_tax(2000))
print(calculate_tax(5000))
```

If the tax rate changes, update it in one place.

## 4. Extracting Repeated Logic into Functions

Extracting repeated logic means moving common code into a separate reusable function.

### Before Refactoring

```python
length1 = 10
width1 = 5
area1 = length1 * width1

length2 = 20
width2 = 8
area2 = length2 * width2

print(area1)
print(area2)
```

### After Refactoring

```python
def calculate_area(length, width):
    return length * width


print(calculate_area(10, 5))
print(calculate_area(20, 8))
```

The repeated calculation is now handled by one function.

## 5. Avoid Over-Engineering

Refactoring does not mean creating a function for every single line of code.

Sometimes simple code is better.

### Unnecessarily Complicated

```python
def get_name(name):
    return name


student_name = get_name("Rahul")
print(student_name)
```

### Simpler Version

```python
student_name = "Rahul"
print(student_name)
```

**Remember:** Refactoring should make code simpler, not more complicated.

## 6. When Should You Refactor?

Consider refactoring when:

1. The same code is repeated multiple times.
2. A function performs too many different tasks.
3. Variable names are confusing.
4. A function is difficult to test.
5. Changing one feature requires editing many places.
6. Code becomes difficult to understand or maintain.

## 7. Important Terms

| Term | Meaning |
|---|---|
| Refactoring | Improving code structure without changing behaviour |
| Duplicate Code | Repeated logic in multiple places |
| DRY | Don't Repeat Yourself |
| Code Reusability | Reusing existing functions |
| Maintainability | Making code easy to modify |
| Code Smell | A sign that code may need improvement |

## 8. Best Practices

1. Identify repeated logic before creating functions.
2. Use meaningful function names.
3. Keep functions focused on one main responsibility.
4. Avoid unnecessary complexity.
5. Reuse existing functions wherever appropriate.
6. Test the code after refactoring to ensure behaviour remains unchanged.
7. Keep business logic in one place when it is shared.

## 9. Key Takeaway

Refactoring improves the structure and quality of existing code without changing its behaviour.

The DRY principle helps avoid duplicate logic by encouraging reusable functions.

**Good code is not just code that works. It is code that is easy to understand, reuse, test, and maintain.**
