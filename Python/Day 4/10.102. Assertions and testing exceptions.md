# 94. Assertions and Testing Exceptions in Python

## 1. What are Assertions?

Assertions are used to check whether the actual result matches the expected result during testing.

If the condition is correct, the test passes. Otherwise, the test fails.

```python
self.assertEqual(10 + 5, 15)
```

**Output:** Test passes.

```python
self.assertEqual(10 + 5, 20)
```

**Output:** Test fails because the actual result is `15`, not `20`.

## 2. Common Assertion Methods

| Method | Purpose |
|---|---|
| `assertEqual(a, b)` | Checks whether values are equal |
| `assertNotEqual(a, b)` | Checks whether values are different |
| `assertTrue(x)` | Checks whether the value is True |
| `assertFalse(x)` | Checks whether the value is False |
| `assertIsNone(x)` | Checks whether the value is None |
| `assertIsNotNone(x)` | Checks whether the value is not None |
| `assertIn(a, b)` | Checks whether a value exists in a collection |
| `assertNotIn(a, b)` | Checks whether a value does not exist |
| `assertGreater(a, b)` | Checks whether a is greater than b |
| `assertLess(a, b)` | Checks whether a is less than b |
| `assertGreaterEqual(a, b)` | Checks whether a is greater than or equal to b |
| `assertLessEqual(a, b)` | Checks whether a is less than or equal to b |

### Example

```python
import unittest

class TestAssertions(unittest.TestCase):

    def test_values(self):
        self.assertEqual(10, 10)
        self.assertNotEqual(10, 20)

        self.assertTrue(5 > 2)
        self.assertFalse(5 < 2)

        self.assertIsNone(None)
        self.assertIsNotNone("Python")

        self.assertIn("apple", ["apple", "mango"])
        self.assertNotIn("grapes", ["apple", "mango"])

        self.assertGreater(10, 5)
        self.assertLess(5, 10)

if __name__ == "__main__":
    unittest.main()
```

## 3. Custom Failure Messages

We can provide our own message as the third argument of an assertion method.

The message is displayed only when the assertion fails.

```python
def test_addition(self):
    result = 10 + 5

    self.assertEqual(
        result,
        20,
        "Addition result is incorrect"
    )
```

**Syntax:**

```python
self.assertEqual(actual, expected, "Custom message")
```

- `actual`: Actual result produced by the code.
- `expected`: Correct result we expect.
- `message`: Custom message displayed if the assertion fails.

## 4. Testing Exceptions

Sometimes a function is expected to raise an error for invalid input.

For example:

```python
int("hello")
```

This raises a `ValueError` because `"hello"` cannot be converted into an integer.

In unit testing, we use `assertRaises()` to verify that the expected exception occurs.

### Syntax

```python
with self.assertRaises(ExceptionName):
    function_call()
```

### Example

```python
import unittest

class TestExceptions(unittest.TestCase):

    def test_invalid_integer(self):
        with self.assertRaises(ValueError):
            int("hello")

if __name__ == "__main__":
    unittest.main()
```

**Result:** Test passes because `int("hello")` raises `ValueError`, as expected.

## 5. Testing Different Exceptions

### ValueError

Raised when a function receives an argument with an inappropriate value.

```python
with self.assertRaises(ValueError):
    int("Python")
```

### ZeroDivisionError

Raised when a number is divided by zero.

```python
with self.assertRaises(ZeroDivisionError):
    10 / 0
```

### TypeError

Raised when an operation is applied to an inappropriate data type.

```python
with self.assertRaises(TypeError):
    "10" + 5
```

## 6. Testing Your Own Functions

Consider a function that checks the age of a user.

```python
def check_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")

    return age
```

Unit test:

```python
import unittest

class TestAge(unittest.TestCase):

    def test_valid_age(self):
        self.assertEqual(check_age(25), 25)

    def test_invalid_age(self):
        with self.assertRaises(ValueError):
            check_age(-5)

if __name__ == "__main__":
    unittest.main()
```

**Explanation:**

- `check_age(25)` returns 25, so the test passes.
- `check_age(-5)` raises `ValueError`, so the exception test passes.

## 7. assertRaises() with Custom Exception Messages

We can also verify the exception message using the context manager.

```python
with self.assertRaises(ValueError) as error:
    check_age(-5)

self.assertEqual(
    str(error.exception),
    "Age cannot be negative"
)
```

Here:

- `error` stores information about the raised exception.
- `error.exception` accesses the exception object.
- `str(error.exception)` gets its message.

## 8. assertRaises() vs assertEqual()

| assertEqual() | assertRaises() |
|---|---|
| Checks whether two values are equal | Checks whether an expected exception occurs |
| Used for normal results | Used for error conditions |
| Compares actual and expected values | Checks exception type |

## 9. Complete Example

```python
import unittest

def divide(a, b):
    if b == 0:
        raise ZeroDivisionError("Cannot divide by zero")

    return a / b


class TestDivision(unittest.TestCase):

    def test_valid_division(self):
        self.assertEqual(divide(10, 2), 5)

    def test_invalid_division(self):
        with self.assertRaises(ZeroDivisionError):
            divide(10, 0)

    def test_exception_message(self):
        with self.assertRaises(ZeroDivisionError) as error:
            divide(10, 0)

        self.assertEqual(
            str(error.exception),
            "Cannot divide by zero"
        )


if __name__ == "__main__":
    unittest.main()
```

## 10. Running Tests

Save the file as `test_division.py`.

Run the following command:

```bash
python -m unittest -v
```

The `-v` option displays detailed test results.

---

**Key Points**

- Assertions verify whether the program produces correct results.
- `assertEqual()` compares actual and expected values.
- A custom message can be provided as the third argument.
- `assertRaises()` checks whether the expected exception occurs.
- `error.exception` allows us to inspect the raised exception.
- Exception testing helps verify how a program handles invalid inputs.
