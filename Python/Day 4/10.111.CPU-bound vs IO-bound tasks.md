# CPU-Bound vs I/O-Bound Tasks in Python

## 1. CPU-Bound Tasks

CPU-bound tasks are operations that spend most of their time performing calculations or processing data using the CPU.

### Real-world examples

- Image processing and resizing
- Video rendering and encoding
- Mathematical calculations
- Machine learning model training
- Data processing

### Python Example

```python
def calculate():
    total = 0

    for i in range(10_000_000):
        total += i * i

    print(total)

calculate()
```

**Explanation:**

- The CPU continuously performs calculations.
- Most execution time is spent processing data.
- There is very little waiting for external resources.

**Recommended approach:** `multiprocessing` for CPU parallelism.

---

## 2. I/O-Bound Tasks

I/O-bound tasks are operations that spend most of their time waiting for input/output operations to complete.

### Real-world examples

- Downloading files from the internet
- Making API requests
- Fetching data from databases
- Reading and writing files
- Sending emails

### Python Example

```python
import time

def download_file(name):
    print(f"{name} started")

    time.sleep(3)  # Simulates waiting for a download

    print(f"{name} completed")

download_file("File 1")
download_file("File 2")
download_file("File 3")
```

**Explanation:**

- The program waits for an operation to complete.
- The CPU does not need to perform calculations during `time.sleep()`.
- Multiple I/O operations can be handled concurrently.

**Recommended approaches:** `threading` or `asyncio`.

---

## 3. CPU-Bound vs I/O-Bound

| CPU-Bound | I/O-Bound |
|---|---|
| Requires heavy CPU processing | Spends time waiting for I/O |
| Image processing | File downloading |
| Video rendering | API requests |
| Mathematical calculations | Database queries |
| Machine learning training | Reading and writing files |
| Multiprocessing is commonly useful | Threading or asyncio is commonly useful |

## 4. Real-World E-commerce Example

Imagine an e-commerce application like Amazon.

### I/O-Bound Operations

When a customer opens a product page, the application may:

- Fetch product details from an API.
- Fetch customer reviews.
- Check product availability.
- Fetch delivery information.

These operations involve waiting for API or database responses.

**Suitable approach:** `threading` or `asyncio`.

### CPU-Bound Operations

When the application processes thousands of product images, it may:

- Resize images.
- Compress images.
- Generate thumbnails.
- Apply image transformations.

These operations require CPU processing.

**Suitable approach:** `multiprocessing`.

## 5. Choosing the Right Python Module

| Module | Purpose | Common use |
|---|---|---|
| `threading` | Multiple threads | I/O-bound concurrency |
| `multiprocessing` | Multiple processes | CPU-bound parallelism |
| `asyncio` | Asynchronous tasks | I/O-bound concurrency |

### Example: Threading for I/O-Bound Tasks

```python
import threading
import time

def download_file(name):
    print(f"{name} started")
    time.sleep(3)
    print(f"{name} completed")

t1 = threading.Thread(target=download_file, args=("File 1",))
t2 = threading.Thread(target=download_file, args=("File 2",))
t3 = threading.Thread(target=download_file, args=("File 3",))

t1.start()
t2.start()
t3.start()

t1.join()
t2.join()
t3.join()

print("All downloads completed")
```

The three tasks can make progress concurrently while waiting.

### Example: Multiprocessing for CPU-Bound Tasks

```python
from multiprocessing import Pool

def calculate_square(number):
    return number * number

if __name__ == "__main__":
    numbers = [10, 20, 30, 40, 50]

    with Pool(processes=4) as pool:
        results = pool.map(calculate_square, numbers)

    print(results)
```

Output:

```text
[100, 400, 900, 1600, 2500]
```

Multiple worker processes distribute the calculations. For such small calculations, multiprocessing overhead may outweigh the benefit; it is more useful for substantial CPU workloads.
